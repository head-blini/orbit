# orbit-threat-model

대상은 **이번 변경분**이다. 전체 시스템을 다시 모델링하지 않는다.

## 순서

1. **자산**: 이 변경이 닿는 것 중 지켜야 할 것. Orbit의 경우 — 훅 토큰, `~/.claude/settings.json`(사용자의 Claude Code 설정), 세션 로그(프롬프트·코드·비밀값이 섞여 있을 수 있음), 사용자의 파일시스템.
2. **신뢰 경계**: 데이터가 덜 믿을 만한 곳에서 더 믿는 곳으로 넘어가는 지점.
   - 로컬 HTTP 서버 ← 같은 PC의 다른 프로세스, 브라우저의 웹 페이지(CSRF, DNS rebinding)
   - 세션 로그·훅 페이로드 내용 → 화면 렌더링(XSS), → 파일 경로, → 셸 명령
   - Tauri 프론트(webview) → Rust 명령(capability 범위)
   - 점검 대상 저장소의 파일 → 에이전트 프롬프트(프롬프트 인젝션)
3. **위협**: 경계마다 "공격자가 여기에 무엇을 넣을 수 있고, 그러면 무슨 일이 생기나"를 한 줄씩. STRIDE를 빠짐 확인용으로만 쓴다(위장·변조·부인·정보 노출·서비스 거부·권한 상승).
4. **완화 확인**: 위협마다 코드의 어느 줄이 막는지 `파일:줄`로 적는다. 못 찾으면 발견 사항이다.
5. **판정**: 악용 가능하고 완화가 없는 것은 차단. 나머지는 권고.

## 이 프로젝트에서 항상 확인할 것

- 서버가 `127.0.0.1`에만 바인딩하는가 (`0.0.0.0` 금지).
- 토큰 검증이 모든 경로에 걸리는가, 비교가 상수 시간인가, 토큰이 로그·URL·화면에 찍히지 않는가.
- `Origin`/`Host` 헤더 검사로 브라우저발 요청을 거부하는가.
- 요청 본문 크기 제한이 있는가.
- settings.json을 고칠 때 백업 후 병합하는가, 쓰기가 원자적인가(임시 파일 → rename).
- 로그·페이로드에서 온 문자열을 HTML로 넣지 않는가(`dangerouslySetInnerHTML` 금지), 경로로 쓸 때 정규화 후 범위 검사하는가.
- Tauri capability가 필요한 최소 권한만 여는가.

## SECURITY.md에 쓰는 형식

발견 사항마다: 심각도(차단/권고) · 위치(`파일:줄`) · 시나리오(공격자 입력 → 결과) · 권장 수정. 추측은 추측이라고 쓴다.
