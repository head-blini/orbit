# design-system-guard

대상은 **이번 변경분의 UI 코드·스타일**이다. 토큰 파일은 `design/tokens.json`이다. 없으면 이 스킬은 "토큰 파일 없음"만 보고하고, 새로 만들지는 Designer의 DESIGN.md 결정에 맡긴다.

## 점검

1. **토큰 밖 값**: 색(`#hex`, `rgb()`, `hsl()`), 글꼴 크기, 간격, 모서리 둥글기, 그림자가 토큰에 있는 값인가. 변경된 줄을 훑어 리터럴 값을 찾고, 같은 값의 토큰이 있으면 토큰 참조로 바꾸게 한다.
2. **새 값이 정말 필요한가**: 가까운 토큰이 있으면 그것을 쓴다. 없으면 값을 코드에 박지 말고 Designer가 토큰을 추가하게 한다(DESIGN.md에 이유 한 줄).
3. **상태**: 빈 상태·로딩·에러·비활성·포커스 상태가 모두 있는가. 상세·기준값은 `orbit:ui-quality`의 바닥.
4. **접근성 기본**: 글자와 배경의 대비, 키보드 포커스 표시, 클릭 영역 크기, 색에만 의존하지 않는 표시. 상세·기준값은 `orbit:ui-quality`의 바닥.
5. **일관성**: 같은 역할의 요소(버튼, 입력, 카드)가 기존 화면과 같은 모양·간격인가. 템플릿 같은 기본값 그대로가 아닌지도 본다. 무엇이 템플릿 기본값인지는 `orbit:ui-quality`의 "AI 티 금지 목록"을 따른다(프로젝트 디자인 문서가 다르게 정했으면 그 문서).
6. **시각 확인**: 가능하면 화면을 띄워 스크린샷으로 본다. 못 띄웠으면 못 봤다고 쓴다.

## 경고 훅과의 관계

`design/tokens.json`이 있을 때 쓰기 뒤에 토큰 밖 값을 경고하는 훅이 동작할 수 있다. 훅은 막지 않고 알리기만 하며, 환경에 따라 꺼져 있을 수 있다. 훅이 없거나 전달되지 않는 환경에서는 1번 "토큰 밖 값" 점검이 훅을 대신한다. 훅 경고가 있어도 1번을 건너뛰지 않는다.

## 결과

발견 사항마다: 위치(`파일:줄`) · 토큰 밖 값 또는 문제 · 권장 수정. 확인하지 못한 항목은 확인하지 못했다고 쓴다.
