# DESIGN — 20261114-graph-ui (마일스톤 ④ 화면)

이 문서는 디자인을 새로 정하지 않는다. `.orbit/decisions.md` "화면 디자인 방향 확정" 절의 "최종"·"확정" 줄(68행: 기준 시안 `orbit_gameboy_rpg_layout_v4`)과 이 run의 DECISIONS.md를 화면 상태로 옮긴다. 줄 번호 `dN`은 `.orbit/decisions.md`의 N행, `RN`은 이 run DECISIONS.md의 N번 항목이다. 68행에 따라 타임라인·승인창·중계·상태 색 기록(38행 타임라인 부분, 40, 42, 47행 중 타임라인·입력창 배치 부분, 50, 62~65행 중계 부분)은 경위로만 읽었다.

- 기준 시안 파일: `design/reference/layout_v4.html` (스크립트·외부 요청 없음, 브라우저로 바로 열림)
- 토큰: `design/tokens.json`

## 1. 사용자 흐름

1. Orbit을 켠다 → 상단 바에 훅 서버 상태가 보인다. 세션 목록에 최근 활동 순으로 세션 줄이 쌓인다.
2. 세션 줄을 누른다(`▶`가 그 줄로 옮겨 감) → 가운데 위 그래프에 그 세션의 Lead와 서브에이전트가 가로로 그려지고, 상세 패널 "세션" 묶음에 id·출처가 나온다.
3. 그래프 노드를 누른다 → 상세 패널 "노드" 묶음에 종류·상태·시작·시간·토큰("—" 가능)이 나온다.
4. 훅 설치·제거, 경로 확인, 액정 폴더 열기는 상세 패널 "설정" 묶음에서 한다(R4).
5. 액정을 누르면 다음 그림(d56). 채팅은 보이기만 하고 입력은 막혀 있다(R1).

## 3. 시각 문법 (확정)

- 4명암 `#f8f8ec`/`#b4b8a4`/`#5c6052`/`#1c1e18`, 앱 배경 `#b4b8a4`(d35, d36). **색 없음**: 상태는 `✕`, `!`, 진행 막대, 반전으로만(d49).
- 큰 패널은 이중 테두리 `3px solid ink` + `inset 0 0 0 2px paper, inset 0 0 0 4px ink`, 둥글기 6px, 간격 8px(d36, d44).
- 픽셀 글꼴(Galmuri11, 한글)은 제목·메뉴·노드 이름·버튼·상태 문구만. 경로·안내문·채팅 본문은 일반 글꼴, 경로·id는 고정폭(d37, d43).
- 선택은 메뉴 커서 `▶`(d38).
- 그래프: 가로 흐름, 왼쪽 Lead → 오른쪽, 같은 단계는 세로로 쌓음(d46). 직각 간선, 네모 점선이 일의 방향(왼→오)으로 흐름, `shape-rendering: crispEdges`(d39). 이번 run은 메인 → 서브에이전트 1단계만(R9).
- 노드 상태(d39, R6): 실행 중 = 반전(ink 바탕·paper 글자) + 진행 막대 / 실패 = 점선 테두리 + `✕`(확인될 때만, R6) / 대기 = 회색(light) 바탕 + 깜빡이는 `!` / 끝남 = 기본 상자. **[개정으로 대체됨: 9절 — 반전 없음, E 모양]**
- 많아지면 칩으로 축소: 얇은 테두리 한 줄 칩, 선택한 것만 큰 상자(d44). **[그래프에 대해 개정으로 대체됨: 9절 — 그래프는 칩 없음. 세션 목록은 그대로]**
- 게임기 화면 틀: 진회색 베젤 + 연회색 액정, 패널 안이 아니라 베젤 자체가 독립 상자, 액정이 남는 높이를 채움(d52, d67). 액정 안은 사용자 그림만, 기본 그림 없음(d52, d60). `object-fit: contain`, `image-rendering: pixelated`(d57). 특정 게임의 로고·문구 없음(d72).
- 입력 줄 문구 "Claude Code에게 무엇을 시킬까?" + `▼`(d38). 이번에는 비활성 + "⑥에서 연결"(R1).

## 4. 화면과 상태 (패널별)

**상단 바**: 확인 중 "확인 중…" / 정상 "127.0.0.1:포트에서 듣는 중" / 에러 "✕ 훅 서버 시작 실패: 사유". `role="status"`. 토큰은 어디에도 표시하지 않는다.

**세션 목록** — 줄 = 폴더 이름(픽셀) + 상태 기호(오른쪽) + 마지막 활동 시각(둘째 줄, 보조 글자)(R4). id·경로를 줄에 잇지 않는다.
- 상태 기호: 작업 중 = 작은 진행 막대(움직이는 칸) / 대기(권한 요청) = 깜빡이는 `!` / 에러(StopFailure) = `✕` / 완료 = 기호 없음(기본) / 멈춤(추정, R7 10분) = `?` (새로 정함). 기호마다 시각 숨김 텍스트로 상태 이름을 같이 둔다.
- 로딩: "불러오는 중…" / 빈: "아직 세션이 없습니다" / 에러(로그 폴더를 못 정함): "✕ 로그 폴더를 읽지 못했습니다 — 설정 참고". 경로 자체는 "설정" 묶음에.
- 6개 이상이면 칩: 한 줄 `▶ 이름 … 기호 시각`, 1px 테두리, 선택 줄만 큰 상자.

**에이전트 그래프**
- 세션 미선택: "세션을 고르면 에이전트 흐름이 보입니다" / 서브에이전트 없음: Lead 노드만 + 오른쪽에 보조 글자 "서브에이전트 없음".
- 노드 = 이름(픽셀, 선택 시 앞에 `▶`) / 상태 문구 + 기호 / 셋째 줄: 실행 중이면 진행 막대, 아니면 "시간 · 토큰"(없으면 "—", BRIEF 4).
- 진행 막대는 진행률을 모르므로 칸 하나가 왼→오로 지나가는 불확정 막대(새로 정함).
- 알 수 없음(`tool_result` 없이 끊긴 호출, R9): 기본 상자 + 기호 `—` + 문구 "알 수 없음"(새로 정함, BRIEF 권고 그대로).
- 간선: 모든 간선이 네모 점선(4 4), 흐름 애니메이션은 실행 중 노드로 가는 간선에만(새로 정함).
- `agent_type`이 빈 SubagentStop은 노드로 만들지 않는다(BRIEF 4). 노드 이름이 없으면 `description`(BRIEF 열린 질문 4).
- 한 단계(열)에 6개 이상이면 칩, 선택 노드만 큰 상자. 패널보다 크면 패널 안에서 스크롤. **[개정으로 대체됨: 9절 — 칩 없음, 단계 열 + 가로·세로 스크롤]**

**채팅 패널**(R1): 항상 빈 상태 "대화 기능은 ⑥에서 연결됩니다." + 맨 아래 비활성 입력 줄(점선 진회색 테두리, 진회색 글자, `▼`는 깜빡이지 않음) + "⑥에서 연결" 칩.

**상세·하네스 패널** — 위에서부터 묶음 셋, 묶음 제목은 픽셀 + 1px 밑줄.
- "세션": 폴더 / 상태 / id(고정폭) / 출처(훅·로그·훅 + 로그) / 마지막 활동. 미선택이면 "세션을 고르면 정보가 보입니다".
- "노드": 종류 / 상태 / 시작 / 시간 / 토큰, 없는 값 "—". 노드 미선택이면 묶음을 숨긴다.
- "설정"(R4): 훅 상태(확인 중… / 설치됨 / 설치 안 됨 / ✕ 확인 실패: 사유) / [설치] [제거] / 결과 줄(`role="status"`: 처리 중… / 성공 · 백업: 경로 / ✕ 오류: 사유) / 평문 토큰 안내 / allowedHttpHookUrls 안내 / 대상 settings 경로 / 로그 폴더 경로 / 액정 폴더 경로 + [폴더 열기]. 처리 중에는 버튼 비활성(점선 테두리, 진회색 글자).
- 내용이 넘치면 패널 안에서 스크롤.

**게임기 화면**: 그림 있음 = 액정에 그림 / 빈(폴더 없음·비었음·읽기 실패) = 빈 연회색 액정, 글자 없음(d56). 액정은 버튼(`aria-label` "다음 그림"), 그림이 없으면 비활성. "폴더 열기" 실패는 설정 결과 줄에 "✕ 오류".

**공통 상호작용**: 버튼 hover = 반전. 포커스 = `outline 2px solid ink, offset 2px`, 베젤 위 액정만 paper 색 outline(ink는 진회색 위 2.6:1이라 부족).

## 5. 토큰

`design/tokens.json`. 색은 4명암 네 값만 있고 나머지는 그 참조다. 새로 넣은 토큰은 전부 이 run에서 처음 만든 것이므로 근거를 줄로 단다.
- `color.*`, `border.panel`, `border.panel-shadow`, `radius.panel`, `space.panel-gap`: d35, d36.
- `font.family.pixel`: d37. `@font-face`는 Galmuri 파일을 넣는 태스크에서 추가(시안은 대체 글꼴만).
- 그 밖(`space.1~4`, `border.box*`·`chip`·`focus*`, `radius.box/bezel`, `font.size.*`, `graph.*`, `layout.*`, `motion.*`): Designer가 정함, 7절 목록.

## 6. 접근성

- 대비(계산값): ink/paper 16:1, ink/light 8.2:1, dark/paper 6.0:1, paper/ink(반전) 16:1 — 본문 AA 통과. **dark/light는 3.2:1**이라 진회색 글자를 연회색 위에 두지 않는다(대기 노드의 보조 글자는 ink).
- 색을 쓰지 않으므로 상태는 기호 + 문구로 구분된다. 기호는 `aria-hidden`, 상태 이름은 보이는 문구 또는 시각 숨김 텍스트로.
- 선택: 세션 줄·노드 버튼에 `aria-current="true"`(N11). `▶`는 장식(`aria-hidden`).
- 그래프 간선 SVG는 `aria-hidden`, 노드는 `<ol aria-label="에이전트">` 안의 버튼. Tab 순서: 상단 바 → 세션 → 그래프 → 상세 → 채팅 → 액정.
- 깜빡임(`!` 1초 주기, 초당 1회)·흐르는 점선·진행 막대는 `prefers-reduced-motion: reduce`에서 멈춘다.
- 클릭 영역 최소 24×24px(버튼 min-height 24, 세션 줄·노드는 더 큼).
- 로그·페이로드 문자열(폴더 이름, agent_type, 파일명)은 텍스트로만 넣는다. 긴 이름은 말줄임, 전체는 상세 패널에서 `overflow-wrap: anywhere`.

### Designer가 새로 정한 것 (DESIGN 승인 때 사용자가 볼 것)
1. **세션 "멈춤(추정)" 기호 = `?`**. 다른 표시 없음.
2. **노드 "알 수 없음" = 기본 상자 + `—` + 문구 "알 수 없음"**(BRIEF 권고를 표기로 옮김). "끝남"과는 문구와 `—`로만 구분된다.
3. 세션 "작업 중" 기호 = 작은 진행 막대, "완료" = 기호 없음.
4. 진행 막대는 불확정(칸이 지나가는) 막대. 토큰 사용량 게이지(d38)는 값이 없어 이번엔 안 씀.
5. 흐르는 점선은 실행 중 노드로 가는 간선에만, 나머지 간선은 멈춘 점선.
6. 칩 축소 기준: 한 묶음(세션 목록, 그래프 한 열)에 **6개 이상**이면 칩(d44 예시는 4개 이하 큰 상자 — 기본 창 900px 높이에 5개가 들어가서 5로 올림). **[그래프에 대해 개정으로 대체됨: R10, 9절. 세션 목록은 그대로]**
7. 열 비율 `minmax(220px,1fr) / 2.6fr / minmax(280px,1.2fr)`, 행 비율 위 3 : 아래 2. 1400×900에서 채팅·게임기 높이 324px.
8. 글자 크기: 픽셀 12px, 앱 이름 24px, 본문 13px, 보조 11px. Galmuri11이 12px에서 선명한지는 글꼴 파일을 넣은 뒤 확인(미확인).
9. 일반 글꼴 `"Segoe UI", system-ui`, 고정폭 `"Cascadia Mono", Consolas`.
10. 최소 창 960×640, 그보다 작으면 창 전체 스크롤. 패널 안 내용이 넘치면 패널 안 스크롤.
11. 노드 168×60px, 같은 열 노드 간격 10px, 단계 간격 80px. 노드·버튼은 모서리 0, 베젤은 `6px 6px 24px 6px`. **[간격·노드 모서리는 개정으로 대체됨: 9절 — 세로 12px, 열 48px, 노드 6px. 버튼·세션 줄은 0 그대로]**
12. 포커스 링 2px ink(베젤 위 액정만 paper), 버튼 hover 반전, 비활성 = 점선 테두리 + 진회색 글자.
13. 노드 선택 표시는 이름 앞 `▶`(노드 상자 밖이 아니라 안).
14. 메인 노드 이름은 "Lead"(d46 표현). 하네스를 안 쓰는 세션에서도 같은 이름.
15. 시각 형식: 오늘이면 `HH:MM`, 아니면 `MM/DD HH:MM`.
16. 상단 바 앱 이름 "ORBIT"(픽셀 24px), 오른쪽에 서버 상태.

## 8. 시각 확인 (시안)

`design/reference/layout_v4.html`을 브라우저 도구로 file://로 열어 1400×900에서 확인: 상단 바(8,8,1384×58) / 세션(8,74,285×486) / 그래프(301,74,741×486, 가운데 위, Lead 왼쪽 → 서브에이전트 5개 오른쪽 세로 쌓임 **[한 열 배치는 개정으로 대체됨: 9절]**) / 상세(1050,74) / 채팅(8,568,1034×324, 두 열) / 게임기(1050,568,342×324, 채팅과 같은 높이, 독립 상자). 960×640에서는 깨지지 않고 그래프·상세가 패널 안에서 스크롤. ## 9. 개정 (사용자 결정 10~13)

근거: run DECISIONS R10(항상 큰 상자), R11(노드 모양 E), R12(단계 열), R13(열 규칙 "다음 열로"). 정확한 값의 출처는 `design/reference/graph_variants.html`의 E와 배치 2. 기준 시안 `layout_v4.html`의 그래프 부분을 이것으로 바꿨다. 4명암·색 없음, 패널 배치, 직각 네모 점선 간선, 기호로 상태 구분은 그대로다. 위 절에서 이 개정과 어긋나는 줄에는 "개정으로 대체됨"을 달았다. 3절의 "1단계만"(R9)은 부모-자식 깊이(손자·Workflow 노드 없음)만 뜻하고 열 배치를 막지 않는다(R12).

### 9.1 노드 상태 (E "작은 RPG 대화창")

모든 노드: 168×60, 모서리 6px(`radius.node`), 바탕 paper, 줄 셋(16px씩) = 이름(픽셀, 선택 시 앞 `▶`) / 상태 문구 + 오른쪽 기호 / 셋째 줄. 칩은 없다(R10).

| 상태 | 테두리 | 안쪽 이중선(box-shadow) | 바탕 | 기호 | 셋째 줄 | padding |
|---|---|---|---|---|---|---|
| 실행 중 | 3px solid ink (`border.node-run`) | paper 2px 틈 + ink 1px 선 (`border.node-run-shadow` = 패널과 같음) | paper | 없음 | 알약형 진행 막대(모서리 4px, 채움 2px) | 3px 9px |
| 끝남 | 2px solid ink (`border.node`) | paper 2px 틈 + ink 1px 선 (`border.node-shadow`) | paper | 없음 | "시간 · 토큰"(dark, 없으면 "—") | 4px 10px |
| 대기 | 2px solid ink | **light** 2px 틈 + ink 1px 선 (`border.node-shadow-wait`) | light | 깜빡이는 `!` | "권한 요청"(ink) | 4px 10px |

- padding은 테두리가 2→3px가 될 때 안쪽 칸을 48px(16×3)로 유지하려는 값이다.

### 9.2 단계 열 배치

- 열 규칙(R13): 시작·종료 시각만 쓴다. 시작 순으로 놓되, 지금 마지막 열의 노드 중 **하나라도 끝난 뒤에** 시작한 노드는 새 열을 연다. 그렇지 않으면 마지막 열에 들어간다. Lead는 항상 0열. 예: Lead | architect | plan-checker | engineer×3 | reviewer.
- 좌표: 열 x = 열번호 × (168 + 48)(`graph.stage-gap-x` 48px). 같은 열은 세로로 쌓고 간격 12px(`graph.node-gap-y`), 열 안 순서는 시작 순. 모든 열은 가장 높은 열의 세로 가운데에 맞춘다(열 높이 = n×60 + (n−1)×12).
- 간선(Lead와 첫 열 사이도 같은 규칙): 앞 열 각 노드의 오른쪽 가운데 → 앞 열 오른쪽 +24px(`graph.edge-bus-x`)의 세로 버스 → 다음 열 각 노드의 왼쪽 가운데. 버스 세로선은 양쪽 노드 가운데 중 가장 위~가장 아래. 1:1이고 높이가 같으면 곧은 선 하나. 선은 2px, 점선 4 4, `crispEdges`.
- 흐름 표시(`.flow`)는 **실행 중 노드로 들어가는 가지**(버스 → 그 노드 왼쪽)에만. 버스·나가는 선·다른 가지는 멈춘 점선.
- 넘칠 때: 노드 크기는 줄이지 않는다. 그래프 패널의 제목 아래 영역 전체가 스크롤 상자(`overflow: auto`, 가로·세로 모두, 안쪽 여백 4px `graph.scroll-pad`로 가장자리 포커스 링이 잘리지 않게). 가로 스크롤 막대는 패널 아래쪽, 세로는 오른쪽. 처음 위치는 위.
- 자동 이동: 새 열이 생기거나 노드 상태가 바뀌면, 실행 중 또는 대기 노드가 있는 가장 오른쪽 열이 보이게 옮긴다(`scrollIntoView({inline: "end", block: "nearest"})` — 그 열 오른쪽 끝을 보이는 오른쪽 끝에 맞춰 앞 열들이 왼쪽에 남게). 사용자가 직접 스크롤했거나 노드를 골랐으면 그 노드가 보이게만 하고(`nearest`) 강제로 끌어가지 않는다. `prefers-reduced-motion`이면 `behavior: "auto"`(부드러운 스크롤 없음).
- 시안의 모습: 1400×900에서 그래프 패널 안 보이는 폭 703px, 그림 폭 1032px → 오른쪽 끝으로 옮긴 상태(plan-checker 일부 · engineer×3 · reviewer 보임, Lead·architect는 왼쪽으로 스크롤해야 보임).

### 9.3 접근성

- 실행 중은 테두리 굵기(2→3px)로만 끝남과 모양이 달라 보이지만, 상태 문구 "실행 중"(보이는 텍스트)과 진행 막대로도 전달된다. 진행 막대는 `aria-hidden`, 상태는 문구가 맡는다.
- 포커스 링 `outline 2px ink, offset 2px`는 둥근 모서리를 따른다(Chromium/WebView2는 outline이 border-radius를 따름). 스크롤 상자 안쪽 여백 4px로 링이 잘리지 않는다.
- 대비: 노드 글자 ink/paper 16:1, 대기 노드 ink/light 8.2:1(보조 글자도 ink), 끝남 보조 글자 dark/paper 6.0:1, 테두리·이중선 ink/paper 16:1, ink/light 8.2:1. dark/light 조합은 쓰지 않는다.
- 스크롤 상자는 키보드로도 닿는다: 노드 버튼에 Tab으로 가면 브라우저가 그 노드를 보이게 스크롤한다. 간선 SVG는 `aria-hidden`, 노드 순서는 `<ol>` 안에서 열 순 → 열 안 시작 순.

### 9.4 토큰 (추가·삭제)

추가: `radius.node` 6px, `radius.pbar` 4px, `radius.pbar-fill` 2px, `border.node`, `border.node-shadow`, `border.node-shadow-wait`, `border.node-run`, `border.node-run-shadow`, `border.node-fail`, `graph.node-pad` 4px 10px, `graph.node-pad-run` 3px 9px, `graph.edge-bus-x` 24px, `graph.scroll-pad` 4px. 바꿈: `graph.node-gap-y` 10→12px, `graph.stage-gap-x` 80→48px(배치 2 값; E 비교 때의 96px은 한 열 배치용이라 쓰지 않음). 삭제: `graph.chip-threshold`(그래프 칩 없음). `role.inverse-*`·`border.chip`은 버튼 hover·세션 칩·묶음 밑줄에 계속 쓰여 남긴다. 모두 사용자 결정 R10~R13을 값으로 옮긴 것이다.

`layout_v4.html`을 file://로 1400×900에서 열어 확인: 패널 위치·크기는 8절과 같음(상단 8,8,1384×58 / 세션 8,74,285×486 / 그래프 301,74,741×486 / 상세 1050,74,342×486 / 채팅 8,568,1034×324 / 게임기 1050,568,342×324). 그래프는 E 모양·단계 열, 오른쪽 끝으로 스크롤된 모습. 계산된 색은 4명암뿐. 키보드 포커스 링 모양, 960×640, reduced-motion은 이번에 보지 않았다.
