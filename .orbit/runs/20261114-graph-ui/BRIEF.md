# BRIEF — 20261114-graph-ui (마일스톤 ④ 화면)

근거: STATE.json `request`, 이 run의 DECISIONS.md 1~5(확정, BRIEF보다 우선), `.orbit/decisions.md` "화면 디자인 방향 확정" 절의 "최종"·"확정" 줄(기준 시안 `orbit_gameboy_rpg_layout_v4`), RESEARCH.md. 이 BRIEF는 디자인을 정하지 않는다.

## 문제

지금 화면(`src/App.tsx`)은 세션 id·경로·날짜를 이어 붙인 줄과 도구 호출 타임라인만 보여 준다. 그래서 Orbit만 봐서는 "지금 어느 세션에서 어떤 에이전트가 돌고 있고, 어디서 멈췄거나 실패했는지"를 알 수 없다. 사용자가 원하는 결과를 한 문장으로 쓰면 이렇다.

> 터미널 대신 Orbit 창 하나만 보고도, 사용자가 이미 확정한 게임기 RPG 화면에서 각 세션의 상태와 그 세션의 에이전트 흐름(Lead → 서브에이전트, 가로)을 바로 읽을 수 있다.

## 누구를 위한 것

- Orbit 사용자 한 명(개인용). Claude Code를 터미널에서 돌리면서 Orbit을 옆에 띄워 두는 개발자다. 오르빗 저장소의 하네스 run(Lead → engineer → reviewer…)을 지켜보는 것도 여기에 들어간다.
- 배포용이 아니다. 배포로 바뀌면 캐릭터 그림 저작권 판단(decisions.md ⓒ)을 다시 한다.

## 범위 안

가장 작은 버전: 확정 배치를 그대로 만들고, 세션 상태와 1단계 에이전트 그래프를 지금 메모리 모델 위에서 그린다. 액정에 그림을 띄우고, 기존 훅 설치·제거 기능을 옮긴다.

1. **배치와 디자인**: 상단 바 / 왼쪽 위 세션 / 가운데 위 그래프 / 아래(왼쪽+가운데) 채팅 / 오른쪽 열은 상자 두 개(위 상세·하네스, 아래 게임기 화면). 게임기 화면의 높이는 채팅 패널과 같다. 4명암만 쓰고 상태 색은 쓰지 않으며, 상태는 기호(`✕`, `!`, 진행 막대, 반전)로만 구분한다. 화면 문구에 "관문"은 쓰지 않고 필요하면 "체크포인트"라고 쓴다. 중계창은 만들지 않는다. "최종·확정" 줄이 뒤집지 않은 같은 절의 결정(제목·메뉴만 픽셀 글꼴, 많아지면 칩으로 축소, 그래프 가로 흐름, 패널마다 격자 칸 명시)도 그대로 따른다(decisions.md 68행이 경위로 돌린 것은 타임라인·승인창·중계·상태 색뿐이다).
2. **Designer 산출물**: `DESIGN.md`, `design/tokens.json`, 그리고 기준 시안 HTML 파일. 시안은 지금 파일로 남아 있지 않다(decisions.md 70행). 확정 줄을 그대로 옮겨 다시 만든다.
3. **세션 목록**: 한 줄에 "폴더 이름 + 상태 기호 + 마지막 활동 시각"을 보인다. 상태는 작업 중 · 대기(권한 요청) · 완료 · 에러다. id와 출처는 세션을 골랐을 때 상세 패널에 보인다. 선택은 `▶` 메뉴 커서로 표시한다.
4. **에이전트 그래프(가로)**: 고른 세션의 메인(Lead) 노드에서 오른쪽으로 서브에이전트 노드가 이어진다. 데이터는 SubagentStart/Stop 훅과 메인 세션 로그의 Agent 도구 호출이다(DECISIONS 2). 노드에는 종류 이름과 상태(실행 중 = 반전 + 진행 막대, 실패 = 점선 테두리 + `✕`, 대기 = 회색 바탕 + 깜빡이는 `!`, 완료 = 기본 상자)를 붙인다. 토큰·소요 시간은 얻을 수 있을 때만 보이고, 없으면 빈칸이나 "—"로 둔다. 노드를 누르면 상세 패널에 그 노드 정보가 나온다. `agent_type`이 빈 문자열인 SubagentStop(내부 에이전트)은 노드로 만들지 않는다.
5. **Rust 세션 모델 확장**: 지금 버리는 `agent_id`·`agent_type`·상태 계열 이벤트(Stop, StopFailure, PermissionRequest, Notification, SessionEnd, SubagentStart/Stop)를 화면에 필요한 만큼만 담는다. 메모리에만 둔다(DECISIONS 3).
6. **채팅 패널**: 틀과 빈 상태만 만든다. 입력 줄은 비활성이고 "⑥에서 연결" 안내를 붙인다(DECISIONS 1).
7. **상세·하네스 패널의 "설정" 묶음**: 훅 설치·제거 버튼, 훅 상태, 평문 토큰 안내, allowedHttpHookUrls 안내, 대상 settings 경로, 로그 폴더 경로, 액정 "폴더 열기" 버튼을 여기에 모은다(DECISIONS 4).
8. **게임기 액정**: 앱 데이터 폴더 아래 `screens/`(Windows `%APPDATA%\dev.orbit.app\screens`)에서 PNG·JPG·GIF·WebP만 고른다. 확장자 검사는 Rust에서 하고 SVG는 뺀다. 앱 시작 때 무작위로 하나를 보이고, 5분마다 다른 파일로 바꾸며, 액정을 누르면 바로 다음 그림으로 넘어간다. 폴더가 비어 있으면 빈 액정이다. 그림은 `object-fit: contain`, `image-rendering: pixelated`로 그린다. Tauri asset 프로토콜의 허용 범위는 그 폴더 하나로 한정하고, 경로는 정규화한 뒤 범위를 검사한다. Orbit은 기본 그림을 넣지 않는다.
9. **픽셀 글꼴 번들**: Galmuri11(OFL 1.1)의 woff2 파일을 저장소에 넣고, 라이선스 전문·저작권 줄·출처(버전·커밋)를 함께 둔다. 원격으로 불러오지 않는다.
10. **기존 화면에서 지울 것**: 타임라인 패널과 도구 호출 목록, 세션 줄의 id·경로·날짜 나열.
11. **SPEC.md 문구 맞춤**(librarian): "화면 3. 타임라인"을 확정 디자인에 맞춘다(도구 호출 목록은 화면에 두지 않는다). 58행·77행 "그래프 · 타임라인" 언급, 46행 "노드 색"(색 없음 확정 → 상태 기호), 45행 Dynamic Workflow 노드와 "React Flow 추천"을 이번 범위와 어긋나지 않게 고친다. 다른 절은 건드리지 않는다.
12. **④에서 보기로 미뤄 둔 참고 항목** 중 이번 변경이 닿는 것: N1(`timestamp` 없는 줄이 `last_ms`를 "지금"으로 끌어올림. 세션 줄의 마지막 활동 시각이 거짓이 된다), N2(늦게 온 훅이 빈 tool 이름을 못 채움. 노드 이름에 영향), N3(listen 등록 전 update 유실), N5·N6, N11(접근성: 선택은 `aria-current`, 버튼 이름에 의미 있는 레이블, 대비), W7(`phase`·`source` enum, 모델을 손대는 김에), Security A5(프론트 세션 맵을 `Map`으로 — `"__proto__"` 세션 id 대응). 나머지 N4·N7~N10·N12~N16은 이번 변경이 그 줄을 건드릴 때만 본다.

## 범위 밖

- 액정 안의 캐릭터 연출(사용자가 직접 넣는다), 기본 그림 동봉.

## 성공 기준

검증은 실제 `~/.claude`를 쓰지 않는다. ②·③에서 쓴 환경변수 방식으로 임시 사본을 가리킨다: `ORBIT_CLAUDE_SETTINGS=<임시>\settings.json`, `ORBIT_CLAUDE_PROJECTS=<임시>\projects`(또는 `CLAUDE_CONFIG_DIR=<임시>`). 실제 세션을 돌리려고 사본에 인증 파일을 복사했다면 검증이 끝난 뒤 지운다. 액정 폴더는 Orbit 자신의 앱 데이터 폴더이므로 실제 경로를 쓰되, 검증용으로 넣은 그림은 끝나고 지운다.

1. `cargo test`(`src-tauri/`에서)가 0으로 끝나고, 새로 넣은 그래프·상태 판단·그림 목록(확장자 필터·범위 검사) 로직마다 테스트가 하나 이상 있다.
2. `npm.cmd run build`가 0으로 끝난다.
3. `node --test harness/hooks/gate.test.mjs`가 0으로 끝난다(회귀 확인).
4. `npm.cmd run tauri dev`로 띄운 앱의 스크린샷을 Designer가 시각 리뷰한 결과가 "확정 배치와 같다"다. 확인할 것은 다음과 같다. 상단 바 / 왼쪽 위 세션 / 가운데 위 그래프 / 아래 두 열 너비의 채팅 / 오른쪽 위 상세·하네스 / 오른쪽 아래 독립된 게임기 화면이 있다. 게임기 화면과 채팅의 높이가 같다. 4명암 외의 색이 없다. 패널은 이중 테두리다. 제목과 메뉴는 픽셀 글꼴이다.
5. 임시 사본 환경에서 서브에이전트를 하나 이상 부르는 실제 Claude Code 세션을 돌린다. 그동안 그 세션을 고르면 그래프 왼쪽에 메인 노드가 있고, 오른쪽에 서브에이전트 노드가 종류 이름과 함께 나타난다. 노드는 도는 동안 "실행 중"(반전 + 진행 막대)이고, 끝나면 "완료"(기본 상자)로 바뀐다. 노드를 누르면 상세 패널에 그 노드 정보가 보인다.
6. Orbit을 끈 상태에서 끝난 그 세션은, Orbit을 다시 켜면 메인 로그의 Agent 도구 호출로 서브에이전트 노드가 다시 그려진다. 얻지 못한 값은 "—"로 보인다.
7. 세션 목록의 각 줄은 "폴더 이름 + 상태 기호 + 마지막 활동 시각"만 보이고, 긴 id나 전체 경로를 이어 붙이지 않는다. 세션을 고르면 id와 출처가 상세 패널에 보인다. 권한 요청 중인 세션은 대기 기호, 끝난 세션은 완료 기호, StopFailure를 받은 세션은 에러 기호다.
8. `screens/`에 PNG·GIF를 각각 하나 넣고 앱을 켜면 액정에 둘 중 하나가 잘리지 않고 보인다. 액정을 누르면 다른 그림으로 바뀐다. 폴더를 비우면 빈 액정이다. 같은 폴더의 `.svg`, 그리고 폴더 밖을 가리키는 이름(`..\` 포함)은 Rust 명령의 목록에 나오지 않는다. "폴더 열기"를 누르면 탐색기에 그 폴더가 열린다.
9. "설정" 묶음의 설치 버튼을 누르면 임시 `settings.json`에 훅이 병합되고 백업 경로가 표시되며, 훅 상태가 "설치됨"이 된다. 제거를 누르면 항목이 빠지고 "설치 안 됨"이 된다. 기존 항목은 남는다(②와 같은 동작).
10. 앱 화면 어디에도 타임라인 패널, 도구 호출(Read·Bash 등) 목록, "관문"이라는 단어, 중계창이 없다. `src/`를 검색해도 화면에 보이는 문자열로 "관문"이나 "타임라인"이 나오지 않는다.
11. 채팅 패널의 입력 줄은 비활성이고 "⑥에서 연결" 안내가 보인다.
12. SPEC.md의 화면 절과 1단계 완료 기준에 도구 호출 타임라인을 화면에 둔다는 문구가 없고, 확정 디자인(타임라인 없음, 색 없음, 넓은 채팅, 가로 그래프)과 어긋나는 문장이 남아 있지 않다. `git diff SPEC.md`가 그 절들만 바꾼다.
13. 로그·페이로드에서 온 문자열(에이전트 종류, 폴더 이름, 파일명 등)은 텍스트로만 렌더된다. `src/`에 `dangerouslySetInnerHTML`이 없다. `<b>x</b>` 같은 agent_type을 담은 훅을 보내면 화면에 글자 그대로 보인다.
14. `tauri.conf.json`의 asset 프로토콜 scope가 `screens/` 폴더 하나뿐이다. capability에는 이 기능에 필요한 것 이상이 추가되지 않았다(diff로 확인).
15. Galmuri 글꼴 파일 옆에 OFL 전문과 저작권 줄이 있고, 출처(버전·커밋)가 기록되어 있다. 앱은 네트워크 없이도 픽셀 글꼴로 보인다.

## 열린 질문

사용자가 아직 정하지 않았고 RESEARCH.md가 드러낸 것만 적는다. 권고안을 붙였다.

1. **서브에이전트 "실패"는 무엇으로 판단하나.** SubagentStop에는 성공·실패 필드가 없다. Agent 도구가 실패할 때 PostToolUseFailure가 오는지는 문서가 보장하지 않는다(미확인). 로그의 오류 표시 필드도 미확인이다.
   - 권고: 실패(`✕`)는 Agent 도구의 PostToolUseFailure, 또는 로그 `tool_result`에 오류 표시가 확인될 때만 쓴다. 그 밖의 종료는 "완료"가 아니라 "끝남"으로 읽히는 기본 상자로 둔다. SPEC의 "성공"은 "끝남"으로 고친다.
   - 위험: 실패한 서브에이전트가 화면에 끝남(완료)으로 보일 수 있다. 사용자가 그 결과를 믿고 넘어가면, 실패한 engineer·qa 결과를 놓친 채 다음 단계로 간다. 이 표시는 모든 세션의 모든 서브에이전트에 적용된다.
2. **사용자가 Esc로 중단한 세션은 언제 "작업 중"에서 빠지나.** 중단하면 Stop이 오지 않으므로 그 세션은 "작업 중"으로 영원히 남는다. 권한 대기도 응답 이벤트가 없어 풀리지 않을 수 있다.
   - 권고: 마지막 이벤트 후 10분 동안 아무것도 오지 않으면 "멈춤(추정)" 기호로 바꾸고, 새 이벤트가 오면 다시 작업 중으로 돌린다. 권한 대기는 다음 Pre/PostToolUse·Stop·StopFailure·SessionEnd에서 해제한다. Notification `idle_prompt`는 입력 대기로 본다.
   - 위험: 10분 넘게 출력 없이 도는 Bash나 긴 서브에이전트가 "멈춤"으로 잘못 보인다. 반대로 기준을 길게 잡으면 죽은 세션이 그만큼 오래 "작업 중"으로 보인다. 표시만 바뀌고 Claude Code에는 영향이 없다. 재시작하면 훅 기반 상태가 사라져(DB 없음) 로그 시각만으로 다시 판단한다.
3. **CSP를 이번에 켜나.** 지금 `tauri.conf.json`은 `"csp": null`이다. 액정 때문에 asset 프로토콜을 켜고 로그·페이로드 문자열을 화면에 더 많이 뿌리게 된다. CLAUDE.md 체크리스트는 "CSP가 필요한 최소인가"를 요구하고, decisions.md 59행은 "CSP `img-src`는 asset 출처만 추가"를 전제로 한다.
   - 권고: 이번에 켠다. `default-src 'self'; img-src 'self' asset: http://asset.localhost; font-src 'self'; style-src 'self' 'unsafe-inline'`에서 출발하고, Vite dev 연결이 깨지면 `devCsp`를 따로 둔다. 실행해서 확인한다.
   - 켜지 않을 때의 위험: 렌더링 실수 하나로 페이로드 속 스크립트가 webview에서 실행되면, 그 스크립트가 capability가 허용하는 Rust 명령을 부를 수 있다. 사용자의 전역 `~/.claude/settings.json` 훅 설치·제거와 폴더 열기가 여기에 들어간다. 원격 출처 로드에도 제한이 없다.
   - 켤 때의 위험: 설정이 틀리면 dev나 빌드 앱이 빈 화면이 되거나 글꼴·그림이 안 뜬다. QA 실행에서 드러난다.
4. **과거 세션(Orbit이 꺼져 있던 동안) 그래프를 메인 로그의 Agent 도구 호출만으로 그리면 무엇이 빠지나.**
   - 채울 수 있는 것(추정): 노드의 존재, `description`, 시작 시각(`tool_use`)과 끝난 시각(`tool_result`).
   - `input.subagent_type`이 로그에 실제로 있는지, 로그 `tool_result`에 토큰·소요 시간이 담기는지는 미확인이다.
   - 못 채우는 것: 손자 노드, Workflow 노드, 실패 여부(1번), 백그라운드 서브에이전트의 실제 종료(로그의 `tool_result`는 `async_launched` 시점일 수 있다), `tool_result` 없이 끊긴 호출의 상태.
   - 권고: 있는 값만 보이고 나머지는 "—"로 둔다. `tool_result`가 없는 노드는 "실행 중"이 아니라 "알 수 없음/끊김"(기본 상자 + "—")으로 둔다. 노드 종류 이름이 없으면 `description`을 쓴다. 서브에이전트 파일 파싱은 하지 않는다(DECISIONS 2).
   - 위험: 오래된 세션이 영원히 실행 중으로 보이거나, 실패한 run이 정상처럼 보인다.
5. **라이브 노드의 부모-자식 짝짓기.** SubagentStart에는 `tool_use_id`가 없다. 시작 시점에는 Pre(Agent)와의 순서·`agent_type`으로 추정해야 하고, 확정은 PostToolUse(Agent) `tool_response.agentId`가 와야 된다(끝날 때만).
   - 권고: ④는 1단계(메인 → 서브에이전트 평면)만 그린다. 그러면 짝짓기는 노드 위치가 아니라 Agent 호출과 노드를 합칠 때(토큰·시간 붙이기)만 쓰인다. 확정 전에는 별개 노드로 두고, 끝날 때 합친다.
   - 위험: 같은 종류를 병렬로 부를 때 실행 중에는 한 노드가 두 개로 보이거나 잘못 합쳐질 수 있다.
6. **`screens/` 폴더가 없을 때.** 권고: 앱은 폴더를 만들지 않고 빈 액정을 보인다. "폴더 열기"를 누르면 그때 폴더를 만들고 연다. RESEARCH 미확인 항목(`$APPDATA` scope와 `app_data_dir()`가 같은 폴더인지, `openPath`의 폴더 동작, Rust 쪽 open의 scope 면제 여부)은 PLAN에서 실행으로 확인한다.

새 의존성(그래프 라이브러리 포함)은 PLAN 승인 때 사용자에게 보인다(DECISIONS 5). BRIEF는 이를 정하지 않는다.
