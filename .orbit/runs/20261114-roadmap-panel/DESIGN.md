# DESIGN — 20261114-roadmap-panel (마일스톤 ⑤: 로드맵 패널 + 노드 이름)

디자인 문법은 다시 정하지 않는다: 4명암·색 없음, 이중 테두리 패널, layout_v4 배치, 그래프 E 모양·단계 열, 게임기 화면(`.orbit/decisions.md` "화면 디자인 방향 확정" 절의 최종·확정 줄, run 20261114-graph-ui DESIGN.md 3·9절). 이 문서의 `Dn`은 이 run DECISIONS.md의 n번.

- 기준 시안: `design/reference/layout_v4.html` (갱신: 오른쪽 위 = 로드맵, 상단 바 오른쪽 = 훅 상태·버튼). 스크립트·외부 요청 없음.
- 토큰: `design/tokens.json` (`roadmap.*`, `topbar.*` 추가)

## 1. 사용자 흐름

1. Orbit을 켠다 → 상단 바 오른쪽에 서버 상태 · 훅 상태 · `설치`|`제거` · `액정 폴더`. 오른쪽 위 로드맵 패널은 "세션을 고르면 그 프로젝트의 로드맵이 보입니다".
2. 세션 줄을 누른다 → 로드맵 패널이 그 세션 cwd의 `ROADMAP.md`를 읽어 "완료 / 전체" + 막대 + 묶음별 항목을 보인다(D1, D5). 30초마다 다시 읽는다(D2).
3. 그래프 노드를 누른다 → 이름 앞 `▶`만 바뀐다(D7). 다른 패널은 변하지 않는다.
4. 훅을 되돌리려면 상단 바 `제거` → 결과 줄에 "처리 중…" → "성공 · 백업: 경로" → 훅 상태가 "훅 설치 안 됨", 버튼이 `설치`로 바뀐다(D4).
5. `액정 폴더` → 탐색기로 폴더가 열린다. 실패하면 결과 줄에 "✕ 오류: 사유".

## 2. 화면과 상태

### 2.1 로드맵 패널 (오른쪽 위, 격자 칸 `grid-column: 3; grid-row: 2` 그대로)

제목 `h2` "로드맵"(픽셀). 아래 상태 중 하나. 안내 문구는 모두 기존 `.empty`(dark/paper), 보조 줄은 기존 `.note`.

| 상태 | 화면 |
|---|---|
| 세션 미선택 | `.empty` "세션을 고르면 그 프로젝트의 로드맵이 보입니다" |
| 불러오는 중 | `.empty` "불러오는 중…" — 세션을 새로 골랐을 때만. 30초 재읽기 중에는 이전 내용을 그대로 둔다(깜빡임 없음) |
| ROADMAP.md 없음 (cwd 없음 포함) | `.empty` "ROADMAP.md가 없습니다" + `.note` "프로젝트 폴더 맨 위에 두면 여기 보입니다 — `## 묶음`, `- [ ] 할 일`, `- [x] 끝난 일`" |
| 항목 0개 | `.empty` "ROADMAP.md에 체크 항목이 없습니다" + 같은 `.note`. 요약 줄·막대 없음 |
| 너무 큼 | `.empty` "✕ ROADMAP.md가 너무 커서 읽지 않았습니다" + `.note` "한도: {크기 상한} · {항목 수 상한}개" (항목 수 상한 초과도 같은 상태) |
| 읽기 실패 (링크·정션 거부, 권한, 그 밖) | `.empty` "✕ 로드맵을 읽지 못했습니다" + `.note` "사유" (Rust가 준 문자열, 텍스트로만) |
| 정상 | 요약 줄 → (묶음 제목 없는 항목) → 묶음 제목 + 항목 목록 반복 |
| 정상 + 건너뛴 줄 | 정상 화면 맨 아래 `.note` "읽지 못한 줄을 건너뛰었습니다" (잘못된 UTF-8 줄). 건너뛰고 남은 항목이 0개면 "항목 0개" 상태 + 이 `.note` |

정상 상태의 모양 (시안에 그림):
- **요약 줄** `.rm-sum`: 왼쪽 "2 / 5"(픽셀 12px, `aria-hidden`), 오른쪽 남는 폭 전체에 **고정 진행 막대** `.rm-bar`. 막대 = 높이 8px, 1px ink 테두리, 모서리 4px, 안쪽 채움 ink·모서리 2px, 채움 폭 = 완료/전체 × 100%. 움직이지 않는다(그래프 `.pbar`의 지나가는 칸과 다름). 0%면 빈 막대, 100%면 꽉 찬 막대. 요약 줄 아래 12px.
- **묶음 제목**: `## 제목`의 글자를 기존 `.detail h3` 그대로(픽셀 12px + 1px 밑줄, 위 12px·아래 4px, 첫 묶음 위 0). 긴 제목은 줄바꿈.
- **묶음 제목 없는 항목**(첫 `##` 전의 항목): 요약 줄 바로 아래 같은 목록 모양, 제목 없음.
- **항목** `.rm li`: 두 칸 격자 — 16px 기호 칸 + 글자 칸. 기호 완료 `✓` / 미완료 `·`(픽셀 글꼴, ink, `aria-hidden`), 글자 앞 시각 숨김 "완료: " / "미완료: ". 글자는 **일반 글꼴 13px, ink**(완료·미완료 같은 색, 취소선 없음). 항목 사이 2px. 긴 항목은 글자 칸 안에서 줄바꿈되어 둘째 줄부터 첫 글자에 맞춰 들여쓰기, 띄어쓰기 없는 긴 낱말도 `overflow-wrap: anywhere`.
- **많을 때**: 패널 전체가 기존 `.panel`의 `overflow: auto`로 패널 안에서 세로 스크롤. 요약 줄도 함께 스크롤된다(고정하지 않음). 패널 크기는 그대로(960×640에서 항목 17개로 확인).
- 파일 순서 그대로, 정렬·접기 없음. 항목·제목 글자는 텍스트로만 렌더(`<b>` 등 글자 그대로).

### 2.2 상단 바 (한 줄 고정)

`ORBIT` | 결과 줄(남는 폭) | 서버 상태 `·` 훅 상태 `[설치|제거]` `[액정 폴더]`. 항목 사이 12px, 오른쪽 묶음 안 8px, `white-space: nowrap`. 높이는 그대로 58px(버튼 24px < 제목 줄 36px).

- **서버 상태**(기존 문구, 픽셀, `role="status"`): 최대 240px, 넘치면 끝 말줄임. "✕ 훅 서버 시작 실패: 사유"가 길어도 버튼을 밀지 않는다.
- **구분** `·`: 픽셀, dark, `aria-hidden`.
- **훅 상태**(픽셀, ink): "훅 확인 중…" / "훅 설치됨" / "훅 설치 안 됨" / "훅 ✕ 확인 실패". 확인 실패의 사유는 결과 줄에 "✕ 확인 실패: 사유"로.
- **버튼 하나**(기존 `.btn`: 24px, 픽셀 12px, 2px 테두리, 모서리 0, hover 반전):
  - 설치됨 → `제거`(aria-label "훅 제거") / 설치 안 됨 → `설치`(aria-label "훅 설치")
  - 확인 중·확인 실패 → `설치` 비활성
  - 처리 중 → 그 버튼 비활성(기존 `.btn:disabled`: 점선 테두리, dark 글자). 글자는 바꾸지 않는다. 끝나면 상태를 다시 읽고 버튼이 바뀐다.
- **`액정 폴더`**(aria-label "액정 폴더 열기"): 항상 활성.
- **결과 줄** `.tb-result`(`role="status"`, 일반 글꼴 11px, dark, 오른쪽 정렬, `flex: 1; min-width: 0`, 끝 말줄임, `title`에 전체 문구):
  - "처리 중…" → "성공 · 백업: 경로" / "성공 (백업 없음: 새 파일이거나 변경 없음)" / "제거할 항목 없음" / "✕ 오류: 사유"
  - 성공 문구는 10초 뒤 비운다. "✕"로 시작하는 문구는 다음 동작까지 남긴다.
  - 비어 있을 때는 빈 칸(자리만 차지).
  - 긴 백업 경로는 이 칸 안에서만 잘린다. 960 폭에서 이 칸은 약 316~418px(오른쪽 묶음 길이에 따라).
- 평문 토큰 안내 두 줄, settings·로그·액정 경로 세 줄은 화면에서 뺀다(D4).

### 2.3 세션 패널 오류 문구 (바꿈)

"✕ 로그 폴더를 읽지 못했습니다 — 설정 참고" → `.empty` "✕ 로그 폴더를 읽지 못했습니다" + (사유가 있으면) `.note` 사유(`projects_error`, 텍스트로만, `overflow-wrap: anywhere`). 사라진 "설정"을 가리키지 않는다.

### 2.4 그래프 노드 이름

규칙: 마지막 `:` 뒤만 보인다(`orbit:qa` → `qa`, 접두사 없으면 그대로), 메인 노드는 "Lead"(D3). 시안의 노드 이름(architect, plan-checker, engineer, reviewer)은 이미 접두사 없는 표기라 바꾸지 않았다. 노드 모양·말줄임·`▶`는 그대로. 노드 클릭은 `▶`만(D7).

## 3. 토큰

재사용: `color.*`(ink·dark·paper만), `font.family.pixel/body`, `font.size.pixel/body/meta`, `border.chip`(막대 테두리·묶음 밑줄), `radius.pbar`(4px)·`radius.pbar-fill`(2px), `space.1~4`, 기존 `.btn`·`.empty`·`.note`·`.sr`·`.detail h3`.

새 토큰(`design/tokens.json`):
- `roadmap.mark-col` 16px — 기호 칸 폭, 줄바꿈된 둘째 줄 들여쓰기 기준.
- `roadmap.item-gap` 2px — 항목 사이(기존 dl 줄 간격과 같은 값).
- `roadmap.bar-height` 8px — 고정 막대 높이(그래프 `.pbar`와 같은 값, 그쪽은 토큰이 없었음).
- `roadmap.summary-gap` 12px — 요약 줄과 첫 목록 사이.
- `topbar.gap` 12px — 상단 바 세 묶음 사이.
- `topbar.status-max` 240px — 긴 서버 오류가 버튼을 밀지 않게 하는 상한.

구현 메모(Engineer): 시안에서 지운 CSS(`dl/dt/dd`, `.path`, `.actions`)는 앱에서도 쓰는 곳이 없어지면 지운다. 패널 클래스는 격자 칸 때문에 `.detail`을 그대로 쓴다(`aria-labelledby`만 `h-roadmap`).

## 4. 접근성

- 완료/미완료: 기호는 `aria-hidden`, 항목 글자 앞 시각 숨김 "완료: " / "미완료: "(기호만으로 전달하지 않음).
- 진행 막대: `role="progressbar"`, `aria-label="로드맵 진행"`, `aria-valuemin=0`, `aria-valuemax=전체`, `aria-valuenow=완료`, `aria-valuetext="5개 중 2개 완료"`. 보이는 "2 / 5"는 중복 낭독을 막으려 `aria-hidden`.
- 목록은 `<ul>`, 묶음 제목은 `<h3>`, 패널은 `<section aria-labelledby="h-roadmap">`.
- 상단 바: 결과 줄과 서버 상태는 각각 `role="status"`. 버튼 접근성 이름은 보이는 글자를 포함("훅 제거" ⊃ "제거", "액정 폴더 열기" ⊃ "액정 폴더"). 말줄임된 결과도 낭독은 전체 문구.
- 대비: 항목·제목·훅 상태 ink/paper 16:1, 결과 줄·구분·안내 dark/paper 6.0:1, 막대 ink/paper. dark/light 조합 없음(로드맵·상단 바는 모두 paper 바탕).
- 포커스: 기존 `outline 2px ink, offset 2px`. 상단 바 버튼은 위아래 여백 안에서 링이 잘리지 않는다. 로드맵 패널은 버튼이 없어 Tab 순서는 상단 바(제거·액정 폴더) → 세션 → 그래프 → 채팅 → 액정.
- 클릭 영역: 버튼 24px 높이(기존 `layout.target-min`).
- 움직임: 로드맵 막대는 움직이지 않는다(reduced-motion 처리 불필요).

## 5. 새로 정한 것 (확정 줄·DECISIONS에 없어 Designer가 채운 값 — 승인 질문용)

1. 로드맵 항목 본문 글꼴 = **일반 글꼴 13px(Segoe UI)**. 이유: 항목은 긴 문장이 될 수 있고, 확정 줄이 픽셀 글꼴을 제목·메뉴·버튼·상태 문구로 한정함. 묶음 제목·"2 / 5"·기호는 픽셀 12px.
2. 기호 `✓`(완료) / `·`(미완료), 픽셀 글꼴, ink. 완료·미완료 글자색은 같고 취소선·흐림 없음.
3. 기호 칸 16px, 긴 항목은 둘째 줄부터 글자 칸에 맞춰 들여쓰기(매달린 들여쓰기). 항목 사이 2px.
4. 요약 줄 = 한 줄에 "2 / 5"(왼쪽) + 막대(오른쪽 남는 폭 전체), 사이 8px, 아래 12px. 사용자가 본 "맨 위 2 / 5 + 진행 막대"를 한 줄로 배치한 것.
5. 막대 = 높이 8px, 1px ink 테두리, 모서리 4px(알약형), 채움 ink·모서리 2px, 채움 폭 = 완료 비율, 고정(움직임 없음).
6. 묶음 제목 = 기존 상세 패널 h3 모양(픽셀 + 1px 밑줄, 위 12px·아래 4px).
7. 묶음 제목 없는 항목은 요약 줄 바로 아래에 제목 없이 같은 모양으로.
8. 많을 때 패널 전체가 세로 스크롤, 요약 줄은 고정하지 않음.
9. 상태 문구: "불러오는 중…"(첫 읽기만, 재읽기 땐 이전 내용 유지) / "ROADMAP.md가 없습니다" + 형식 안내 `.note` / "ROADMAP.md에 체크 항목이 없습니다" / "✕ ROADMAP.md가 너무 커서 읽지 않았습니다" + 한도 `.note`(항목 수 상한 초과 포함) / "✕ 로드맵을 읽지 못했습니다" + 사유 `.note` / 건너뛴 줄 `.note` "읽지 못한 줄을 건너뛰었습니다". (세션 미선택 문구는 D5 그대로.)
10. 상단 바 순서: `ORBIT` | 결과 줄 | 서버 상태 `·` 훅 상태 [버튼] [액정 폴더]. 구분 기호 `·`(dark). 묶음 사이 12px, 오른쪽 묶음 안 8px.
11. 훅 상태 문구: "훅 확인 중…" / "훅 설치됨" / "훅 설치 안 됨" / "훅 ✕ 확인 실패"(사유는 결과 줄).
12. 버튼 = 기존 `.btn` 크기 그대로(24px, 패딩 2px 12px). 확인 중·확인 실패면 `설치` 비활성, 처리 중이면 그 버튼만 비활성(글자 그대로), `액정 폴더`는 항상 활성. 버튼 글자 `제거`/`설치`/`액정 폴더`, 접근성 이름 "훅 제거"/"훅 설치"/"액정 폴더 열기".
13. 결과 줄: 일반 글꼴 11px dark, 오른쪽 정렬, 남는 폭에서 끝 말줄임 + `title`에 전체. 성공은 10초 뒤 지움, "✕" 오류는 다음 동작까지 유지.
14. 서버 상태 최대 240px, 넘치면 말줄임(기존에는 상한 없음).
15. 세션 패널 오류 문구: "✕ 로그 폴더를 읽지 못했습니다" + 사유 `.note`.
16. 시안 예시 데이터: 묶음 "1단계: 관찰"(완료 2) · "2단계: 화면"(미완료 3, 긴 항목 1개 포함), "2 / 5".

- **1400×900**: 패널 위치·크기가 ④ 9.5절과 같다 — 상단 8,8,1384×58 / 세션 8,74,285×486 / 그래프 301,74,741×486 / 로드맵 1050,74,342×486 / 채팅 8,568,1034×324 / 게임기 1050,568,342×324. 상단 바 `scrollWidth = clientWidth`(1378), 한 줄. 결과 줄 폭 858px, 백업 경로 전체 보임. 로드맵: 2 / 5 + 40% 막대, 묶음 2개, 긴 항목 3줄 줄바꿈·들여쓰기 정상, 패널 안 넘침 없음.
- **960×640**: 상단 8,8,944×58 / 세션 8,74,220×330 / 그래프 236,74,428×330 / 로드맵 672,74,280×330 / 채팅 8,412,656×220 / 게임기 672,412,280×220. 상단 바 한 줄(`scrollWidth = clientWidth` 938). 최악 조합(긴 서버 오류 + "훅 설치 안 됨" + 비활성 `설치` + 긴 백업 경로)에서도 한 줄·높이 58 그대로, 서버 상태 240px에서 말줄임, 결과 줄 316px에서 말줄임, 버튼 밀림 없음. 로드맵에 항목 17개를 넣으면 패널 높이 330 그대로, 패널 안 세로 스크롤.
- 로드맵 패널 안 계산된 색은 ink(+투명)뿐.
- **못 본 것**: Galmuri11 실제 글꼴(file://·스냅숏에서 글꼴 파일이 막혀 monospace 대체로 측정 — 앱에서 폭이 조금 다를 수 있음, 960 최악 조합에서 여유가 크지 않으니 QA가 실제 앱 960×640에서 다시 볼 것). 빈·로딩·오류 상태 화면(시안에는 정상만 그림). 키보드 포커스 링, reduced-motion, hover 반전 실제 모습. `orbit:design-system-guard` 스킬은 이 에이전트에 Skill 도구가 없어 불러오지 못했고 위 점검을 직접 했다.
