# BRIEF — 20261114-roadmap-panel (마일스톤 ⑤ 다시 정하기: 로드맵 패널 + 노드 이름)

근거: 사용자 요청 원문(2026-11-14, ④를 써 본 뒤) "지금은 중앙 그래프에 orbit:qa 이렇게 표현되는데 이거 고치고 싶고 오른쪽 상세 하네스 저거말고 로드맵 써놓고 진행 어떻게 되고 있나 그런거보고싶음" → "프로젝트 로드맵 보여주도록 상세정보 일단 필요없을듯 원래 오른쪽 패널에있떤것들 일단 필요없을듯". `.orbit/decisions.md` 15번(41~46행)과 "화면 디자인 방향 확정" 절의 "최종"·"확정" 줄. 기준 시안은 `design/reference/layout_v4.html`. 이 BRIEF는 디자인 문법을 다시 정하지 않는다(4명암, 색 없음, 이중 테두리, layout_v4 배치).

## 문제

오른쪽 위 패널(`src/App.tsx` 152~198행 "상세 · 하네스")에는 세션 id, 출처, 노드 정보, 훅 설치·제거 버튼, 경로 세 줄이 있다. 사용자는 이것들을 매일 보지 않는다. 사용자가 실제로 보고 싶은 것은 "이 프로젝트가 큰 계획에서 어디까지 왔나"인데, 그 정보는 지금 화면 어디에도 없다. 그래프 노드 이름도 `orbit:qa`처럼 플러그인 접두사가 붙은 내부 이름 그대로 보인다(`src/Graph.tsx` 39행 `a.kind ?? a.description`).

한 문장으로:

> 세션을 고르면 오른쪽 위에 그 프로젝트의 로드맵(사용자가 직접 쓴 큰 계획)과 그 진행 정도가 보이고, 그래프 노드 이름은 접두사 없는 역할 이름으로 읽힌다.

## 누구를 위한 것

- Orbit 사용자 한 명(개인용). 한 프로젝트를 여러 run과 세션에 걸쳐 진행하면서 전체 계획 가운데 어디쯤인지 한눈에 보고 싶은 개발자다. 첫 사용처는 오르빗 저장소 자신(마일스톤 ①~⑥)이다.

## 범위 안

가장 작은 버전은 이렇다. 로드맵 파일 하나를 읽기 전용으로 보여 주고, 기존 상세 패널 내용을 걷어 내고, 노드 이름 표시 규칙 한 줄을 바꾼다. 아래 괄호의 기본값은 열린 질문의 권고안이며, 사용자가 다르게 고르면 그에 따라 바뀐다.

1. **로드맵 패널**: 오른쪽 위 패널의 제목을 "로드맵"으로 바꾸고, 고른 세션의 작업 폴더(`Session.cwd`)에 있는 로드맵 파일을 보여 준다(위치·형식은 질문 a, e).
   - 항목마다 완료/미완료 표시를 붙인다.
   - 맨 위에 "완료 수 / 전체 수"와 기존 진행 막대 스타일의 막대를 둔다.
   - 세션을 고를 때와 기존 30초 타이머마다 다시 읽는다. 파일 감시(notify)는 쓰지 않는다.
2. **빈 상태와 오류 상태**: 세션을 고르지 않았을 때, 파일이 없을 때, 너무 크거나 읽을 수 없을 때 각각 한 줄 안내를 보인다. 어느 경우에도 앱은 죽지 않는다.
3. **Rust 명령 하나**: 세션 id를 받아 Rust가 가진 그 세션의 `cwd`로 로드맵 파일을 읽고, 항목 목록을 돌려준다.
   - 프론트가 임의 경로를 넘기지 않는다.
   - 경로는 정규화한 뒤, 파일이 정확히 `<cwd>/<로드맵 파일>`인지 검사한다.
   - 일반 파일만 읽는다(정션·심볼릭 링크 거부).
   - 크기 상한을 둔다(예: 256 KiB, 항목 수 상한 포함).
   - 잘못된 UTF-8이나 모르는 줄은 버리고 계속 읽는다.
   - 새 의존성 없이 최소 형식을 직접 읽는다(마크다운 파서 추가 금지. 필요하면 PLAN 승인 때 보인다).
4. **상세 패널에서 뺄 것**:
   - 세션 상세: 폴더, 상태, id, 출처, 마지막.
   - 노드 상세: 종류, 상태, 시작, 시간, 토큰.
   - "설정" 묶음: 훅 상태, 설치·제거, 안내 문구 두 줄, 대상·로그·액정 경로, 폴더 열기.
   - 이 기능들을 어디에 남길지는 질문 d를 따른다.
   - 쓰이지 않게 된 프론트 코드(`SOURCE_LABEL`, `run`, `openScreens`, `Status`의 안 쓰는 필드 등)는 지운다.
   - 세션 패널의 "로그 폴더를 읽지 못했습니다 — 설정 참고" 문구는 사라진 "설정"을 가리키지 않게 고친다.
5. **노드 클릭**: 상세 패널이 없어지므로, 노드를 누르면 `▶` 선택 표시와 자동 스크롤 기준만 바뀐다(질문 g).
6. **노드 이름 표기**: 질문 c의 규칙을 그래프 노드 이름에 적용한다. 적용할 곳을 grep으로 모두 찾는다(Graph.tsx 39행. 상세 패널의 "종류"는 4에서 사라진다).
7. **기준 시안 갱신(Designer)**: `design/reference/layout_v4.html`의 오른쪽 위 패널을 같은 문법의 로드맵 패널로 바꾼다. 예시 데이터에는 완료 항목, 미완료 항목, 묶음 제목이 들어간다. 노드 이름도 바뀐 표기로 고친다. 새로 정한 값은 승인 질문에 "새로 정한 것" 목록으로 빠짐없이 적는다(decisions.md 95행의 교훈).
8. **문서(librarian)**:
   - SPEC.md 147행 ⑤ 설명을 바꾼다.
   - 화면 절(39~62행)을 고친다. 2의 "노드 클릭 → 오른쪽 상세 패널", 4 "하네스 카드"를 질문 f에 따라 고치고, "로드맵" 항목을 추가한다.
   - SPEC.md 30~31행 "Orbit 화면의 버튼으로 … 제거 버튼도 제공"을 질문 d에 맞춘다.
   - 다른 절은 건드리지 않는다.
   - HARNESS.md는 사용자가 직접 고친다. 고칠 줄은 10절 "팀 명단 뷰"이며, 이 run에서는 목록으로만 넘긴다.
9. 로드맵 파일 내용, cwd, 에이전트 종류 문자열은 텍스트로만 렌더한다.

## 성공 기준

검증은 실제 `~/.claude`를 쓰지 않고, ②~④와 같은 환경변수 방식으로 임시 사본을 가리킨다: `ORBIT_CLAUDE_SETTINGS=<임시>\settings.json`, `ORBIT_CLAUDE_PROJECTS=<임시>\projects`. 로드맵 파일도 임시 프로젝트 폴더에 만들고, 끝나면 지운다.

1. `cargo test`(`src-tauri/`)가 0으로 끝난다. 로드맵 읽기에는 다음 테스트가 각각 하나 이상 있다: 정상 형식, 파일 없음, 크기 초과, 잘못된 UTF-8, 깨진 줄 섞임, 링크/정션 또는 범위 밖 경로 거부.
2. `npm.cmd run build`가 0으로 끝난다. `node --test harness/hooks/gate.test.mjs`도 0으로 끝난다(회귀 확인).
3. `npm.cmd run tauri dev`로 앱을 띄우고, 임시 프로젝트 폴더에 로드맵 파일(완료 2개, 미완료 3개)을 둔 세션을 고른다. 오른쪽 위 "로드맵" 패널에 다섯 항목이 파일 순서대로 보이고, 완료 표시 2개, "2 / 5", 그만큼 찬 진행 막대가 보인다.
4. 앱을 켠 채로 그 파일에서 항목 하나를 완료로 고친다. 30초 안에 패널이 "3 / 5"로 바뀐다(세션을 다시 골라도 바뀐다).
5. 세션 미선택, 로드맵 파일 없음, 300 KiB 파일, 잘못된 UTF-8 파일의 네 경우 각각에서 패널에 한 줄 안내가 보이고 앱은 계속 동작한다.

## 열린 질문

각 질문의 선택지마다 "화면·사용에서의 모습"을 한 줄로 붙였다.

**a. 로드맵을 어디서, 어떤 형식으로 읽나**
- (1) **권고**: 프로젝트 폴더 맨 위의 `ROADMAP.md`. 형식은 `- [ ] 할 일` / `- [x] 끝난 일` 줄과 묶음 제목 `## 제목`만 인식하고, 다른 줄은 무시한다.
  → 모습: 사용자가 메모장이나 에디터로 `ROADMAP.md`를 쓰면 그 체크 목록이 그대로 패널에 뜨고, GitHub에서도 체크박스로 보인다. 오르빗 저장소에서는 Lead가 관문 때문에 이 파일을 직접 못 고치므로, 사용자가 고치거나 librarian run으로 고친다.
- (2) `.orbit/roadmap.md`(같은 형식).
  → 모습: 하네스 폴더 안이라 Lead가 대화 중에 바로 체크해 줄 수 있다. 대신 하네스를 쓰지 않는 프로젝트에서는 숨은 폴더에 파일을 만들어야 한다.
- (3) SPEC.md 같은 기존 문서의 마일스톤 줄을 읽는다.
  → 모습: 새 파일은 없지만, 오르빗의 SPEC처럼 `①→②→…` 한 줄로 쓴 문서는 항목으로 나뉘지 않아 거의 빈 패널이 된다. 완료 표시도 둘 곳이 없다.
- 하위 질문: "진행 중" 표시(`- [~]` 등)가 필요한가? 권고는 필요 없음이다. 그러면 화면은 완료/미완료 두 가지로만 보인다.

**b. 진행 표시를 누가 갱신하나**
- (1) **권고**: 파일에 사용자가 직접 쓴 체크만 반영한다.
  → 모습: 사용자가 `[x]`로 바꿔야 완료로 보이고, run이 머지돼도 패널은 그대로다.
- (2) 파일 체크 + 맨 아래에 읽기 전용 한 줄로 "지금 run: `<run-id>` · `<단계>`"를 덧붙인다(`.orbit/runs/*/STATE.json`에서).
  → 모습: 로드맵 아래에 지금 도는 run 이름과 단계가 한 줄 보인다. 로드맵 항목 체크는 여전히 사용자가 한다.
- (3) run이 머지되면 해당 항목을 자동으로 완료로 본다.
  → 모습: 체크를 안 해도 완료로 바뀐다. 다만 run과 로드맵 항목을 잇는 규칙(항목에 run id 적기 등)이 새로 필요하고, 잘못 이으면 끝나지 않은 일이 완료로 보인다.

**c. 노드 이름 표기**
- (1) **권고**: 마지막 `:` 앞의 플러그인 접두사만 뗀다(`orbit:qa` → `qa`). 다른 플러그인에도 같은 규칙을 쓰고, 접두사가 없으면 그대로 둔다.
  → 모습: 노드에 `qa`, `engineer`, `general-purpose`처럼 소문자 역할 이름이 보인다. 메인 노드만 "Lead"로 대문자다.
- (2) 접두사를 떼고 첫 글자를 대문자로(`Qa`, `Engineer`).
  → 모습: "Lead"와 모양은 맞지만 `Qa`, `Plan-checker`처럼 어색한 이름이 생긴다.
- (3) 오르빗 역할만 한글 이름 표로 바꾼다(`qa` → "QA", `engineer` → "엔지니어").
  → 모습: 오르빗 역할은 한글로 보이고 다른 플러그인 에이전트는 영문 그대로라 섞인다. 역할이 늘 때마다 표를 고쳐야 한다.
- 어느 선택지든 화면 어디에도 전체 이름(`orbit:qa`)은 남지 않는다(상세 패널이 사라지므로). 같은 이름의 다른 플러그인 에이전트는 구별되지 않는다.

**d. 훅 설치·제거와 액정 "폴더 열기"**
지금 사용자의 실제 `~/.claude/settings.json`에 훅이 설치돼 있다. 훅은 Orbit이 꺼져 있어도 2초 타임아웃 뒤 조용히 끝나므로 Claude Code를 막지는 않는다.
- (1) 화면에서만 빼고, Rust 명령과 테스트는 남긴다.
  → 모습: 앱에 훅·폴더 버튼이 하나도 없다. 훅을 지우려면 사용자가 `settings.json`을 손으로 고쳐야 한다(백업 파일은 남아 있음). 액정 폴더는 탐색기에서 `%APPDATA%\dev.orbit.app\screens`를 직접 연다.
- (2) **권고**: 상단 바 오른쪽 끝에 작은 텍스트 버튼 세 개를 둔다. "훅: 설치됨/설치 안 됨" 상태 글자, `설치`/`제거` 중 지금 해당하는 하나, `액정 폴더`. 결과(백업 경로·오류)는 상단 바 같은 줄에 잠깐 보인다. 평문 토큰 안내 두 줄과 경로 세 줄은 뺀다.
  → 모습: 오른쪽 위 패널은 로드맵만 보이고, 상단 바 한 줄에 "127.0.0.1:… 듣는 중 · 훅 설치됨 [제거] [액정 폴더]"가 보인다. 클릭 한 번으로 훅을 되돌릴 수 있다.
- (3) Rust 명령까지 완전히 뺀다.
  → 모습: (1)과 화면은 같다. 나중에 다시 넣으려면 ②의 설치·제거 코드와 테스트를 되살려야 한다(되돌리기가 가장 비싸다).

**e. 어느 프로젝트의 로드맵인가**
- (1) **권고**: 세션 목록에서 고른 세션의 `cwd`를 기준으로 하고, 상위 폴더로 올라가며 찾지는 않는다. 세션을 고르지 않았으면 "세션을 고르면 그 프로젝트의 로드맵이 보입니다"를 보인다.
  → 모습: 세션을 바꾸면 로드맵도 그 프로젝트 것으로 바뀐다. 하위 폴더에서 연 세션이나 cwd가 없는 세션은 "로드맵 파일이 없습니다"로 보인다.
- (2) (1)에 더해, 세션을 고르지 않았으면 가장 최근 활동 세션의 프로젝트를 자동으로 보인다.
  → 모습: 앱을 켜자마자 로드맵이 보인다. 대신 다른 프로젝트 세션이 방금 움직였으면 그쪽 로드맵이 떠서 헷갈릴 수 있다.
- (3) 앱에서 프로젝트 폴더 하나를 직접 골라 고정한다.
  → 모습: 세션과 상관없이 늘 같은 로드맵이 보인다. 폴더 선택 대화상자, 설정 저장, dialog 권한이 새로 필요하다(범위와 capability가 커진다).

**f. SPEC·HARNESS의 원래 ⑤ "하네스 카드 + 팀 명단 뷰"**
- (1) **권고**: 나중으로 미룬다. SPEC ⑤를 "로드맵 패널 + 노드 이름"으로 바꾸고, 하네스 카드와 팀 명단 뷰는 "⑥ 뒤, 시점 미정"으로 한 줄 남긴다.
  → 모습: 이번 화면은 같다. 나중에 넣을 때 오른쪽 위 패널의 탭 등 자리를 다시 정해야 한다.
- (2) 아예 안 만든다. SPEC 화면 절 4와 HARNESS 10절 "팀 명단 뷰"를 지운다(HARNESS는 사용자가 직접).
  → 모습: 이번 화면은 같다. 문서에서 계획이 사라진다.

**g. 노드를 누르면 무엇이 되나** (상세 패널이 없어져서 생긴 질문)
- (1) **권고**: `▶` 선택 표시와 자동 스크롤 기준만 바뀐다.
  → 모습: 누르면 이름 앞에 `▶`가 붙는 것 외에는 변화가 없다. 토큰·시간은 노드 상자 안 셋째 줄에 이미 보인다.
- (2) 노드 클릭을 없앤다.
  → 모습: 노드가 버튼이 아니게 되고, 키보드로 노드를 돌아다닐 수 없다.
