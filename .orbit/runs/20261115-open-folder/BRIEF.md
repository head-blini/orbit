# BRIEF — 20261115-open-folder (폴더 열기)

## 문제

사용자가 실제로 얻으려는 것: **Claude Code를 한 번도 쓰지 않은 폴더에서도, 터미널 없이 Orbit 채팅으로 첫 대화를 시작하는 것.**

지금은 채팅의 cwd가 "왼쪽 목록에서 고른 세션의 cwd"뿐이다(`src/Chat.tsx:205` `chat_send {session, text}` → `lib.rs` `chat_send`가 store에서 cwd 조회). 목록은 세션 로그가 있는 폴더만 보여 주므로, 새 폴더는 고를 길이 없다. 결국 터미널에서 `claude`를 한 번 실행해 로그를 만들어야 Orbit으로 넘어올 수 있다(.orbit/decisions.md 17번).

진짜 풀 문제는 "버튼 추가"가 아니라 **cwd의 출처를 하나 더 만드는 것**이다. 그 출처는 신뢰 경계를 넘지 않아야 한다: 웹뷰에서 온 문자열이 그대로 cwd가 되면 안 된다.

## 누구를 위한 것

Orbit을 관제실로 쓰는 개발자 본인(Windows 우선). 새 저장소를 클론했거나 새 프로젝트 폴더를 만든 직후, 그 폴더에서 바로 Claude Code에 일을 시키고 그래프로 지켜보려는 사람.

## 범위 안 (가장 작은 버전)

1. **"폴더 열기" 버튼 1개.** 누르면 OS 기본 폴더 선택 창이 뜬다. 취소하면 아무 일도 없다(오류 표시 없음).
2. **폴더 선택은 Rust에서 한다.** 새 `#[tauri::command]`(async)가 `tauri-plugin-dialog`의 Rust API(`app.dialog().file().blocking_pick_folder()`)로 폴더를 받고, 그 경로를 Rust 상태(`Chat` 또는 `AppState`)에 보관한다. 프론트에는 화면 표시용 폴더 이름만 돌려준다. 프론트는 경로 문자열을 cwd로 보내지 않는다.
3. **Rust 쪽 검증**: 정규화(절대경로화) + 존재하는 디렉터리인지 확인 + 비 UTF-8이면 오류. `chat.rs` `spawn_with`의 기존 검증(`roadmap::local_abs`, `is_dir`, 빈 cwd 거부)을 같은 길로 재사용한다. Windows `\\?\` 접두·UNC 경로가 이 검증을 통과·거부하는지 단위 테스트로 고정한다.
4. **채팅 연결**: 폴더를 고른 뒤 첫 메시지를 보내면 그 폴더에서 새 대화가 시작된다. 고른 폴더가 있으면 세션 선택 없이도 보내기가 켜진다(`canSend` 조건 확장). 빈 화면 문구와 구분선(`새 대화 · 폴더: <이름>`)이 고른 폴더 이름을 보인다.
5. **의존성**: `tauri-plugin-dialog` 크레이트 하나(2.8.x, tauri 2.12.5와 호환), `lib.rs`에 `.plugin(tauri_plugin_dialog::init())`, `generate_handler!`에 새 커맨드. npm 패키지 `@tauri-apps/plugin-dialog`는 Rust 방식이면 넣지 않는다.
6. **capability**: `capabilities/default.json`에 `dialog:*`를 추가하지 않는 것을 목표로 한다(아래 "capability 정리"). CSP 변경 없음.
7. **ROADMAP.md**: "미뤄 둔 작업"에 `- [ ] 폴더 열기: 처음 쓰는 폴더에서 채팅 시작` 한 줄 추가, 머지 커밋에서 `[x]`.
8. **디자인**: 새 시안 없음. 기존 `btn` 클래스를 그대로 쓴다. layout_v4 확정(색 없음, 타임라인 없음, 넓은 채팅)을 바꾸지 않는다.
9. **테스트**: 경로 검증 단위 테스트(`cargo test`, 기존 `spawn_rejects_bad_cwd...`와 같은 방식). 다이얼로그 자체는 수동 QA.

### capability 정리 (요청의 "최소한의 dialog: capability"와 RESEARCH 권고의 관계)

- 요청의 의도는 "웹뷰에 열어 주는 권한을 최소로"이다. 최소는 `dialog:default`(message·save·open 모두)가 아니라 `dialog:allow-open` 하나이고, **Rust에서 선택하면 0개**가 가능하다. 0개가 더 작으므로 그쪽을 기본안으로 한다.
- 0개 방식의 추가 이점: 경로가 웹뷰를 한 번도 거치지 않아 "프론트 문자열을 cwd로 쓰지 않는다" 조건이 구조로 보장된다. 프론트 방식(`dialog:allow-open` + JS `open({directory:true})`)은 경로 문자열이 웹뷰를 거쳐 다시 Rust로 오므로 재검증이 필수이고, 웹뷰가 임의 경로를 보낼 수 있는 커맨드가 하나 생긴다.
- **확인 필요(미확인 전제, Engineer가 구현 초기에 확인)**:
  - (a) `AppHandle`에서 직접 부르는 `app.dialog()`가 capability 없이 동작하는지 — 실제 앱에서 `dialog:*` 없이 창이 뜨는지로 확인.
  - (b) `DialogExt` / `FilePath`(`into_path`/`as_path`)의 정확한 API — 컴파일로 확인.
  - (c) 로컬 rustc가 플러그인 요구 버전(1.90) 이상인지 — `rustc --version`.
  - (d) `blocking_pick_folder`를 메인 스레드에서 부르지 않을 것(교착) — async 커맨드 안에서 호출.
- (a)가 거짓이면(capability가 필요하면) `dialog:allow-open` 하나만 추가하고 그 이유를 PLAN에 적는다. `dialog:default`는 쓰지 않는다.

## 성공 기준 (QA가 그대로 검증)

자동:
1. `npm run build`가 0으로 끝난다.
2. `src-tauri/`에서 `cargo test`가 0으로 끝나고, 새 경로 검증 테스트가 포함되어 통과한다: 없는 경로 거부, 파일(디렉터리 아님) 거부, 빈 문자열 거부, 정상 디렉터리 통과.
3. `node --test harness/hooks/gate.test.mjs`가 0으로 끝난다.
4. `git diff main -- src-tauri/capabilities/` 가 비어 있다(기본안). 비어 있지 않다면 추가된 항목이 `dialog:allow-open` 하나뿐이고 PLAN에 이유가 있다.
5. `git diff main -- package.json src-tauri/Cargo.toml`에서 추가된 의존성이 `tauri-plugin-dialog` 하나뿐이다.
6. 프론트 코드에서 `chat_send` 또는 새 커맨드 호출 인자에 경로 문자열(cwd)이 없다(코드 확인: 새 커맨드는 인자 없이 또는 텍스트만 받는다).

실제 앱(`npm run tauri dev`), 모델 호출은 짧은 프롬프트 1회:
7. 화면에 "폴더 열기" 버튼이 보이고, 기존 버튼과 같은 모양(`btn`)이다. 새 색이 없다.
8. 버튼을 누르면 OS 폴더 선택 창이 뜬다. 취소하면 화면에 변화·오류가 없다.
9. 세션 로그가 한 번도 없는 새 빈 폴더(예: 스크래치 폴더에 새로 만든 디렉터리)를 고르면 채팅 빈 화면 문구가 그 폴더 이름을 보이고, 왼쪽에서 세션을 고르지 않아도 입력 줄과 보내기가 켜진다.
10. 짧은 메시지(예: "이 폴더 이름만 말해")를 보내면 구분선 `새 대화 · 폴더: <고른 폴더 이름>`이 보이고 Claude 응답이 오고 `완료`로 끝난다.
11. 대화가 시작된 뒤 왼쪽 세션 목록에 그 폴더 이름의 세션이 **정확히 1개** 나타나고, 그 세션을 누르면 에이전트 그래프에 Lead 노드가 보인다(중복 항목 없음).
12. 응답이 그 폴더에서 실행됐다(응답 내용 또는 세션 cwd가 고른 폴더와 같음).
13. 대화 실행 중에는 "폴더 열기"가 비활성이다(열린 질문 2의 권고안 채택 시).
14. 기존 흐름 회귀 없음: 목록에서 기존 세션을 고르고 보내면 예전처럼 그 세션 폴더에서 시작한다.

## 열린 질문 (권고안 포함)

1. **버튼 위치** — 상단 바 / 세션 목록 머리 / 채팅 패널 머리.
   - 권고: **채팅 패널 머리(`chat-head`), 기존 `새 대화` 버튼 옆.** 이 기능은 "채팅을 어느 폴더에서 시작할지"이므로 채팅 옆이 맞고, `chat-head`에 이미 `btn` 버튼 자리가 있어 새 배치가 필요 없다. 상단 바는 앱 상태(서버·훅·게임보이 화면) 자리이고, 세션 목록 머리는 "로그에서 읽은 것" 목록이라 의미가 섞인다.
2. **대화 중일 때 폴더 열기** — 사이드카가 살아 있으면 `chat.rs` `send`가 cwd를 무시하므로, 그대로 두면 새 폴더를 골라도 이전 폴더에서 계속된다(조용한 오동작).
   - 권고: **실행 중(`running`)에는 버튼 비활성. 대화가 열려 있고 멈춰 있을 때 폴더를 고르면 `새 대화`와 같은 동작(`chat_reset`)을 한 뒤 고른 폴더를 다음 대화의 cwd로 둔다.** 확인 창은 만들지 않는다(이미 `새 대화`가 확인 없이 지운다).
3. **고른 폴더가 목록에 나타나기 전·후, 채팅이 어느 세션에 묶이는가.**
   - 고른 뒤 첫 메시지를 보내기 전: 채팅의 cwd는 "고른 폴더"이고 왼쪽 선택과 무관하다. 고른 폴더가 있으면 그것이 왼쪽 선택보다 우선한다.
   - 왼쪽에서 다른 세션을 누르면: 권고는 **고른 폴더를 버리고 그 세션 폴더로 돌아간다**(마지막에 한 선택이 이긴다). 단 대화가 열려 있으면 지금과 같이 같은 대화가 이어진다(현행 동작 유지).
   - 대화 시작 후 새 세션이 목록에 나타나도 **자동으로 선택하지 않는다**(현행 ⑥ 동작과 같음; 자동 선택은 범위 밖). 그래프 확인은 사용자가 목록에서 누른다. 이게 불편하다면 다음 run 후보.
4. **고른 폴더가 Orbit 로드맵 검사(`roadmap::local_abs`)에서 거부되는 경로(네트워크 드라이브·UNC)** — 권고: 이번엔 거부하고 채팅에 `✕ 오류:` 한 줄로 이유를 보인다. 지원 확대는 범위 밖.
5. **버튼 문구** — 권고: `폴더 열기`. (`새 폴더에서 대화` 등 대안은 화면 폭 때문에 비권장.)
6. **capability 0개 방식이 실제로 안 되는 경우(전제 (a) 거짓)** — 권고: `dialog:allow-open`만 추가하고 계속 진행, 사용자 재확인 불필요(요청 원문이 허용한 범위). 다른 dialog 권한이 필요해지면 멈추고 묻는다.
