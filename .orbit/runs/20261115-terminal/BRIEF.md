# BRIEF — 20261115-terminal (채팅 → 앱 내장 터미널)

## 문제

사용자가 실제로 얻으려는 것: **Orbit 안에서 진짜 `claude` CLI를 직접 쓰고(새로 시작·이어 가기), 그 작업을 옆의 그래프로 지켜보는 것.**

지금 가운데 아래 칸은 Agent SDK 사이드카 위에 Orbit이 다시 만든 채팅이다. 사용자가 원한 것은 "채팅 흉내"가 아니라 터미널 그 자체였다(decisions.md 19번 갱신 줄: "나는 직접 터미널은 사용하는 걸 만들고 싶었는데"). 그래서 진짜 풀 문제는 두 가지다.

1. **같은 칸에서 claude TUI가 그대로 돌아가야 한다** — 화면이 깨지지 않고 한글 IME 조합 입력이 되어야 한다. 이게 안 되면 나머지는 의미가 없다. 그래서 첫 태스크는 이 두 가지를 확인하는 검증용 최소 터미널이고, 실패하면 사이드카를 지우기 전에 멈춘다.
2. **웹뷰가 프로세스 실행을 좌우하지 못해야 한다** — 실행 파일과 인자는 Rust가 정한다. 웹뷰는 "고른 폴더에서 시작" 또는 "이 세션 id를 이어 가기"만 요청할 수 있다. 세션 id와 cwd는 로그에서 온 신뢰할 수 없는 값이므로 검증한 뒤 인자 배열로만 넘긴다.

그래프 쪽은 새로 만들 것이 없다. 터미널의 claude가 남기는 세션 로그(③)와 훅(②)이 이미 그래프를 그린다.

## 누구를 위한 것

Orbit을 관제실로 쓰는 개발자 본인(Windows 우선, 혼자 씀). 평소 터미널에서 `claude`를 쓰고, 한글로 지시하며, 지난 세션을 이어 가고 싶은 사람.

## 범위 안 (가장 작은 버전)

확정된 결정이라 다시 묻지 않는 것: 채팅을 터미널로 교체한다, ⑥ 사이드카를 삭제한다, 새 의존성 `@xterm/xterm` + `portable-pty` 2개는 승인되었다(decisions.md 19번 갱신 줄, 116행).

**태스크 1 — 검증용 최소 터미널 (멈춤 조건)**
1. `@xterm/xterm`(6.x) + `@xterm/addon-fit` + Rust `portable-pty`(0.9, ConPTY). PTY 출력은 Tauri Channel로 보내고, 입력·리사이즈는 일반 커맨드 2개로 받는다. 이 단계에서는 사이드카 코드를 건드리지 않는다.
   - `@xterm/addon-fit`은 승인된 2개와 별개인 세 번째 npm 패키지다. 쓰지 않고 직접 계산할 수도 있다. 쟁점 6 참고.
2. 실제 앱(`npm run tauri dev`)에서 고른 폴더로 `claude`를 띄우고 확인한다: TUI 그리기, 한글 조합·확정·Backspace, 조합을 끝내는 키(스페이스·마침표)에서 글자가 두 번 들어가는지, 창 크기 바꾸기, 앱 종료 시 claude 프로세스가 정리되는지.
   - 모델 호출 없이 확인한다. 입력 줄에 타이핑만 하고 Enter는 누르지 않는다.
3. 운영 빌드에서 CSP를 확인한다. 쟁점 3의 결정에 따른다.
4. **멈춤 조건**: TUI가 쓸 수 없을 정도로 깨지거나 한글 조합이 안 되면, Lead는 사이드카 삭제 태스크로 가지 말고 결과(스크린샷·증상)를 붙여 사용자에게 묻는다. 통과하면 다음 태스크로 간다.

**태스크 2 이후 — 터미널 완성**

5. **시작 방법 두 가지.** 실행 파일은 PATH의 `claude`, 인자는 Rust 상수에 검증된 UUID만 붙인다.
   - (a) `폴더 열기`: 지난 run에서 만든 Rust 쪽 선택·검증(`blocking_pick_folder` → `strip_verbatim_disk` → `check_cwd` → `picked`)을 그대로 쓴다. 그 폴더에서 `claude`를 실행한다.
   - (b) 왼쪽에서 고른 세션 `이어 가기`: 웹뷰는 세션 id만 보낸다. Rust는 8-4-4-4-12 hex 형식인지, store에 있는 id인지 확인한다. 그다음 store의 cwd를 `check_cwd`로 검사하고, 그 cwd에서 `["--resume", id]`로 실행한다.
   - 웹뷰가 실행 파일·인자·경로 문자열을 보내는 커맨드는 없다.
   - `term_write`는 사용자가 친 바이트를 PTY에 쓰기만 한다. 실행 대상을 바꾸지 못한다.
6. **cwd 검사**: portable-pty는 cwd가 없으면 조용히 홈 폴더로 바꾼다. 그래서 실행 전에 Rust에서 반드시 `check_cwd`로 막는다.
7. **실행 파일을 못 찾을 때**: `claude`가 없으면 터미널에 한국어 오류 한 줄을 보이고, 앱은 죽지 않는다.
8. **프로세스 정리**: claude가 끝나면 터미널에 "종료됨" 한 줄이 보이고 다시 시작할 수 있다. 앱을 닫거나 새로 시작할 때 이전 claude와 그 하위 프로세스가 남지 않는다. portable-pty `kill`이 프로세스 트리를 끝내지 못하면 기존 `stop()`처럼 `taskkill /T /F`를 쓴다(RESEARCH 미확인 항목, 구현에서 실측).
9. **출력 핫패스**:
   - UTF-8 문자 경계를 지켜서 청크를 모은다.
   - 청크는 순서대로 한 번만 `write`한다.
   - 버퍼에는 상한을 둔다.
10. **사이드카 삭제** (RESEARCH 6절 목록 기준). 남은 호출부가 없는지 plan-checker가 확인한다.
    - 삭제할 파일: `sidecar/` 전체, `src-tauri/src/chat.rs`, `src/Chat.tsx`, `src/Chat.css`.
    - `lib.rs`: `mod chat`, `AppState.chat`, `chat_*` 커맨드 6개와 그 등록, 종료 훅(터미널 정리로 바꾼다).
    - `package.json`과 `package-lock.json`: `@anthropic-ai/claude-agent-sdk`와 optional 플랫폼 패키지.
    - `chat.rs`를 지우기 전에 `check_cwd`, `strip_verbatim_disk`, `picked`를 테스트와 함께 다른 모듈로 옮긴다.
11. **원래 요청에 있었지만 실제로는 없는 것**: RESEARCH가 확인한 결과는 아래와 같다. 삭제 범위가 요청문보다 작다. plan-checker가 다시 확인한다.
    - **사이드카 준비 스크립트**: 없다. `tauri.conf.json`의 `beforeDevCommand`·`beforeBuildCommand`는 `npm run dev`·`npm run build`뿐이고, `package.json` scripts에도 사이드카 단계가 없다.
    - **사이드카 capability**: 없다. `capabilities/default.json`은 `core:default`, `opener:default`뿐이다.
    - 새 터미널 커맨드도 capability를 추가하지 않는 것이 목표다.
12. **디자인**:
    - layout_v4의 칸 위치·크기·패널 이중 테두리는 그대로 둔다. 안쪽만 터미널로 바꾼다.
    - 터미널 글자는 고정폭 일반 글꼴이다.
    - 터미널 테마(바탕·글자·커서·선택, ANSI 색 매핑)는 `design/tokens.json`의 4명암만 쓴다. 새 색은 없다. `tokens.json`의 `"chat"` 키는 터미널용으로 바꾼다.
    - 칸 머리의 버튼은 기존 `btn` 클래스를 쓴다.
    - Designer는 `design/reference/layout_v4.html`의 채팅 칸을 터미널 모습으로 고친다. 기준 시안이 실제 화면과 어긋나지 않게 하기 위해서다.
13. **문서**:
    - `ROADMAP.md`: 22행 `폴더 열기` 줄을 `[x]`로 바꾼다. 1단계 ⑥ 줄은 그대로 두고 그 아래에 `- [ ] 앱 내장 터미널 (채팅·사이드카 대체, 이어 가기)`를 추가한다. 추가한 줄은 머지 커밋에서 `[x]`로 바꾼다.
    - `SPEC.md`: ⑥ 사이드카 서술(53~78, 153행)을 터미널 서술로 최소한만 고친다.
    - `CHANGELOG.md`: 항목을 하나 추가한다.
    - `docs/solutions/chat-sidecar.md`: 지우지 않는다. 맨 위에 "사이드카는 run 20261115-terminal에서 삭제됨" 한 줄만 단다.
14. **테스트**: `cargo test`에 아래를 추가한다.
    - UUID 검증 테스트: 정상, 대소문자, 길이·문자 오류, 앞뒤 공백, `--` 같은 옵션 모양, 경로 모양.
    - store에 없는 id는 거부한다.
    - 옮긴 `check_cwd`·`strip_verbatim_disk` 테스트가 계속 통과한다.
    - 인자 배열 구성 테스트: 실행 파일과 인자가 상수 + id로만 이루어지는지 확인한다.
15. **진행 규칙**: 푸시하지 않는다. 머지 전에 Lead가 사용자에게 한 번 묻는다.

## 범위 밖

- npm 전역 설치(`claude.cmd`)만 있는 PC 지원. `cmd.exe /c` 경유는 인자 인용 위험이 있다. 이번에는 "claude를 찾을 수 없음" 오류 한 줄로 끝낸다. 이 PC에는 네이티브 `~\.local\bin\claude.exe`가 있다. 쟁점 4 참고.
- 탭·여러 터미널 동시 실행, 터미널 분할.
- 스크롤백 검색, 링크 클릭(web-links addon), WebGL 렌더러, 글꼴 크기 설정.
- 모델 고르기, git worktree, 출발 브랜치 선택. 이것은 19번 (1) "새 대화 입구" run에서 다룬다.
- `--fork-session`, 이름·경로로 이어 가기(UUID만 받는다).
- 터미널 출력을 파싱해 그래프를 그리는 일. 그래프는 기존 로그 감시와 훅만 쓴다.
- macOS·Linux 실측. 코드는 크로스플랫폼으로 쓰지만 확인은 Windows에서만 한다.
- decisions.md 18번의 사이드카 보안 후속 R1·R2·R4·R5·R6과 REVIEW 참고 항목. 사이드카를 지우면 대상이 사라진다. Lead가 decisions.md에 "사이드카 삭제로 해소"라고 기록한다.
- R3 훅 포트 불일치. 이미 처리했거나 별도 항목이다.
- `CLAUDE_CODE_NO_FLICKER` 같은 claude 환경변수 조정. 태스크 1에서 깜빡임이 쓸 수 없는 수준이면 그때 사용자에게 묻는다.
- 터미널 출력이나 세션 로그를 Orbit DB에 저장하는 일.

## 성공 기준 (QA가 그대로 검증)

### QA 실제 모델 호출 상한

- 지난 run 기준으로 1회에 약 $0.11이다.
- 필요한 호출:
  - (가) 새 폴더에서 claude를 실행하고 한글 메시지를 1회 보낸다. 이 세션이 목록에 나타나고 그래프에 반영되는지도 같은 세션으로 확인한다.
  - (나) 그 세션을 `--resume`으로 이어 가며 1회 보낸다.
  - 최소 2회다.
- **상한은 3회(재시도 1회 포함), 추정 $0.35**다.
- 태스크 1의 검증과 Engineer·Debugger의 확인은 모델 호출 0회가 원칙이다. 입력 줄에 타이핑만 하고 Enter를 누르지 않는다. 불가피하면 run 전체 합계 4회, $0.45를 넘지 않는다.
- 상한에 닿으면 더 부르지 않고 미검증 항목으로 남긴 뒤 Lead에게 보고한다. 지난 run은 상한을 1회 넘겼다.
- QA는 VERIFY에 호출 횟수와 추정 금액을 적고, 금액의 근거(세션 로그 usage 또는 claude `/cost` 출력)를 붙인다.

### 실제 앱 (`npm run tauri dev`, 필요 시 운영 빌드)

10. 화면 배치가 layout_v4와 같다.
    - 아래(왼쪽+가운데) 넓은 칸이 터미널이다.
    - 칸의 위치·크기·이중 테두리가 그대로다.
    - 터미널 글자가 고정폭이다.
    - 화면에 4명암 외의 색이 없다. 스크린샷을 첨부한다.
11. `폴더 열기`를 누르면 OS 폴더 선택 창이 뜬다. 취소하면 아무 변화가 없다.
12. 세션 로그가 없는 새 빈 폴더를 고르면 터미널에 claude TUI가 나타난다. 입력 상자와 테두리가 깨지지 않는다(스크린샷).
13. 터미널 안에서 claude에게 현재 폴더를 묻지 않아도, TUI 머리 또는 `/status`에 표시되는 cwd가 고른 폴더다. `/status`는 모델 호출이 아니다.
14. 한글 입력을 확인한다.
    - 방법은 쟁점 1의 결정에 따른다.
    - "안녕하세요 반갑습니다."를 입력하면 입력 줄에 정확히 그 문자열이 보인다. 자모가 분해되거나 마지막 글자가 중복되지 않는다.
    - Backspace로 한 글자씩 지워진다.
15. 메시지를 1회 보내면 응답이 오고 claude 입력 줄로 돌아온다. 호출 (가)에 해당한다.
16. 그 뒤 왼쪽 세션 목록에 그 폴더 이름의 세션이 정확히 1개 나타나고, 누르면 그래프에 Lead 노드가 보인다.
17. 그 세션을 고르고 `이어 가기`를 누르면 그 세션의 cwd에서 claude가 다시 열린다. 지난 대화가 보이고, 보낸 메시지에 이어서 답한다. 호출 (나)에 해당한다. 세션 목록에 새 항목이 생기지 않는다(같은 id에 이어짐).
18. 창 크기를 바꾸면 터미널이 칸에 맞게 다시 그려진다. 가로가 잘리거나 겹치는 줄이 남지 않는다. 잔상이 있으면 Ctrl+L 뒤에 정상으로 돌아오는지 기록한다.
19. claude에서 `/exit` 하면 터미널에 종료 표시가 보이고, 다시 시작할 수 있다.
20. claude 실행 중에 앱을 닫으면 `tasklist`에 claude.exe(이 앱이 띄운 것)가 남지 않는다. 실행 전·중·후의 `tasklist /FI "IMAGENAME eq claude.exe"` 출력을 첨부한다.
21. PATH에서 claude를 못 찾는 상황(예: PATH를 비운 채 앱 실행)에서 시작하면 터미널에 한국어 오류 한 줄이 보이고, 앱은 계속 동작한다. 재현이 어렵다면 단위 테스트로 대신하고, 그 사실을 VERIFY에 적는다.
22. 쟁점 3의 결정대로 운영 빌드에서 터미널이 그려지고, 웹뷰 콘솔에 CSP 위반이 없다.

## 사용자에게 물을 쟁점 (선택지와 권고안)

1. **한글 IME 실측은 누가 하나.**
   - 에이전트는 Windows 실제 IME를 누를 수 없다. CDP `Input.imeSetComposition`은 조합 이벤트를 흉내 낼 뿐이다.
   - 선택지:
     - (가) 태스크 1이 끝나면 사용자가 앱을 열어 1분간 직접 한글을 쳐 본다.
     - (나) CDP 흉내만으로 판정한다.
   - **권고: (가)와 (나)를 함께 한다.**
     - 태스크 1의 멈춤 지점에서 Lead가 사용자에게 직접 입력을 부탁한다. 성공 기준 14번의 본 판정은 사용자 확인이다.
     - QA는 CDP 흉내로 회귀만 본다.
     - (나)만 하면 실제 IME 문제가 가려질 수 있다.
2. **세션을 고르면 무엇이 시작되나.**
   - 요청에는 "고른 세션의 cwd에서 실행"과 "`--resume` 이어 가기"가 함께 있다.
   - 선택지:
     - (가) 버튼 두 개: `폴더 열기`(새로), `이어 가기`(고른 세션).
     - (나) (가)에 `새로 시작`(고른 세션의 폴더에서 resume 없이)을 더한 세 개.
     - (다) 세션을 누르기만 해도 자동으로 이어 가기.
   - **권고: (나).**
     - 세 번째 버튼은 같은 커맨드에서 인자만 빠지는 것이라 비용이 작다. 기존 채팅의 "고른 세션 폴더에서 새 대화"를 잃지 않는다.
     - (다)는 목록을 둘러보기만 해도 프로세스가 뜨고 토큰이 들 수 있어 비권장이다.
3. **운영 빌드 CSP.**
   - 운영 CSP는 `style-src 'self'`이다. xterm의 인라인 스타일이 막힐 수 있다(미확인). dev에서는 드러나지 않는다.
   - 선택지:
     - (가) 태스크 1에서 운영 빌드로 실측하고, 깨지면 `style-src`에만 `'unsafe-inline'`을 추가한다. `script-src`는 그대로 둔다.
     - (나) 깨지면 멈추고 다시 묻는다.
     - (다) 이번 run은 dev만 검증하고, 운영 빌드는 범위 밖으로 둔다.
   - **권고: (가).** 스타일 인라인 허용은 스크립트 실행을 열지 않는다. 로그·페이로드 문자열은 HTML로 넣지 않으므로 추가 위험이 작다. Security가 SECURITY.md에 근거를 적는다.
4. **`claude.cmd`(npm 설치)만 있는 환경.**
   - 선택지:
     - (가) 범위 밖으로 두고 오류 한 줄만 보인다.
     - (나) `cmd.exe /c` 경유로 지원한다.
   - **권고: (가).** 혼자 쓰는 앱이고 이 PC는 네이티브 설치다. npm 설치는 deprecated다. `cmd.exe` 경유는 인자 인용 위험을 새로 만든다.
5. **실행 중에 다른 시작 버튼을 누르면.**
   - 선택지:
     - (가) 실행 중에는 시작 버튼을 비활성으로 하고 `종료` 버튼 하나를 둔다.
     - (나) 확인 없이 이전 claude를 죽이고 새로 시작한다.
   - **권고: (가).** 실행 중인 claude를 실수로 죽이면 진행 중인 작업이 끊긴다. 지난 run의 "실행 중 폴더 열기 비활성"과도 같은 규칙이다.
6. **`@xterm/addon-fit`**:
   - 승인된 두 의존성(`@xterm/xterm`, `portable-pty`) 밖의 npm 패키지다. 의존성 없음, 공식 xterm 조직 패키지다.
   - 선택지:
     - (가) 추가한다.
     - (나) 칸 크기에서 cols·rows를 직접 계산한다.
   - **권고: (가).** 글자 셀 크기 측정을 직접 하면 xterm 내부 API에 기대게 되고, 리사이즈 회귀 위험이 더 크다. 사용자가 "2개만"을 고수하면 (나)로 간다.
