# BRIEF: 마일스톤 ② 훅 수신 서버 + 훅 설치 도우미

RUN: 20261114-hook-server / TRACK: full
근거: SPEC.md 17~37행(데이터 수집 1·2), 73~77행(1단계 완료 기준), 145~150행(마일스톤 ②), RESEARCH.md, CLAUDE.md 코드 규칙·보안 체크리스트, 사용자가 덧붙인 조건 (a)~(d).

## 문제

사용자가 실제로 얻으려는 결과(한 문장):
**터미널에서 돌고 있는 Claude Code 세션이 지금 무엇을 하는지가, 버튼 한 번으로 훅을 넣은 뒤부터 Orbit 화면에 실시간으로 도착하고, Orbit을 꺼 두어도 Claude Code는 전과 똑같이 돈다.**

"정말 풀어야 할 문제"는 서버를 만드는 것이 아니라 **실시간 이벤트가 들어오는 신뢰할 수 있는 통로 하나**를 여는 것이다. 이후 마일스톤(③ 로그 병합, ④ 그래프·타임라인)은 모두 이 통로 위에 올라간다. 그래서 이번에 중요한 것은 세 가지다.
1. 통로가 안전하다: 로컬의 다른 프로세스나 브라우저가 가짜 이벤트를 넣지 못한다.
2. 통로를 여는 일이 사용자의 설정을 망가뜨리지 않는다: 백업 후 병합, 제거하면 원래대로 돌아간다.
3. 통로가 끊겨도 Claude Code가 느려지거나 막히지 않는다.

## 누구를 위한 것

- 1차: Orbit을 쓰는 개발자 본인(도그푸딩 중인 사용자). 터미널에서 Claude Code를 띄워 일하면서 옆에 Orbit을 켜 둔다.
- 2차: 다음 마일스톤의 팀(③·④). 이번 run의 이벤트 형태(프론트로 emit되는 이름과 payload)가 그들의 입력이다.

## 범위 안 (가장 작은 버전)

1. **훅 수신 서버 (Rust, Tauri 백엔드 안)**
   - 앱 시작 시 `127.0.0.1`에만 바인딩. 포트는 열린 결정 6.
   - `POST /events` 하나. 토큰 헤더 검증(상수 시간 비교), `Origin` 헤더가 있거나 `Host`가 `127.0.0.1:<port>`/`localhost:<port>`가 아니면 거부, 본문 크기 상한, 그 외 경로·메서드 거부.
   - 응답은 항상 **빈 본문**의 2xx(성공) 또는 4xx(거부). JSON 본문을 돌려주지 않는다(RESEARCH 질문 2: 2xx JSON은 훅 출력으로 해석되어 Claude 동작에 영향).
   - 통과한 페이로드는 해석하지 않은 JSON 그대로(모르는 필드에 죽지 않음) 프론트로 emit.
   - 토큰은 앱 최초 실행 시 랜덤 생성, 재시작해도 유지(settings.json에 박힌 값과 맞아야 하므로). 저장 위치는 열린 결정 7.
2. **훅 설치 도우미 (Rust 명령 + 버튼)**
   - 설치: 대상 settings 파일을 백업한 뒤, 기존 내용을 보존한 채 Orbit 훅 항목만 병합. 쓰기는 임시 파일 → rename.
   - 제거: Orbit이 넣은 항목만 식별해 지운다(다른 훅·다른 키는 그대로). 백업 후 원자적 쓰기.
   - 여러 번 설치해도 항목이 중복되지 않는다. 대상 파일이 없으면 만들고, JSON이 깨져 있으면 손대지 않고 오류를 보여준다.
   - 훅 형태·이벤트 목록·타임아웃·설치 위치는 열린 결정 1~5.
3. **최소 화면 (조건 a)**: 기존 빈 화면 안에 다음만.
   - 서버 상태 한 줄(듣는 주소·포트, 또는 시작 실패 사유). 토큰은 보이지 않거나 마스킹.
   - 설치 대상 경로 표시 + "설치" / "제거" 버튼 + 현재 설치 여부 + 마지막 결과(성공, 백업 파일 경로, 또는 오류).
   - 도착한 이벤트 목록: 최근 N개(메모리에만), 각 줄에 시각 · `hook_event_name` · `session_id` 앞부분 · `tool_name`(있으면). 페이로드 문자열은 텍스트로만 렌더(HTML 삽입 금지).
   - 디자인은 하지 않는다(④).
4. **검증 경로 (조건 c)**: 설치·제거 로직은 임시 폴더의 사본 settings 파일로 자동 테스트한다. QA가 앱 화면에서 끝까지 확인할 때도 대상 파일을 임시 사본으로 가리킬 방법이 필요하다(방법은 Architect가 정한다. 예: 개발용 환경변수로 대상 경로 덮어쓰기). 실제 `~/.claude/settings.json` 적용은 사용자가 화면에서 직접 누른다.

## 범위 밖

- 세션 로그(JSONL) 감시와 훅·로그 병합·중복 제거 → 마일스톤 ③
- 그래프·타임라인·세션 목록·RPG 디자인 → 마일스톤 ④
- SQLite 저장, 마이그레이션, 보관 기간 → 이벤트는 메모리에만, 재시작하면 사라진다
- 하네스 카드, 프롬프트 입력창, Agent SDK 사이드카 → ⑤·⑥
- command 유형 훅(셸 스크립트 POST) — 열린 결정 1에서 http를 택하면 만들지 않는다
- 프로젝트 폴더 선택 UI — 열린 결정 2에서 전역만 택하면 만들지 않는다
- 토큰 재발급(회전) 버튼, 포트 변경 UI, 이벤트 필터·검색
- 이 저장소의 `.claude/settings.json`과 사용자의 실제 `~/.claude/settings.json`을 에이전트가 고치는 것(조건 c)
- `allowedHttpHookUrls`·`httpHookAllowedEnvVars`·`disableAllHooks` 같은 사용자 정책 우회. 감지해서 알려주는 것도 이번에는 하지 않는다(열린 결정 8)

## 성공 기준 (관찰 가능한 것 — QA가 그대로 검증)

자동 테스트
1. `src-tauri/`에서 `cargo test`가 0으로 끝난다. 테스트에 최소한 다음이 있다.
   - 서버: 올바른 토큰 + 올바른 Host → 2xx 빈 본문, 이벤트 1건 전달 / 토큰 없음·틀림 → 401, 전달 0건 / `Origin` 헤더 있음 → 403 / 상한 초과 본문 → 413 / `GET /events`·다른 경로 → 거부 / 깨진 JSON·모르는 필드 → 서버가 죽지 않는다.
   - 서버가 `127.0.0.1`에 바인딩된다(`0.0.0.0` 아님).
   - 설치 도우미(임시 폴더 사본): 다른 훅과 다른 키가 있는 파일에 설치 → 원래 키·훅 보존, Orbit 항목 추가, 백업 파일이 원본과 바이트 단위로 같다 / 두 번 설치 → 항목 중복 없음 / 제거 → Orbit 항목만 사라지고 나머지는 원본과 같은 JSON / 파일 없음 → 생성 / 깨진 JSON → 오류, 파일 그대로.
2. 저장소 루트에서 `npm run build`가 0으로 끝난다.
3. `node --test harness/hooks/gate.test.mjs`가 0으로 끝난다(회귀 없음).

앱 실행 (QA, 임시 사본 설정으로)
4. `npm run tauri dev`로 앱을 띄우면 화면에 서버 상태(`127.0.0.1:<port>`에서 듣는 중)가 보이고, 토큰 원문은 화면 어디에도 보이지 않는다.
5. 대상이 임시 사본 파일인 상태에서 "설치"를 누르면 화면에 성공과 백업 파일 경로가 보이고, 사본 파일에 Orbit 훅 항목이 들어가 있으며 기존 내용은 그대로다. "제거"를 누르면 Orbit 항목만 빠진다.
6. 그 사본 설정을 쓰는 Claude Code 세션을 띄워(예: `claude --settings <사본 경로>` — 이 옵션의 동작은 QA가 확인, 안 되면 사본을 임시 프로젝트의 `.claude/settings.local.json`으로 둔다) 프롬프트 하나를 보내고 도구를 한 번 쓰게 하면, Orbit 화면의 이벤트 목록에 SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · Stop이 같은 `session_id`로 순서대로 나타난다.
7. 토큰 없이 또는 틀린 토큰으로 `curl`로 `POST /events`를 보내면 거부되고 화면에 아무것도 추가되지 않는다. `Origin` 헤더를 붙인 요청도 거부된다.
8. 이벤트 페이로드에 `<b>x</b>` 같은 문자열이 들어 있어도 화면에는 글자 그대로 보인다.

Orbit이 꺼져 있을 때 (조건, SPEC 76행)
9. Orbit 앱을 끈 상태에서, 훅이 설치된 같은 사본 설정으로 Claude Code에 프롬프트를 보내면 오류 없이 평소처럼 완료되고, 훅 때문에 눈에 띄는 지연이 없다(Orbit 켜짐/꺼짐 각각 `claude -p` 한 번의 소요 시간을 비교해 기록).

사용자 확인 (에이전트가 하지 않음)
10. 사용자가 화면에서 실제 `~/.claude/settings.json`(또는 결정 2에서 정한 위치)에 설치를 누르고, 터미널의 새 Claude Code 세션 이벤트가 Orbit 화면에 도착하는 것을 본다. 백업 파일이 생기고 기존 설정이 남아 있다.

## 열린 결정 (사용자가 정한다)

1. **훅 유형: `http` vs `command`**
   - 선택지: (A) `type:"http"`로 `http://127.0.0.1:<port>/events`에 직접 POST. (B) SPEC 예시대로 `command` 훅이 stdin을 curl/PowerShell/node로 POST.
   - 권고: **A**.
   - 이유: 공식 지원되고, Windows에서 Git Bash/PowerShell 중 무엇이 잡히느냐에 따른 인용·실행 파일 문제가 사라진다. 연결 실패·비-2xx는 비차단 오류라 "Orbit이 꺼져도 막지 않는다"를 그대로 만족한다. command 방식은 종료 코드 2나 stdout 출력이 Claude를 막을 위험이 있다.
   - 확인할 것: http 유형이 도입된 Claude Code 버전은 RESEARCH에서 확인하지 못했다. 사용자의 `claude --version`이 이를 지원하는지 QA 6번에서 실측된다. `onFailure`는 넣지 않는다(v2.1.295+ 전용이고 기본이 계속 진행).

2. **설치 위치 (토큰이 settings 파일에 평문으로 들어가는 문제와 묶임)**
   - 사정: 이미 실행 중인 Claude Code에 Orbit이 환경변수를 넣어 줄 수 없으므로, 헤더의 토큰은 settings 파일에 문자 그대로 들어간다. 그 파일이 git에 커밋되면 토큰이 새어 나간다.
   - 선택지: (A) 전역 `~/.claude/settings.json`만. (B) 전역 + 프로젝트 `.claude/settings.local.json`(보통 git에서 무시됨). (C) SPEC 문구대로 전역 + 프로젝트 `.claude/settings.json`. (D) 토큰을 환경변수(`allowedEnvVars`)로 두고 사용자가 OS 사용자 환경변수를 직접 등록한 뒤 터미널을 다시 열게 함.
   - 권고: **A**.
   - 이유: 모든 세션을 한 번에 관찰하는 것이 목표라 전역 하나면 충분하고, 커밋될 위험이 없으며, 프로젝트 선택 UI와 중복 설치 문제(결정 5)가 함께 사라진다. C는 커밋으로 토큰이 유출될 수 있어 권하지 않는다. D는 안전하지만 사용자 수작업과 재시작이 필요해 "버튼 한 번"이 깨진다.
   - 함께 정할 것: 화면에 "토큰이 settings 파일에 평문으로 저장됩니다"를 알리는 한 줄을 넣는 것(권고: 넣는다). 토큰의 위협 모델은 "로컬의 다른 프로세스"이고, 그 프로세스가 사용자 홈의 파일을 읽을 수 있다면 토큰도 읽을 수 있다는 한계를 사용자가 받아들일지.

3. **수신 이벤트 목록**
   - 선택지: (A) SPEC의 7개(SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, SubagentStop, Stop, Notification). (B) A + SubagentStart, PostToolUseFailure, PermissionRequest, SessionEnd, StopFailure (12개). (C) 33개 전부.
   - 권고: **B**.
   - 이유: 다음 마일스톤 화면이 쓰는 정보가 B에 다 있다 — 서브에이전트 노드의 시작(SubagentStart), 실패한 도구 빨간색(PostToolUseFailure), "대기(권한 요청)" 배지(PermissionRequest), 세션 완료·에러(SessionEnd, StopFailure). 설치 항목 수만 늘 뿐 코드 차이는 없다. C는 FileChanged·ConfigChange 등 화면에서 안 쓰는 이벤트가 매번 호출되어 비용만 든다. 나중에 늘리려면 재설치가 필요하다는 점은 감수한다.
   - 확인할 것: PermissionRequest 훅에 빈 2xx를 돌려주면 권한 판단에 영향이 없다는 것(RESEARCH가 이 이벤트의 필드·동작은 미확인). QA가 실측하고, 영향이 있으면 이 이벤트는 뺀다.

4. **타임아웃 값**
   - 사정: 명시하지 않으면 기본 600초(UserPromptSubmit은 30초). Orbit이 켜져 있지만 멈춘 경우 Claude Code가 그만큼 기다린다. 꺼져 있으면 연결 거부라 즉시 실패한다.
   - 선택지: (A) 1초. (B) 2초. (C) 5초.
   - 권고: **B(2초)**, 모든 항목에 명시.
   - 이유: 로컬 루프백 POST는 밀리초 단위라 2초면 넉넉하고, 서버가 멈춰도 한 이벤트당 최대 2초로 묶인다. 서버는 받는 즉시 응답하고 처리는 나중에 하도록 만들어 이 시간에 닿지 않게 한다. 단위는 정수 초(소수 허용 여부 미확인이라 1 미만은 쓰지 않는다).

5. **전역·프로젝트 중복 설치**
   - 사정: 훅은 수준 간 합쳐지므로 두 곳에 설치하면 같은 이벤트가 두 번 올 수 있다(완전히 같은 핸들러는 1회로 합쳐진다고 문서에 있음).
   - 선택지: (A) 결정 2에서 전역만 택해 문제 자체를 없앤다. (B) 두 곳 다 허용하고, 서버가 같은 내용 이벤트를 무시. (C) 두 곳 다 허용하고, 설치 시 다른 곳에 이미 있으면 경고만.
   - 권고: **A** (결정 2가 A면 자동). 결정 2에서 B/C를 고르면 이번에는 C(경고만), 실제 중복 제거는 ③의 병합 작업에 맡긴다.

6. **포트**
   - 사정: settings 파일의 url에 포트가 박히므로 앱을 재시작해도 같은 포트여야 한다.
   - 선택지: (A) 코드에 고정한 포트 하나. 이미 쓰이고 있으면 화면에 오류를 보여주고 서버를 띄우지 않는다. (B) 최초 실행 때 빈 포트를 골라 저장하고 이후 재사용. 막혀 있으면 오류 표시(재설치 필요).
   - 권고: **B**.
   - 이유: 고정 포트는 다른 프로그램과 겹칠 수 있고 그때 사용자가 할 수 있는 일이 없다. B는 토큰과 같은 곳에 함께 저장하면 되어 추가 비용이 작다. 다만 B도 저장된 포트가 나중에 막히면 재설치해야 하는 한계가 있다.

7. **토큰·포트 저장 위치**
   - 사정: SPEC 112행은 "토큰은 OS 키체인"이라 하지만, 결정 2대로라면 같은 토큰이 이미 settings 파일에 평문으로 있다.
   - 선택지: (A) Tauri `app_data_dir` 아래 파일 하나(사용자 프로필 권한). (B) OS 키체인(새 의존성 필요).
   - 권고: **A**.
   - 이유: 같은 값이 홈 폴더의 settings.json에 평문으로 있으므로 키체인은 보안을 더하지 못하고 의존성만 늘린다. 키체인은 API 키를 다루는 ⑥에서 도입한다. SPEC과 다른 선택이므로 사용자가 확정해야 한다.

8. **사용자 정책 때문에 훅이 조용히 안 도는 경우**
   - 사정: `allowedHttpHookUrls`나 `disableAllHooks`가 어느 설정에든 있으면 Orbit 훅이 실행되지 않는다.
   - 선택지: (A) 이번에는 다루지 않고, "이벤트가 안 오면 확인할 것"을 화면 문구 한 줄로만. (B) 설치 시 설정 파일들을 읽어 감지·경고.
   - 권고: **A**. 감지는 여러 설정 출처(관리형 정책 포함)를 읽어야 해 범위가 커진다.

9. **새 Rust 의존성 허용 범위**
   - 사정: CLAUDE.md는 요청받지 않은 의존성을 금한다. 후보는 HTTP 파서(tiny_http), 난수(getrandom), JSON 병합(serde_json — 이미 있을 수 있음).
   - 선택지: (A) 표준 라이브러리 + 이미 있는 크레이트만(HTTP 파싱을 직접 구현). (B) 작은 크레이트 1~2개(tiny_http, getrandom) 허용, 상수 시간 비교는 직접 구현.
   - 권고: **B**. HTTP 파싱·본문 제한을 직접 짜면 보안 검토 대상 코드가 늘어난다. 정확한 목록은 Architect가 PLAN에 적고 사용자가 승인한다.
