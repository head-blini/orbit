## 문제

지금 Orbit은 보기만 할 수 있다. 일을 시키려면 터미널로 돌아가 `claude`를 띄워야 하고, 권한 요청도 터미널에서 답해야 한다. 그래서 "터미널 대신 Orbit 화면만 본다"는 1단계 목표의 절반이 비어 있다. 사용자에게 필요한 것은 모델 선택, 트랙 선택 같은 조작 다양성이 아니다. **지시하고, 답을 보고, 위험한 행동을 허락하거나 막고, 멈추는 고리가 Orbit 안에서 끊김 없이 닫히는 것**이다.

한 문장으로:

> 세션 목록에서 프로젝트를 고르고 채팅에 지시를 쓰면, 그 폴더에서 터미널과 같은 설정으로 Claude Code가 돈다. 답은 채팅에 흘러나오고, 권한 요청과 질문은 채팅 안 카드로 답하며, 중단 버튼으로 멈출 수 있다. 그 세션은 그래프와 세션 목록에 한 번만 뜬다.

## 누구를 위한 것

- Orbit 사용자 한 명이다(개인용, 배포하지 않음. decisions.md 82행). 이미 이 PC에서 Claude Code에 로그인해 쓰고 있는 개발자이고, 첫 사용처는 오르빗 저장소 자신이다.
- 이 사람은 "터미널에서 하던 일을 그대로" 하길 원한다. 같은 로그인, 같은 CLAUDE.md·`.claude/` 설정, 같은 권한 규칙을 쓰고, 다른 점은 화면뿐이다.

## 범위 안

가장 작은 버전은 **입력 → 스트리밍 응답 → 권한 승인(질문 포함) → 중단** 고리 하나를 끝까지 잇는 것이다. 괄호 안 기본값은 "사용자에게 물을 것"의 권고안이고, 사용자가 다르게 고르면 그에 따라 바뀐다.

1. **사이드카 (Node, Agent SDK)**: Rust가 띄우고 stdin/stdout JSON 줄로만 주고받는다. 사이드카는 네트워크 포트를 열지 않는다.
   - `query()`는 다음 옵션으로 연다.
     - `prompt`: 항상 AsyncIterable(스트리밍 입력). interrupt를 쓰려면 필요하다.
     - `includePartialMessages: true`
     - `permissionMode: "default"`(명시)
     - `settingSources` 생략(터미널과 같음)
     - `systemPrompt: {type:"preset", preset:"claude_code"}`
     - `cwd`: 고른 폴더
     - `canUseTool`: Rust ↔ UI 왕복
   - `env`는 `{...process.env}`를 그대로 넘긴다. Orbit은 인증 값을 더하지도 읽지도 않는다(쟁점 2).
   - 실행 방식(쟁점 3: 사용자 PC의 `node`, Rust `std::process`로 spawn, 새 Tauri 플러그인·capability 없음)
2. **채팅 패널 연결** (layout_v4의 채팅 칸 그대로):
   - 내 말과 Claude의 답이 시간 순서로 보인다. 답은 `text_delta`가 오는 대로 늘어난다.
   - 끝나면 한 줄이 붙는다: "완료 · 추정 비용 $0.0123". 실패하면 오류 문구가 붙는다. SPEC 71행 "비용 항상 표시"의 최소 버전이고, 값은 `total_cost_usd`이며 "추정"이라고 적는다.
   - 입력 줄과 보내기. 실행 중에는 입력이 비활성이고 그 자리에 `중단` 버튼이 보인다.
   - 폴더(쟁점 1: 왼쪽 세션 목록에서 고른 세션의 `cwd`). 대화를 시작하면 첫 줄에 "폴더: <이름>"이 보이고, 그 대화가 끝날 때까지 폴더는 고정된다.
   - 한 대화 안에서 앞 답이 끝난 뒤 다시 보내면 같은 세션으로 이어 간다(같은 query에 메시지 추가). `새 대화` 버튼은 지금 대화를 닫는다.
3. **권한 카드** (채팅 안):
   - 도구 이름과 대상(Bash 명령, 파일 경로)을 텍스트로 보인다. 버튼은 `▶` 허용 / 거부 / 이 세션 동안.
   - 허용하면 `{behavior:"allow", updatedInput: input}`, 거부하면 `{behavior:"deny", message}`를 돌려준다.
   - `signal`이 abort되면 카드를 닫는다.
   - "이 세션 동안"의 범위(쟁점 4: Bash는 같은 명령 문자열만, 그 밖의 도구는 도구 이름 단위, 사이드카 메모리에만 저장)
4. **AskUserQuestion**:
   - `header`, 질문, 선택지 label·description을 `▶` 버튼으로 보인다. 다중선택은 고른 뒤 `보내기`.
   - 답은 `answers`로 돌려준다.
   - `preview`는 표시하지 않는다(HTML일 수 있음).
5. **중단**: `중단`을 누르면 `interrupt()`를 부른다. 채팅에 "중단됨"이 보이고 입력이 다시 열린다. 대기 중인 카드는 거부로 닫힌다.
6. **수명**:
   - 앱을 닫으면 사이드카와 그 아래 `claude.exe`를 정리한다. 대기 중이던 카드는 거부로 처리된다(쟁점 4).
   - 사이드카 시작 실패(node 없음, 버전 미달, SDK 오류, 로그인 안 됨)는 채팅에 한 줄로 보이고, 앱은 계속 동작한다.
7. **그래프·세션 목록**: 쟁점 5의 권고대로, Orbit이 띄운 세션은 기존 훅·로그 경로로 그래프와 세션 목록에 뜬다. SDK 스트림은 채팅에만 쓴다.
8. **신뢰 경계**:
   - SDK에서 온 문자열(답, 도구 입력, 질문, 오류)은 텍스트로만 렌더한다.
   - 프론트는 사이드카를 직접 부르지 않고 Rust 명령·이벤트만 쓴다. 따라서 CSP와 capability는 바뀌지 않는다.
   - 사이드카로 보내는 `cwd`는 Rust가 가진 세션의 cwd에서만 나온다. 프론트가 임의 경로를 넘기지 않는다.
9. **문서(librarian)**:
   - SPEC.md 화면 6번과 실행 엔진 절에 "이번에 된 것 / 뒤로 미룬 것"(모델 선택, 세션 이어가기, 실행 중 추가 지시, 트랙 선택, 예산 상한, 내장 하네스 플러그인 로드, SDK 직접 이벤트 수집)을 맞춰 적는다.
   - 다른 절은 건드리지 않는다.

## 사용자에게 물을 것

각 안마다 "→ 모습"으로 화면·동작에서 어떻게 보이는지 적었다. 위험을 받아들이는 안은 최악의 결과를 줄이지 않고 적었다.

### 1. 범위와 폴더 선택

- **(가) 권고: 최소 고리만**
  - 입력 → 스트리밍 응답 → 권한 카드·질문 → 중단 → 같은 대화 안의 후속 메시지까지 한다. 모델 선택, 기존 세션 이어가기(resume), 실행 중 추가 지시, 트랙 선택, 예산 상한은 뒤 run으로 미룬다.
  - 폴더는 **왼쪽 세션 목록에서 고른 세션의 cwd**다. 그 폴더에서 **새 세션**이 시작된다. 고른 세션을 이어 가는 것이 아니다.
  - → 모습: 세션을 고르면 입력이 열린다. 보내면 채팅 첫 줄에 "폴더: orbit"이 보이고, 세션 목록에 새 줄이 하나 생긴다. 고른 세션의 대화가 이어지는 것처럼 보이지 않도록 첫 줄에 "새 대화"라고 적는다. 모델은 CLI 기본값이고, 실행 중에는 입력 대신 `중단`만 보인다. 한 번도 Claude Code를 쓰지 않은 폴더는 세션이 없어서 고를 수 없다.
- (나) 최소 고리 + 폴더 선택 대화상자
  - → 모습: 채팅 위에 `폴더…` 버튼이 생기고 아무 폴더나 고를 수 있다. 대신 `tauri-plugin-dialog`(cargo + npm)와 `dialog:` capability가 새로 들어오고, 고른 경로를 저장·검증하는 코드가 는다.
- (다) SPEC 6번 전부(모델·트랙 선택, resume, 실행 중 추가 지시, 예산 상한까지)를 한 run에
  - → 모습: 입력 줄 위에 모델·트랙 드롭다운이 생기고, 세션 목록에서 고른 세션을 그대로 이어 쓴다. 대신 run이 커지고, 실제 모델 호출이 드는 검증 항목도 대략 두 배가 된다.
- 하위 질문: 앞 답이 끝난 뒤 다시 보내면 같은 세션으로 이어 갈지(권고), 매번 새 세션을 시작할지.
  - 같은 세션으로 이어 가면 → 모습: 앞 대화의 맥락이 남는다.
  - 매번 새 세션이면 → 모습: 보낼 때마다 세션 목록에 줄이 하나씩 는다.

### 2. 인증

- **(가) 권고: 사용자가 이미 쓰는 Claude Code 로그인·환경을 그대로 쓴다**
  - Orbit은 키·토큰을 받지 않고, 읽지 않고, 저장·표시·기록하지 않는다. 사이드카는 Orbit의 환경변수를 그대로 물려받는다.
  - → 모습: 로그인 화면이 없고 바로 보낼 수 있다. 로그인이 안 돼 있으면 채팅에 "터미널에서 `claude`로 로그인하세요" 계열의 SDK 오류 한 줄이 보인다.
  - **받아들이는 위험 (최악 그대로)**:
    - ① **정책.** Anthropic 문서는 "Agent SDK로 제품을 만드는 개발자는 API 키를 써야 하고, Free/Pro/Max 자격증명으로 요청을 중계하거나 Claude.ai 자격증명을 수집·저장·중개하면 안 된다"고 적는다. 동시에 "최종 사용자가 수정되지 않은 Claude Code 바이너리에 자기 구독으로 로그인하는 것"은 막지 않는다고 적는다. 개인용 로컬 앱이 본인의 로그인된 CLI를 SDK로 돌리는 경우가 어느 쪽인지는 문서가 말하지 않는다(RESEARCH 6, 미확인 1). 최악은 이 사용이 약관 위반으로 판단돼 **사용자의 Claude 계정(구독)이 제한되거나 정지되는 것**이다. 범위는 Orbit 세션만이 아니라 그 계정 전체, 즉 터미널 사용까지 포함한다.
    - ② **과금.** 지금(2026-11-14) 기준으로 구독 로그인의 SDK 사용은 구독 한도를 쓴다. 정책은 예고 없이 바뀔 수 있다. 이미 환경변수에 `ANTHROPIC_API_KEY`나 `ANTHROPIC_AUTH_TOKEN`이 있으면 구독보다 그것이 먼저 쓰여 **API 요금이 따로 청구되는데, 화면에는 차이가 보이지 않는다.** 비용 줄은 추정치이고 청구서가 아니다.
    - ③ **이름.** SDK 제품은 "Claude Code" 이름을 쓰지 말라는 브랜딩 규칙이 있다. 확정 시안의 입력 안내문 "Claude Code에게 무엇을 시킬까?"는 디자인 결정이라 바꾸지 않는다. 다만 배포로 바뀌면 다시 봐야 할 항목으로 남긴다.
- (나) Orbit이 Console API 키를 받아 OS 키체인에 저장하고, 사이드카 env로만 넘긴다
  - → 모습: 처음 보낼 때 "API 키 입력" 칸이 한 번 보이고, 이후에는 키 없이 `저장됨`만 보인다. 정책상 문서가 권하는 길이다. 대신 API 사용량만큼 **별도 요금**이 들고, `keyring` 계열 cargo 의존성과 키 입력·삭제 화면이 새로 생긴다.
- (다) 이미 설정된 `ANTHROPIC_API_KEY` 환경변수가 있을 때만 실행한다(입력 화면 없음, 구독 로그인은 쓰지 않음)
  - → 모습: 키가 없으면 채팅에 "ANTHROPIC_API_KEY가 없어 실행하지 않습니다" 한 줄만 보인다. 정책 위험은 (나)와 같이 낮고 코드도 작다. 대신 키를 사용자가 직접 OS 환경변수에 넣어야 하고, 터미널 Claude Code도 그 키로 청구되기 시작한다.

### 3. Node 사이드카를 어떻게 동반할지와 새 의존성

- **(가) 권고: 사용자 PC의 `node`(18.14 이상)로 저장소 안의 사이드카 스크립트를 Rust `std::process`로 띄운다**
  - 기존 Rust 코드처럼 스레드 + 파이프를 쓴다.
  - 새 의존성은 npm `@anthropic-ai/claude-agent-sdk` 하나와 그 peer(`zod ^4`, `@anthropic-ai/sdk`, `@modelcontextprotocol/sdk`)다. Windows용 `claude.exe`는 SDK의 선택 의존성(`-win32-x64`)으로 함께 깔린다.
  - cargo 의존성, Tauri 플러그인, capability는 새로 생기지 않는다.
  - → 모습: `npm run tauri dev`로 지금처럼 쓴다. node가 없으면 채팅에 버전 안내 한 줄이 보인다. **설치 파일로 만들어 다른 PC에서 쓰면 동작하지 않는다**(아직 설치 파일을 만든 적 없음, 개인용).
- (나) `bun build --compile` 단일 exe + `extractFromBunfs()`로 `claude.exe`를 풀어 쓴다. SDK 문서에 공식 절차가 있다.
  - → 모습: node 없이 설치 파일 하나로 돈다. 대신 빌드 도구에 bun이 필요하고, `externalBin`과 triple 접미 파일 관리가 생기며, 설치 파일 크기가 Node 런타임 + `claude.exe`만큼 커진다(크기 미측정). 사이드카 실행에 `tauri-plugin-shell`을 쓰면 `shell:allow-spawn` 같은 capability도 열린다.
- (다) `@yao-pkg/pkg` 단일 exe(Tauri 공식 Node 가이드 방식)
  - → 모습: (나)와 같다. 다만 pkg 안에서 SDK가 `claude.exe`를 찾는 공식 절차가 없어 동작이 미확인이다.
- 하위 질문: `claude.exe`는 SDK에 들어 있는 것을 쓸지(권고: 버전이 SDK와 맞음), 사용자가 설치한 `claude`를 `pathToClaudeCodeExecutable`로 가리킬지.
  - 사용자 설치본을 쓰면 → 모습: 터미널과 같은 버전이 돈다. 대신 SDK와 버전이 어긋날 수 있다(미확인).

### 4. "이 세션 동안 허용"의 범위, 앱을 닫을 때, AskUserQuestion

- **(가) 권고**:
  - **Bash는 똑같은 명령 문자열만**, 그 밖의 도구(Edit·Write 등)는 **도구 이름 단위**로 허용한다.
  - 규칙은 **사이드카 메모리에만** 저장하고, 대화가 끝나거나(`새 대화`, 앱 종료) 사이드카가 죽으면 사라진다.
  - SDK `suggestions`의 `localSettings`·`userSettings`·`projectSettings` 항목은 쓰지 않는다. `localSettings`를 쓰면 사용자 저장소의 `.claude/settings.local.json`에 규칙이 영구히 남는다(RESEARCH 3).
  - → 모습: 카드의 세 번째 버튼에 범위가 함께 보인다. 예: "이 세션 동안 (이 명령만)", "이 세션 동안 (Edit 전부)".
  - 받아들이는 위험: Edit를 한 번 "이 세션 동안"으로 허용하면, 그 대화가 끝날 때까지 **cwd 안팎의 어떤 파일 편집도** 카드 없이 통과한다. 여기에는 `.claude/settings.json`, CLAUDE.md도 포함된다. 저장소에서 읽은 내용에 담긴 프롬프트 인젝션이 그 틈을 쓸 수 있다.
- (나) 모든 도구를 도구 이름 단위로 허용(Bash 포함)
  - → 모습: 버튼이 단순해진다. **최악은 `npm test` 한 번을 허용하면 그 대화 동안 `rm -rf`, `git push --force`, 자격 증명 파일을 읽어 외부로 보내는 명령까지 사용자 권한으로 묻지 않고 실행되는 것**이다.
- (다) SDK가 제안한 규칙을 그대로 돌려준다(`localSettings` 포함)
  - → 모습: 터미널의 "항상 허용"과 같다. 대신 사용자 저장소에 `.claude/settings.local.json`이 생기거나 바뀌고, 그 규칙은 **Orbit을 지워도 터미널 세션에까지 영구히 적용된다.** 이 쓰기는 도구 호출이 아니라서 오르빗 저장소의 관문 훅에도 걸리지 않는다.
- **승인 대기 중에 앱을 닫으면 (권고)**: 대기 카드는 거부로 처리하고, 사이드카와 `claude.exe`를 끝낸다(`close()` → 프로세스 종료). 확인 창은 띄우지 않는다.
  - → 모습: 창이 바로 닫히고, 기다리던 명령은 실행되지 않는다.
  - 최악: 그 순간 **이미 실행 중이던 다른 도구**(예: 앞서 허용한 긴 Bash, 파일 쓰기)가 중간에 끊겨 파일이 반쯤 쓰인 상태로 남을 수 있다. 자식 프로세스 정리가 실패하면 `claude.exe`가 창 없이 남아 계속 돌 수 있다(Windows 동작 미확인, 성공 기준 12로 확인).
  - 대안: "실행 중인 작업이 있습니다. 닫을까요?" 확인 창을 띄운다. → 모습: 실수로 닫는 일이 줄어든다. 창 닫기 이벤트 처리가 는다.
- **AskUserQuestion (권고)**: 채팅에 `header`와 질문, 선택지 버튼(`▶ label`과 그 아래 description)을 보인다. 다중선택은 토글 뒤 `보내기`. 선택지 밖의 답은 입력 줄에 쓰면 자유 답으로 보낸다. `preview`는 보이지 않는다.
  - 제한(카드 아래에 작게 안내하지는 않고 문서에만 둔다): 서브에이전트 안에서는 AskUserQuestion이 오지 않는다. 사용자의 settings.json allow 규칙에 맞는 호출은 카드 없이 통과한다.
  - 대안: 자유 답 없이 버튼만. → 모습: 코드가 조금 줄고, 선택지가 마음에 안 들면 거부해야 한다.

### 5. 같은 세션이 그래프·세션 목록에 두 번 뜨지 않게

- **(가) 권고: SDK 스트림은 채팅에만 쓰고, 그래프·세션 목록은 지금 경로(훅 + 로그 감시)가 그대로 맡는다**
  - SDK 세션도 `settingSources` 기본값이라 사용자 훅이 발화하고, 로그가 `~/.claude/projects/`에 남는다. 그래서 세 번째 수집 경로를 만들지 않으면 중복도 생기지 않는다. 같은 `session_id`·`tool_use_id`라 기존 병합이 그대로 맞는다(RESEARCH 8).
  - → 모습: 보낸 뒤 세션 목록에 줄 하나가 생기고, 그래프가 터미널 세션과 똑같이 움직인다.
  - 한계: 훅을 제거한 상태면 그래프는 로그 감시 주기만큼 늦게 따라온다. SPEC 69행의 "SDK 메시지 스트림으로 직접 이벤트를 받는다"와는 다르다(문서에 미룬 것으로 적는다). id가 실제로 같은지는 성공 기준 7에서 실행으로 확인한다.
- (나) SDK 이벤트를 Store에 세 번째 출처(`Source::Sdk`)로 넣고, 같은 `call:/result:{tool_use_id}` 키로 병합한다
  - → 모습: 훅이 없어도 그래프가 즉시 반응한다. 대신 Rust 수집 코드와 테스트가 늘고, 키 규칙이 하나라도 어긋나면 노드가 두 개씩 보인다.
- (다) Orbit이 띄운 세션 id를 등록해 두고 훅·로그 쪽에서 그 세션을 무시한다
  - → 모습: 평소에는 (나)와 같다. 사이드카가 죽거나 스트림이 끊기면 **그 세션의 그래프가 멈춘 채 남는다**(다른 경로를 꺼 두었으므로).

### 6. 채팅 기록 보존

- **(가) 권고: 이번에는 메모리만 쓴다.** DB는 별도 run이고(decisions.md 13번 나), 이 run에서 정하지 않는다.
  - → 모습: 앱을 다시 켜면 채팅 칸이 비어 있다. 세션 목록·그래프는 로그에서 복원된다. 대화 내용은 Claude Code 로그에 남아 터미널 `claude --resume`으로 이어 갈 수 있다.
- (나) 세션을 고르면 그 세션의 JSONL 로그에서 채팅을 다시 그린다(읽기 전용, DB 없음)
  - → 모습: 터미널 세션을 포함해 어떤 세션을 골라도 과거 대화가 채팅에 보인다. 대신 로그 형식 파서가 하나 더 생기고(형식은 바뀔 수 있음), "보고 있는 세션"과 "새로 시작할 대화"의 구분을 화면에서 새로 정해야 한다.
- (다) 이번에 DB까지 넣는다
  - → 모습: (나)보다 빠르고 Orbit에서 시작한 대화의 메타데이터까지 남는다. 대신 SPEC의 마이그레이션·보관 정책을 함께 만들어야 해서 run이 크게 커진다.

### 7. 검증 분담 (실제 모델 호출)

- **(가) 권고**:
  - 에이전트(QA)는 호출 없는 항목(1~4, 13, 14의 grep, 16, 17)을 모두 한다.
  - `[호출]` 항목은 **임시 폴더 안에서, 한 run에 대략 10회 이내의 짧은 프롬프트로** 한다(5~12, 15, 사용자 로그인과 구독 한도를 씀). 승인 카드에서 QA가 누르는 대상은 성공 기준에 적힌 명령(`echo … > a.txt` 등)으로만 한정한다.
  - **사용자**는 실제 로그아웃 상태 확인(14), 오르빗 저장소 같은 실제 프로젝트에서 한 번 써 보기, 비용 줄과 실제 사용량 대조를 한다.
  - → 모습: QA 보고서에 `[호출]` 항목마다 보낸 프롬프트, 누른 버튼, 화면 캡처가 붙는다. 그동안 사용자의 구독 한도가 조금 줄어든다.
  - 최악: QA의 호출은 사용자 계정과 사용자 권한으로 돈다. Claude가 성공 기준 밖의 명령을 제안했는데 QA가 잘못 `허용`을 누르면, 그 명령이 사용자 PC에서 실행된다. 쟁점 2 (가)의 정책 위험도 이 호출들에 그대로 해당한다. 에이전트 셸(MSIX 컨테이너) 안에서 띄운 Orbit이 같은 로그인 파일을 보는지는 미확인이다(decisions.md 14번 T8 참고).
- (나) 에이전트는 실제 호출을 하지 않는다. 사용자가 `[호출]` 항목 체크리스트를 받아 직접 한다.
  - → 모습: 계정 위험이 사용자 손에만 있다. 대신 QA 보고서의 `[호출]` 칸이 "사용자 확인 대기"로 남고, 결과를 사용자가 붙여 줘야 VERIFY가 끝난다.
- (다) 에이전트가 횟수 제한 없이 모두 한다
  - → 모습: 사용자는 결과만 본다. 실패 → 수정 → 재검증 루프마다 호출이 다시 들어 사용량을 예측할 수 없다.

### 8. 권한 모드와 자동 승인

- **(가) 권고: 이번 run에서는 자동 승인 토글을 만들지 않는다.** `permissionMode: "default"`를 코드에 고정한다. 명시하면 사용자 설정의 `defaultMode`가 덮어쓰지 못한다.
  - → 모습: 권한 모드를 바꾸는 UI가 없고, 카드가 늘 뜬다. 예외로 사용자 settings.json의 allow 규칙에 맞는 호출은 지금 터미널처럼 카드 없이 통과한다.
  - decisions.md 10번("자동 승인 모드를 켜기로 할 때까지 관문 보강 보류")과도 맞는다.
- (나) `acceptEdits` 토글(편집만 자동, Bash 등은 계속 카드)
  - → 모습: 채팅 위에 "편집 자동 허용" 체크가 생긴다. 최악은 Claude가(또는 저장소 파일의 프롬프트 인젝션이) 작업 폴더의 파일을 묻지 않고 고쳐서 **커밋 안 된 작업이 덮이거나** `.claude/` 설정·CLAUDE.md가 바뀌는 것이다. 10번 보류를 먼저 풀어야 하는지도 함께 정해야 한다.
- (다) `bypassPermissions` 토글(`allowDangerouslySkipPermissions`)
  - → 모습: 켜면 카드가 사라진다. **최악은 사용자 권한으로 모든 명령이 묻지 않고 실행되는 것이다**: 저장소 밖 파일 삭제, `git push --force`, 자격 증명 읽기와 외부 전송. 저장소의 README·이슈에 심은 지시 하나로도 일어날 수 있다. decisions.md 10번에 따라 관문 F1~F3 run이 먼저다.

### 9. (추가) "그 프로젝트의 하네스"를 어디까지 붙일지

SPEC 67행은 Orbit 내장 하네스를 SDK `plugins`로 붙인다고 적었지만, 8개 쟁점에는 없어서 따로 묻는다.

- **(가) 권고: 이번에는 터미널과 같은 설정만 쓴다**(`settingSources` 기본: `~/.claude`, `<cwd>/.claude`, CLAUDE.md). `plugins` 주입은 뒤 run으로 미룬다.
  - → 모습: 오르빗 저장소에서는 이미 `.claude/settings.json`이 `orbit` 플러그인을 로드하므로 지금 터미널과 똑같이 관문이 걸린다. 하네스가 없는 다른 저장소에서는 맨 Claude Code로 돈다.
- (나) cwd에 `orbit` 플러그인이 없으면 `plugins:[{type:"local", path:<harness 절대경로>}]`로 붙인다
  - → 모습: 어느 저장소에서 보내도 Lead·관문이 걸린다. 대신 관문 훅(`gate.mjs`)이 그 저장소의 편집·빌드를 막기 시작한다. 이것은 제품 방향 결정이고, 없는 경로는 조용히 건너뛰므로 init 메시지 검사가 필요하다. HARNESS.md 8절 판단도 필요하다.
