## 1. SDK 패키지 · 버전 · Node · CLI 번들 · Windows
- 패키지 `@anthropic-ai/claude-agent-sdk`, 설치 `npm install @anthropic-ai/claude-agent-sdk` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)).
- npm 최신 0.3.325, `engines.node >=18.14.0`, peer 의존성 `zod ^4`, `@anthropic-ai/sdk >=0.93.0`, `@modelcontextprotocol/sdk ^1.29.0`, 선택 의존성 `@anthropic-ai/claude-agent-sdk-win32-x64` / `-win32-arm64` ([npm registry](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/latest)). 라이선스 필드는 "SEE LICENSE IN README.md"(내용 미확인).
- Node 18.14+ 요건은 [Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)에도 있다.
- Claude Code 네이티브 바이너리를 **번들한다**(플랫폼별 선택 의존성). SDK 버전이 번들 CLI 버전을 따른다(예: SDK 0.3.191 = Claude Code 2.1.191). 별도 설치 불필요 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript), [Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)).
- 함정: `npm ci --omit=optional`처럼 선택 의존성을 건너뛰면 `Native CLI binary for <platform>-<arch> not found`. 이때 `pathToClaudeCodeExecutable`로 따로 설치한 `claude` 경로를 준다 ([Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)).
- Windows: 바이너리 하위 경로가 `claude.exe`(`@anthropic-ai/claude-agent-sdk-win32-x64/claude.exe`) ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). SDK는 "Claude Code 바이너리를 실행하는 라이브러리"다 ([overview](https://code.claude.com/docs/en/agent-sdk/overview)). 즉 사이드카(Node) 아래에 `claude.exe`가 자식 프로세스로 또 뜬다.
- `executable: 'bun'|'deno'|'node'`(자동 감지), `env`는 병합이 아니라 **교체**라서 `{...process.env, ...}`로 줘야 PATH가 유지된다 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)).

## 2. 스트리밍 입력 · 부분 메시지
- `prompt`는 `string` 또는 `AsyncIterable<SDKUserMessage>`. 스트리밍 입력 모드가 권장이며 메시지 큐잉(실행 중 추가 지시), 중단, 권한 요청 처리를 지원한다 ([streaming-vs-single-mode](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode)). 사용자 메시지 형태: `{type:"user", message:{role:"user", content}, parent_tool_use_id:null}`.
- `interrupt()`, `setPermissionMode()`, `setModel()`, `applyFlagSettings()`는 **스트리밍 입력 모드에서만** 된다 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). 단일 문자열 프롬프트는 큐잉·중단 불가 → Orbit은 항상 AsyncIterable로 시작해야 한다.
- 부분 메시지: `includePartialMessages: true`(기본 false). `{type:"stream_event", event}`로 원시 API 이벤트가 오고 글자 조각은 `event.type==="content_block_delta"` + `event.delta.type==="text_delta"`의 `delta.text`. 도구 입력은 `input_json_delta.partial_json` ([STREAM](https://code.claude.com/docs/en/agent-sdk/streaming-output)).
- 제한: 스트림 이벤트는 **메인 세션만**(서브에이전트 토큰 델타는 안 옴, `parent_tool_use_id`는 항상 null). 서브에이전트 출력은 완성된 AssistantMessage로만 온다. 스트림이 끊기면 `message_delta`/`content_block_stop`이 빠질 수 있다 ([STREAM](https://code.claude.com/docs/en/agent-sdk/streaming-output)). 번들 CLI 2.1.290 이상(SDK 0.3.290+)이어야 `message_stop` 보장.
- 메시지 순서 예: message_start → content_block_start → text_delta들 → 완성 AssistantMessage → content_block_stop … → ResultMessage ([STREAM](https://code.claude.com/docs/en/agent-sdk/streaming-output)).

## 3. canUseTool · 권한 모드 · AskUserQuestion
- 서명 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)):
  `CanUseTool = (toolName, input, options:{signal, suggestions?:PermissionUpdate[], blockedPath?, mcpServer?, decisionReason?, defaultToNo?, suppressAlwaysAllowRule?, toolUseID, agentID?, requestId}) => Promise<PermissionResult | null>`
- 반환 `PermissionResult`: 허용 `{behavior:"allow", updatedInput?, updatedPermissions?: PermissionUpdate[], toolUseID?}`, 거부 `{behavior:"deny", message, interrupt?, toolUseID?}` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). v2.1.207 전에는 `updatedInput` 생략한 allow가 검증 오류로 거부됐다 → 항상 `updatedInput: input`을 넣는다 ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)).
- 입력 수정 허용 = allow + 바꾼 `updatedInput`. 거부 메시지는 Claude가 읽는다. 거부 + 대안 안내 가능. 완전한 방향 전환은 스트리밍 입력으로 새 지시를 보낸다 ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)).
- "항상/이 세션 허용": `options.suggestions`(제안된 PermissionUpdate)를 `updatedPermissions`로 되돌려 준다. 문서 예시는 `destination === "localSettings"` 제안을 고르는데 이는 `.claude/settings.local.json`(사용자 저장소 파일)에 규칙을 쓴다 ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)). `suppressAlwaysAllowRule: true`인 요청은 "항상 허용" 선택지를 숨기라는 힌트이며 SDK 0.3.268+ ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)).
- `PermissionUpdate` = addRules / replaceRules / removeRules(`rules:{toolName, ruleContent?}[]`, `behavior:"allow"|"deny"|"ask"`, `destination`) / setMode / addDirectories / removeDirectories. `destination` = `"userSettings"|"projectSettings"|"localSettings"|"session"|"cliArg"` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). 즉 destination `"session"`이 "이 세션 동안"에 해당하는 값으로 **타입상** 존재한다.
- 권한 모드 `PermissionMode` = `default | acceptEdits | bypassPermissions | plan | dontAsk | auto` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript), [PERM](https://code.claude.com/docs/en/agent-sdk/permissions)). Claude Code 2.1.302+는 `permissionMode`를 안 주면 `default`로 시작하지만 설정 파일의 `permissions.defaultMode`가 바꿀 수 있다 → Orbit은 `permissionMode`를 명시한다. `bypassPermissions`는 `allowDangerouslySkipPermissions: true`가 필요 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)).
- canUseTool이 **안 불리는** 경우: 훅이 결정, deny 규칙, acceptEdits/bypass/auto 모드, allow 규칙(`allowedTools` 이름만 적은 항목 포함), `dontAsk` 모드(거부), `permissionPrompts:'none'`(CC 2.1.259+). `bypassPermissions` + canUseTool이면 Node 경고 `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` ([PERM](https://code.claude.com/docs/en/agent-sdk/permissions)). 사용자의 settings.json allow 규칙도 적용되므로 "Orbit 카드 없이 통과"하는 호출이 있을 수 있다.
- 콜백은 **무기한 대기 가능**(실행이 멈춰 기다린다). 오래 걸릴 수 있으면 PreToolUse 훅 `defer`를 쓰라는 안내가 있다 ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)). SDK 세션에서 `permission_prompt` Notification 훅이 약 6초 대기 후 발화(SDK 0.3.233+) ([HOOKS](https://code.claude.com/docs/en/agent-sdk/hooks)).
- AskUserQuestion: canUseTool로 **온다**(`toolName === "AskUserQuestion"`). 단 `tools` 배열로 도구를 제한했다면 `AskUserQuestion`을 포함해야 한다. 입력 `{questions:[{question, header(≤12자), options:[{label, description, preview?}] (2~4개), multiSelect}]}` (질문 1~4개). 답은 `{behavior:"allow", updatedInput:{questions: input.questions, answers:{[질문 텍스트]: 선택 label}}}`. 다중선택은 label 배열 또는 `", "`로 합친 문자열. 자유 입력은 그 텍스트를 값으로. 카드를 닫고 일반 답장을 줄 땐 `response` 필드. 서브에이전트 안에서는 AskUserQuestion을 **쓸 수 없다** ([INPUT](https://code.claude.com/docs/en/agent-sdk/user-input)). `toolConfig.askUserQuestion.previewFormat: "markdown"|"html"`이면 `preview`가 오며 html은 `<script>` 등을 SDK가 거른다지만 화면에는 HTML로 넣지 않는 편이 CLAUDE.md 규칙에 맞다.

## 4. resume · interrupt · 세션 id · 모델
- 세션 id: init `SystemMessage`(`type:"system", subtype:"init"`)의 `session_id`(TS는 직접 필드)가 가장 빠르고, `SDKResultMessage.session_id`는 성공·실패 모두 있다 ([SESS](https://code.claude.com/docs/en/agent-sdk/sessions)).
- resume: `resume: <sessionId>`. 최근 세션 이어가기는 `continue: true`. 분기는 `forkSession: true`(새 id). 다른 cwd에서도 id로 찾지만(CC 2.1.223+) 같은 PC에 파일이 있어야 한다 ([SESS](https://code.claude.com/docs/en/agent-sdk/sessions)). `persistSession`(기본 true)을 false로 하면 resume 불가.
- interrupt: `Query.interrupt()`는 스트리밍 입력 모드 전용. CC 2.1.205+에서 `interrupt_receipt_v1` 능력이 있으면 `still_queued`(대기 중이던 사용자 메시지 UUID 목록)를 돌려주고, 그 전에는 `undefined` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). 훅 콜백이 대기 중일 때 interrupt하면 도구 호출이 취소된다(2.1.208+) ([HOOKS](https://code.claude.com/docs/en/agent-sdk/hooks)). 강제 종료는 `close()`, 취소 신호는 `abortController` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)).
- 모델: `model: string`(별칭 또는 전체 이름, 기본은 CLI 기본값), 실행 중 변경은 `setModel()`(스트리밍 입력). 사용 가능한 모델 이름 목록은 이 조사에서 열지 않았다(미확인).
- 비용: `SDKResultMessage.total_cost_usd`(누적 **추정치**, 청구서 아님), 토큰은 `modelUsage` 권장(`usage`는 메인 루프만) ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). 예산 상한은 `maxBudgetUsd`(클라이언트 추정치라 초과 가능, 이어받은 세션의 이전 합계는 안 셈) → 결과 subtype `error_max_budget_usd`.
- 세션 목록·읽기 함수 `listSessions()`, `getSessionMessages()`, `getSessionInfo()`, `renameSession()` 존재 ([SESS](https://code.claude.com/docs/en/agent-sdk/sessions)).

## 5. 설정 · 하네스 로드 · 훅 · 로그
- `settingSources`: `"user" | "project" | "local"`. 생략하면 `["user","project","local"]`과 같다(CLI와 동일: ~/.claude, <cwd>/.claude, CLAUDE.md, 스킬·에이전트·커맨드, 훅). `[]`는 user·project·local 설정을 끈다. 관리형 정책 설정, `~/.claude.json`, 자동 메모리는 이 옵션과 무관하게 항상 읽힌다 ([FEAT](https://code.claude.com/docs/en/agent-sdk/claude-code-features)). 프로젝트 `settings.json`은 `<cwd>/.claude/`만 보고 부모 폴더로 올라가지 않는다. 옵션 이름은 현재도 `settingSources`다.
- "터미널과 같게" = `settingSources` 생략(또는 3개 명시). `systemPrompt`는 기본이 최소 프롬프트(`undefined`)이므로 Claude Code 프롬프트를 원하면 `{type:"preset", preset:"claude_code"}`를 준다 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). CLAUDE.md 로드가 preset 지정에 의존하는지는 문서에서 명시를 못 찾았다(미확인, FEAT는 `settingSources`에 `project`가 있으면 로드한다고만 적음).
- 플러그인: `plugins: [{ type: "local", path: "<절대경로>" }]` (`type`은 `"local"`만 허용). 경로는 플러그인 루트(`skills/ agents/ hooks/ commands/ .claude-plugin/`의 부모). 상대경로는 `cwd` 기준, `~`는 확장 안 됨, **없는 경로는 조용히 건너뜀** → init 메시지의 `plugins` / `plugin_errors` / `skills` / `slash_commands`로 로드를 확인해야 한다. 스킬은 `/플러그인이름:스킬이름`으로 네임스페이스가 붙는다. 실행 중 `reloadPlugins({addPlugins})`(SDK 0.3.301+) ([PLUG](https://code.claude.com/docs/en/agent-sdk/plugins)). 플러그인은 agents·skills·hooks·MCP를 묶는다 → `harness/`를 사용자 저장소에 쓰지 않고 붙일 수 있다. 사용자 저장소 파일은 안 쓴다는 HARNESS.md 8절 요건과 맞는다.
- 훅: 파일시스템 훅(settings.json의 command / **http** / mcp_tool / prompt / agent)과 프로그램 훅(`options.hooks` 콜백)이 **나란히** 돈다. 파일시스템 훅은 해당 `settingSources`가 켜져 있으면 SDK 세션에서도 발화하고 서브에이전트에서도 발화한다 ([FEAT](https://code.claude.com/docs/en/agent-sdk/claude-code-features), [HOOKS](https://code.claude.com/docs/en/agent-sdk/hooks)). 모든 훅 입력에 `session_id`, `cwd`, `hook_event_name`이 있고 서브에이전트 안이면 `agent_id`/`agent_type`. 도구 훅은 `tool_use_id`로 Pre/Post를 짝지을 수 있다. 훅 콜백 기본 타임아웃은 이벤트별 600초/30초 등(HOOKS).
- → **이중 포착**: 사용자의 `~/.claude/settings.json`에 Orbit http 훅이 설치돼 있으면 Orbit이 띄운 SDK 세션의 이벤트도 같은 훅 서버로 온다. 문서상 `settingSources` 기본값이 user를 포함하므로 거의 확실하다(Orbit 훅 서버로 실제 도착하는지는 실행 실험으로 미확인).
- 로그: 세션은 `~/.claude/projects/<인코딩된 cwd>/<session-id>.jsonl`에 저장되고 `CLAUDE_CONFIG_DIR`이 있으면 `$CLAUDE_CONFIG_DIR/projects/`. 인코딩은 비영숫자를 `-`로 바꾸며 200자 초과 시 잘라 해시를 붙인다 ([SESS](https://code.claude.com/docs/en/agent-sdk/sessions)). `persistSession:false`가 아니면 같은 위치에 남는다 → 기존 로그 감시(watch.rs)가 그대로 잡는다. 줄 형식이 터미널과 완전히 같은지는 이 조사에서 직접 비교 못 했다(미확인).
- TS SDK 전용 훅: SessionStart, SessionEnd, StopFailure 등. Python에는 없음(Orbit은 TS라 무관). SDK의 `includeHookEvents`(기본 false)는 훅 수명주기를 메시지 스트림에 넣는다 ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)).

## 6. 인증 · 정책 · 과금
- 인증 우선순위(Claude Code 공통, SDK도 CLI를 거침): Bedrock/Vertex/Foundry 변수 → `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY`(비대화형 `-p`에선 있으면 항상 사용) → `apiKeyHelper` → `CLAUDE_CODE_OAUTH_TOKEN` → Anthropic 프로필 → `/login`의 구독 OAuth ([AUTH](https://code.claude.com/docs/en/authentication)). `apiKeyHelper`/`ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`은 "CLI와 그것을 감싼 Agent SDK 등"에 적용된다고 명시돼 있다. 즉 환경변수에 ANTHROPIC_API_KEY가 있으면 그것이 구독보다 우선한다.
- 구독 로그인 자체를 SDK가 쓰는지: 지원 문서가 "plan 로그인 상태에서 Agent SDK/`claude -p`는 구독 한도를 쓴다"고 적는다([Claude 지원 문서](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). SDK 문서 쪽에는 `Not logged in` 오류 안내가 있다([Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)). 구독 로그인 사용 경로가 막혀 있지는 않다.
- **정책 제한**: 공식 안내는 "별도 승인이 없으면 서드파티 개발자는 claude.ai 로그인이나 요금 한도를 자기 제품(Agent SDK 기반 에이전트 포함)에서 제공할 수 없다. API 키 인증을 써라" ([overview](https://code.claude.com/docs/en/agent-sdk/overview), [Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)). 법무 문서는 더 구체적이다: Agent SDK 등으로 제품을 만드는 개발자는 Console API 키나 클라우드 제공자 인증을 써야 하고, Free/Pro/Max/Ultra 플랜 자격증명으로 사용자를 대신해 요청을 중계하거나 Claude.ai 자격증명·세션 토큰을 **수집·저장·중개하면 안 된다**. 다만 "최종 사용자가 수정되지 않은 Claude Code 바이너리에 자기 구독으로 로그인하는 것"은 막지 않는다고 적힌다 ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance)). 개인용 로컬 도구가 사용자 본인의 이미 로그인된 CLI 자격증명을 그대로 쓰는 경우가 어디에 해당하는지는 문서가 직접 말하지 않는다(미확인, 판단은 사람이). 안전한 설계 쪽: Orbit은 토큰·OAuth를 읽지도 저장하지도 않고, 바이너리를 수정하지 않고, 로그인은 CLI 자체 흐름에 맡긴다. API 키는 Orbit에 입력받는다면 키체인에 둔다(SPEC과 일치).
- 과금: 지원 문서 기준(2026-11-14 열람) 구독 로그인 상태의 Agent SDK/`claude -p`는 **구독 한도**를 쓴다. 2026-06-15에 예고됐던 별도 크레딧 분리는 "paused"(보류), 2026-10-07 갱신으로 Max/Ultra/Team에 월 API 크레딧이 생겼고 이는 Console API 키로 돌릴 때 적용된다([지원 문서](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). 페이지에 마지막 수정일이 명시돼 있지 않아 이 정책은 바뀔 수 있다. 화면에 비용을 "추정치"로 표시하라는 근거는 `total_cost_usd`가 추정이라는 점이다.
- 브랜딩: SDK 기반 제품은 "Claude Code"/"Claude Code Agent" 이름이나 Claude Code를 흉내 낸 시각 요소를 쓰면 안 되고, "Claude Agent" 또는 "{이름} Powered by Claude"를 쓴다([overview](https://code.claude.com/docs/en/agent-sdk/overview)). 법무 문서는 "Claude Code를 실행한다"고 평문으로 사실을 말하는 것은 허용한다([legal](https://code.claude.com/docs/en/legal-and-compliance)). ## 7. Tauri 2 사이드카
- `bundle.externalBin: ["binaries/my-sidecar"]`, 실제 파일은 `src-tauri/binaries/my-sidecar-<target-triple>`(Windows는 `.exe`), 호스트 triple은 `rustc --print host-tuple`(Rust 1.84+) ([Tauri sidecar](https://v2.tauri.app/develop/sidecar/)). Orbit은 edition 2024라 Rust 1.85+이므로 충족.
- 실행 API: Rust `app.shell().sidecar("my-sidecar")` → `.spawn()` → `(rx, child)`; `CommandEvent::Stdout(bytes)`로 줄 단위 수신, `child.write(...)`로 stdin 송신. JS는 `Command.sidecar('binaries/my-sidecar')`의 `execute()`/`spawn()`. 인자는 Rust `.args([...])`, JS 두 번째 인자 ([Tauri sidecar](https://v2.tauri.app/develop/sidecar/)). 플러그인 `tauri-plugin-shell`(Rust)과 JS는 `@tauri-apps/plugin-shell` 설치 필요: `npm run tauri add shell` 또는 `cargo add tauri-plugin-shell` ([shell plugin](https://v2.tauri.app/plugin/shell/)).
- capability: 위험 명령은 기본 차단. `shell:allow-execute` / `shell:allow-spawn` / `shell:allow-stdin-write` / `shell:allow-kill`을 켜야 하고 사이드카는 `{ "identifier":"shell:allow-spawn", "allow":[{ "name":"binaries/my-sidecar", "sidecar":true, "args":[{"validator":"\\S+"}] }] }`처럼 이름과 `args` 검증으로 범위를 좁힌다(`args:true`는 모든 인자 허용) ([sidecar](https://v2.tauri.app/develop/sidecar/), [plugin](https://v2.tauri.app/plugin/shell/)).
- Tauri 가이드의 주의: 예제는 명령 하나당 프로세스 하나인 단발성이며, 오래 도는 앱은 localhost 서버·stdin/stdout·소켓 같은 IPC를 따로 고려하라고 한다 ([Node sidecar guide](https://v2.tauri.app/learn/sidecar-nodejs/)).
- Node 런타임 동반 방식(조사 결과):
  - `@yao-pkg/pkg`로 단일 exe: Tauri 공식 Node 가이드가 쓰는 방식. 가이드는 SEA·bun은 다루지 않고 "JS를 컴파일하는 다른 도구도 된다"고만 쓴다. 런타임+JS 리소스 동봉은 더 크다고 적음 ([guide](https://v2.tauri.app/learn/sidecar-nodejs/)).
  - Node SEA: 안정성 "1.1 Active development", 스크립트 하나만 실행(번들 필요), 파일 모듈 로드는 `createRequire`로, Windows 빌드는 `node --build-sea`(Node 25.5+) 또는 postject. 다른 바이너리 spawn 제약은 문서에 없음 ([Node SEA](https://nodejs.org/api/single-executable-applications.html)).
  - `bun build --compile`: SDK가 번들 CLI를 `require.resolve`로 못 찾아 오류가 나므로, 플랫폼 바이너리를 파일 에셋으로 임베드하고 `extractFromBunfs()`(SDK 0.3.144+, `@anthropic-ai/claude-agent-sdk/extract`)로 실제 경로에 풀어 `pathToClaudeCodeExecutable`에 넘기라는 **공식 절차**가 있다. Windows 서브경로는 `.../claude.exe` ([TS](https://code.claude.com/docs/en/agent-sdk/typescript)). SEA/pkg에 대한 SDK 공식 절차는 못 찾았다.
  - 사용자 PC의 `node` 사용: Tauri 문서에 해당 방식 안내는 없다. SDK는 Node ≥18.14 요구(앞 절)이므로 가능은 하나 PC에 Node가 없으면 실패한다(미확인 영역은 설계 판단).
- 어느 쪽이든 `claude.exe`(네이티브)는 Node 단일 exe와 별개 파일이다. 번들 크기는 이 조사에서 재지 않았다. 대안: 사용자가 이미 설치한 `claude`를 `pathToClaudeCodeExecutable`로 쓰면 동봉이 필요 없고 CLI 로그인·버전이 사용자 것과 같다(번들 버전과 SDK의 짝이 어긋날 수 있다는 점은 문서에 명시 없음, 미확인).
- `tauri dev`와 번들 차이: 공식 가이드는 `npm run tauri dev`로 확인하라고만 하고(단계 7), dev에서 `externalBin` 파일이 없을 때 빌드가 실패하는지는 문서에 명시가 없다(미확인). 번들은 triple 접미 파일이 있어야 포함된다([sidecar](https://v2.tauri.app/develop/sidecar/)).
- Rust `std::process`로 직접 띄우기: Tauri 문서가 이 방식을 다루지 않아 장단점은 문서 근거가 없다. 코드베이스 사실만: 지금 Rust 쪽은 tokio 없이 `std::net`/스레드로 서버·감시를 돌리고 있어 `std::process::Command` + 파이프 스레드가 기존 스타일에 맞고 `tauri-plugin-shell` 의존성·`shell:*` capability가 필요 없다. 대신 번들 사이드카 경로 해석(`externalBin` 파일 위치 계산)과 프로세스 정리는 직접 해야 한다. capability는 웹뷰→명령 IPC 권한이라 Rust가 자체로 띄우는 프로세스에는 적용되지 않는다는 점은 이 조사에서 문서로 확인하지 못했다(미확인).

## 8. 이 저장소의 현재 상태 (코드 직접 확인)
- `package.json`: react/react-dom ^19.1, `@tauri-apps/api` ^2, `@tauri-apps/plugin-opener` ^2, vite ^8, typescript ~6.0.3. SDK·shell 플러그인 없음. 스크립트 `dev`, `build`(`tsc && vite build`), `tauri`.
- `src-tauri/Cargo.toml`: edition 2024, `tauri 2`(feature `protocol-asset`), `tauri-plugin-opener 2`, serde, serde_json(preserve_order), getrandom 0.4. tokio·shell 플러그인 없음.
- `src-tauri/capabilities/default.json`: `core:default`, `opener:default`만(창 `main`).
- `src-tauri/tauri.conf.json`: CSP `default-src 'self' ipc: http://ipc.localhost; img-src 'self' asset: http://asset.localhost; font-src 'self'; style-src 'self'`(dev는 `script-src 'unsafe-inline'`, `connect-src ... ws://localhost:1420` 추가). `bundle.targets:"all"`, `externalBin`/resources 없음. 프론트가 사이드카와 직접 통신하지 않고 Rust `invoke`/이벤트만 쓰면 CSP 변경은 필요 없다(`connect-src` 없이 ipc만).
- 훅 서버(`src-tauri/src/server.rs`): `TcpListener::bind(("127.0.0.1", port))`, Host가 `127.0.0.1:port`/`localhost:port`가 아니면 403, `Origin` 헤더 있으면 403, `X-Orbit-Token`을 `ct_eq`로 비교(없거나 틀리면 401), 본문 `MAX_BODY` 4 MiB(초과 413), 스레드별 처리, 헤더 과대 431. `POST /events`만. 사이드카도 이 서버를 쓰려면 같은 토큰이 필요하다(토큰은 `config::load_or_create(app_data_dir)`).
- 세션 식별(`sessions.rs`, `lib.rs`): 세션 키는 `session_id` 문자열 하나. 훅은 페이로드 `session_id`(+`cwd`), 로그는 `<root>/<dir>/<uuid>.jsonl`의 파일명 uuid(`watch.rs` `is_uuid`, 깊이 2)를 세션 id로 쓴다. 이벤트 중복 제거 키는 `call:{tool_use_id}` / `result:{tool_use_id}`, id가 없으면 로그 줄 `uuid:{uuid}:{i}`. 같은 키가 다른 경로로 오면 `Source`가 `Both`로 합쳐진다(`Source`는 현재 `Hook | Log | Both`, SPEC의 `SDK` 출처는 없음).
- 따라서 이중 포착 문제의 키는 **SDK `session_id`** 와 **`tool_use_id`**다. SDK가 주는 `session_id`는 init 메시지와 결과 메시지에서 오고, 로그 파일명이 `<session-id>.jsonl`이므로([SESS](https://code.claude.com/docs/en/agent-sdk/sessions)) 훅·로그와 같은 id일 가능성이 높다(실제 일치는 실행해서 확인하지 않음). SDK 이벤트(`assistant`의 `tool_use` 블록 id, `PreToolUse` 콜백의 `tool_use_id`)를 `call:{id}`/`result:{id}` 키 규칙에 맞춰 넣으면 현재 `add_event` 병합 로직이 그대로 중복을 막는다. 훅 `PreToolUse`는 `tool_use_id`를 주고 로그 tool_use 블록 `id`와 같은 값이 이미 코드·테스트(`b_hook_and_log_call_both_orders`)에서 가정돼 있다.
- 실행 엔진에 쓸 `~/.claude/settings.json` 경로는 lib.rs `settings_path`, 프로젝트 로그 루트는 `CLAUDE_CONFIG_DIR` 존중(`projects_dir`). 개발용 덮어쓰기 환경변수 `ORBIT_CLAUDE_SETTINGS`, `ORBIT_CLAUDE_PROJECTS`(debug 빌드 한정).
- `.orbit/profile.json`: 이미 최신(2026-11-14, stack에 `node` 포함, 신호 근거가 현재 저장소와 맞음). 이번에 바꾸지 않았다. ⑥이 끝나면 `devops`(사이드카 패키징)와 `security-deep`(사이드카 프로세스 경계·권한 카드)의 근거를 보강할 수 있다.

## 설계에 미치는 영향 (권고, 최종 결정은 Lead)
- 사이드카는 `prompt`를 AsyncIterable로 항상 열어 두고(큐잉·interrupt·setModel 가능), `includePartialMessages: true`, `permissionMode`를 명시(기본 `default`), `settingSources` 생략(= 터미널과 동일), `plugins: [{type:"local", path:<harness 절대경로>}]`, `cwd` = 선택한 프로젝트로 `query()`를 건다. 시작 시 init 메시지로 plugins/plugin_errors를 검사해 조용한 로드 실패를 잡는다.
- 권한 카드: `canUseTool`을 Rust↔UI 왕복(requestId/toolUseID로 매칭, `signal` abort 시 카드 닫기)으로 풀고 응답은 allow(+`updatedInput: input`)/deny(+message). "이 세션 동안 허용"은 `suggestions`의 session 항목 또는 직접 만든 session 목적지 규칙, `localSettings`는 사용자 저장소를 건드리므로 기본 선택지에서 뺀다. 자동 승인 모드는 명시적 사용자 옵션(`bypassPermissions`는 `allowDangerouslySkipPermissions` 필요, canUseTool이 거의 안 불림).
- 사용자 allow 규칙이나 모드로 canUseTool을 우회하는 호출은 Orbit 카드가 안 뜬다. 완전한 감사가 필요하면 PreToolUse 훅 콜백이 필요하다는 점을 승인 UI 설명에 남긴다.
- AskUserQuestion은 canUseTool 경로로 선택지 버튼 → `answers` 반환. 서브에이전트에서는 안 온다는 제한을 UI 문구에 반영.
- 이중 포착: SDK 경로 이벤트를 기존 Store에 `call:/result:{tool_use_id}` 키로 넣고 `Source`에 SDK 출처를 추가하거나(Both 확장), SDK 세션 id를 Store에 등록해 훅·로그 쪽이 병합하도록 한다. 훅·로그가 이미 같은 키 규칙이라 새 중복 제거 로직은 필요 없을 가능성이 높다(실행으로 확인 필요).
- 사이드카 통신은 stdin/stdout JSON 줄(Tauri 가이드가 장기 실행 앱에 권장하는 IPC 중 하나). 프론트는 Rust 명령·이벤트만 쓰고 웹뷰가 사이드카를 직접 부르지 않으면 `shell:*` capability와 CSP 변경을 피할 수 있다(Rust에서 spawn할 경우). 토큰·API 키는 사이드카 `env`로만 넘기고 로그·URL에 남기지 않는다(SDK `env`는 교체 방식).
- 패키징은 결정이 필요하다: (a) bun compile + `extractFromBunfs` = 공식 절차 있음, (b) pkg = Tauri 공식 Node 가이드, (c) SEA = 실험적 단계 표기, (d) 사용자 `claude` 재사용 = 동봉 불필요. `claude.exe`를 따로 싣거나 사용자 설치본을 가리켜야 한다는 점이 공통.
