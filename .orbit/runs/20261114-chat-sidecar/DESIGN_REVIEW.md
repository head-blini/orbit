# DESIGN_REVIEW — 20261114-chat-sidecar (V2, designer)

대상 COMMIT: ed57684 (VERIFY.md와 같음). 앱은 직접 띄우지 않았다. QA 스크린샷 16장(`shots/`)과 기준 시안 `design/reference/layout_v4.html`을 같은 뷰포트(1400×900, 960×640, 브라우저 에뮬레이션)로 비교했다.

## 방법

- 구현: 스크린샷 PNG를 브라우저 canvas로 읽어 ink(#1c1e18 근처, RGB<60) 픽셀이 이어지는 구간을 행·열로 스캔해 패널 테두리·입력 줄·카드·버튼의 실제 좌표를 쟀다.
- 시안: 같은 뷰포트에서 DOM 좌표를 쟀다(`getBoundingClientRect`). 시안은 file://이라 Galmuri11 대신 monospace가 쓰이므로 글자 폭은 1~2px 다를 수 있다. 상자 위치·크기만 비교했다.
- 눈으로도 봤다: 16장 전부 + 시안 첫 화면 1400×900·960×640.

## 차이 목록

1. **페이지 스크롤 막대 때문에 패널이 15px 좁아지고, 960×640에서는 오른쪽·아래 테두리가 가려진다** — 기준: 시안(페이지 스크롤 없음).
   - 위치: `src/App.tsx:28` 세션 줄마다 있는 `<span className="sr">`, `src/App.css:44` `.sr { position: absolute }`, `src/App.css:66` `.panel`에 `position` 없음.
   - 원인(실측): `.sr`의 기준 상자가 세션 패널이 아니라 문서다. 그래서 스크롤 안쪽 90번째 세션의 `.sr`이 문서를 아래로 늘린다. 시안에 세션 줄 90개를 넣어 재 보니 문서 높이가 640에서 4981로 늘었고, `.panel { position: relative }`를 더하면 640으로 돌아왔다. 시안에도 같은 잠복 버그가 있는데(`layout_v4.html:57`, `:79`) 세션이 4개뿐이고 `html { scrollbar-width: none }`(308행)이라 보이지 않았을 뿐이다. 이 run의 변경으로 생긴 문제는 아니다. 세션이 많아지면(QA 환경 89~90개) 드러난다.
   - 권장(Engineer): `src/App.css` `.panel`에 `position: relative;` 한 줄을 더한다. 확인: 세션 20개 이상에서 1400×900·960×640에 페이지 스크롤 막대가 없는지 본다. 시안 57/79행도 같이 맞춘다(design/ 쪽, Designer 몫).
2. **기록 맨 아래에 8px 빈칸이 하나 더 생긴다** — 기준: 시안.
   - 위치: `src/Chat.tsx:258` `<div ref={endRef} />`가 `.chat-items`(gap 8px, `Chat.css:14`) 안에 있어서 마지막 항목 뒤에 gap이 하나 더 생긴다. 실측: 카드 아래와 입력 줄 사이가 1400에서 21px(시안 11px)이다.
   - 권장(Engineer): 스크롤 기준 요소를 `.chat-items` 밖, `.chat-log` 안의 첫 자식으로 옮긴다(column-reverse라 맨 아래에 놓이고 gap이 붙지 않는다). 또는 sentinel을 없애고 마지막 카드 요소에 `scrollIntoView({block:"nearest"})`를 건다. 카드가 기록보다 높을 때 "nearest"를 카드에 걸면 카드 위쪽이 보이도록 정렬되므로, 960에서 질문 글이 가려지는 것(변형 6, 수용됨)도 덜해진다. 이것은 동작 변경이라 아래 질문 3으로 사용자에게 묻는다.

나머지는 같다. 바꾼 줄은 상단 바(D10)와 채팅 패널뿐이고, 세션·그래프·로드맵·게임기의 위치와 크기는 차이 1을 빼면 시안과 1px 안에서 같다.

## 사용자 승인 질문

1. 사이드카가 비정상 종료했을 때 문구는 이렇다: 카드 "→ 거부됨 (사이드카 종료)" / "→ 답하지 않음 (사이드카 종료)", 오류 줄 "✕ 오류: 사이드카가 끝났습니다"(`Chat.tsx:134-135`). 화면에 개발 용어 "사이드카"를 그대로 둘까, 아니면 "→ 거부됨 (연결 끊김)" / "✕ 오류: Claude 연결이 끊겼습니다" 같은 말로 바꿀까?
2. 결과에 비용이 없을 때 끝 줄을 "완료"만 보이는 것을 승인할까?
3. (선택) 차이 2를 고치면서 새 카드가 뜰 때 카드 **위쪽**이 보이게 맞출까? 지금과 시안은 960에서 질문 카드의 질문 글이 가려진 채로 뜬다.

## 못 본 것

- 실제 앱은 보지 못했다(셸 없음). 키보드 포커스 이동, hover, `▼`·커서 깜빡임 주기, reduced-motion은 정적 스크린샷이라 확인하지 못했다.
- 960×640은 CDP 에뮬레이션이다. 실제 창 크기 조절은 확인하지 않았다.
- 상단 바 결과 줄("성공 · 백업: …")은 설치 직후 장면이 없어 확인하지 못했다.
- 범위 밖 참고: 960에서 그래프 패널에 노드가 Lead 하나뿐인데 가로 스크롤 막대가 보인다(`Graph.tsx`, 이전 run). 채팅이 끝났는데도 Lead가 "실행 중"으로 남는 것은 데이터 문제로 보인다(VERIFY 7의 훅 포트 불일치).
- `orbit:design-system-guard`는 이 에이전트에 Skill 도구가 없어 부르지 못했다. 대비·포커스·좁은 폭은 직접 점검했다.
