# 채팅 사이드카 (마일스톤 ⑥)

사이드카는 run 20261115-terminal에서 삭제됨

## Agent SDK 사이드카 구조 요점
- 구조: Rust가 이 PC의 node로 사이드카를 `std::process`로 띄우고, 줄 단위 JSON으로 주고받는다. 사이드카가 SDK `query()`를 돌린다. 권한은 `permissionMode: "default"`에서 `canUseTool`로 카드를 띄워 받는다.
- 주의: 중단 플래그는 턴 동안에만 켠다(턴 밖에 남으면 다음 턴이 바로 끊김). 쿼리 오류 시 대기 중인 권한 요청은 모두 거부한다. 사이드카가 죽으면 열린 카드는 닫는다. 재시작한 프로세스는 카드 id를 p1부터 다시 쓰므로 화면 id에 대화 번호를 섞고 결과는 아직 결과 없는 카드에만 반영한다.
- 다음에 미리 할 것: 프로세스 경계 UI는 "프로세스가 죽는 순간"과 "재시작 뒤 id 재사용"을 먼저 시나리오로 적는다.

## 병렬 engineer는 같은 체크아웃에서 커밋이 섞인다
- 증상: 여러 engineer가 한 작업 트리에서 동시에 일하면 서로의 변경이 한 커밋에 들어가거나 add가 엇갈린다.
- 해결: 파일 영역이 안 겹치게 나누고, 각자 자기 파일만 add한다. 합친 뒤 커밋 범위를 확인한다.
- 다음에 미리 할 것: 병렬로 돌릴 때 PLAN에 태스크별 파일 목록을 적고 겹치면 순차로 바꾼다.

## PLAN 행 일부를 빠뜨림 (F2)
- 증상: PLAN의 한 항목(F2)이 일부만 구현됐고 리뷰 1회차에서 차단(B1)으로 잡혔다.
- 원인: engineer가 PLAN 행을 끝까지 대조하지 않았다.
- 해결: 리뷰 수정 커밋으로 마무리.
- 다음에 미리 할 것: 완료 보고 전에 PLAN 행마다 "어느 파일·어느 줄"을 대응시켜 본다.

## 리뷰 수정 뒤에는 COMMIT을 다시 확인한다
- 흐름: 리뷰 차단·권고를 고치면 해시가 바뀐다. QA·Security가 새 커밋을 확인해 VERIFY·SECURITY의 `COMMIT:` 줄을 갱신해야 `check ship`이 통과한다. 이번엔 출고 전 수정(포트·토큰 비교 등) 뒤 모델 호출 없이 재확인했다.

## 자동 분류기가 QA의 보내기 클릭을 막을 때
- 증상: 실제 모델을 부르는 `보내기` 클릭을 자동 분류기가 막아 화면 확인이 불가능했다.
- 해결: 우회하지 않고 미검증으로 기록하고, 사용자에게 위험(최악: 간격·문구 어긋남)을 보여 승인받아 사용자 확인 항목으로 넘겼다.
- 다음에 미리 할 것: 모델 호출이 필요한 확인은 사용자 실사용 항목으로 처음부터 분리해 둔다.
