# 세션 로그 감시 (마일스톤 ③)

run `20261114-session-log-watch`, 검토 커밋 83cc9fa. 로그를 읽어 세션 목록과 도구 호출 타임라인을 만들고 ②의 훅 이벤트와 합친다.

## 확정된 결정 (사용자, 2026-11-14)
- 감시는 std 폴링 1초. `notify` 크레이트 없음. 새 의존성 없음.
- 합치기·저장은 Rust 메모리만. SQLite·오프셋 파일 없음. 앱을 끄면 사라지고 시작 때 로그에서 다시 만든다.
- 서브에이전트 로그(`<session>/subagents/agent-*.jsonl`)는 제외하고 테스트로 고정했다.
- 시작 시 과거 기록은 전부 읽고 세션당 이벤트는 500개로 자른다(`MAX_EVENTS`).
- `CLAUDE_CONFIG_DIR`을 존중한다(릴리스 포함). 디버그 빌드는 `ORBIT_CLAUDE_PROJECTS`로 폴더를 바꿀 수 있다.
- 줄 길이 상한 16 MiB. 넘는 줄은 버린다.
- 이번에는 도구 호출(`tool_use`/`tool_result`)만 중복 제거·표시한다. 중복 키는 세션별 `<phase>:<id>`.
- ②의 `hook-event` 이벤트는 없앴다. webview에는 고른 필드(세션 ID, cwd, 시각, 도구 이름, tool_use_id)만 `session-update`로 간다. 프롬프트·도구 입출력은 화면 쪽으로 가지 않는다.

## 실측한 것 (QA, 임시 폴더와 가짜 로그만 사용)
- cargo test 54개, npm run build, gate 테스트 71개 통과.
- 시작 전 기록 복원, 실행 중 새 파일 = 새 세션, 호출·결과 표시.
- 훅과 로그가 같은 도구 호출이면 한 줄(출처 "둘 다"). 로그 먼저/훅 먼저 둘 다 확인.
- 깨진 줄, 모르는 type, 16 MiB 초과 줄, 개행 없는 반쪽 줄(나중에 완성되면 반영)에서 죽지 않음.
- 로그 문자열의 HTML은 글자 그대로 보임. 덧붙이기·이름 변경·삭제 중에도 앱 생존. 로그 파일 해시 불변. 콘솔에 로그 내용 없음.
- 약 52 MiB, 10만 줄 로그를 시작 때 복원: 창이 뜬 뒤 첫 읽기에 세션이 보이고 이벤트는 500개로 제한됨.

## 확인 못 한 것 (사용자 몫, BRIEF 기준 14)

- 실제 Claude Code 세션에서 훅 `tool_use_id`와 로그 `tool_use.id`가 같은 값인지. 다르면 "둘 다" 중복 제거가 안 되고 같은 호출이 두 줄로 보인다.
- 사람 눈으로 본 화면(QA는 DOM 텍스트로 확인), `CLAUDE_CONFIG_DIR` 경로, Windows 정션 걸러짐(std 동작 지식, 실측 없음), A1의 메모리 증폭(계산값).

## 다음 사람이 알아야 할 함정
- 한 회차에 파일 끝까지 읽는다. 처음엔 줄 중간에서 끝나는 16 MiB 덩어리마다 회차를 끝내 큰 파일이 초당 16 MiB로만 들어왔다(W1, 수정됨). 읽기 루프를 고칠 때 "버퍼가 찼고 offset이 전진했으면 계속"을 지킨다.
- 상한 초과 줄 테스트는 내용이 유효한 JSON이어야 상한을 검증한다. `x`만 채우면 파싱 실패로 어차피 통과한다(W5). 다만 상한 검사를 지우면 테스트 l이 실패하는지는 아무도 돌려 보지 않았다.
- `timestamp` 없는 줄은 `last_ms`를 읽은 시각으로 끌어올려 오래된 세션이 방금 활동한 것처럼 보일 수 있다(N1).
- 로그 `tool_result`가 훅 PostToolUse보다 먼저 오면 tool 이름이 빈 채로 남는다(N2).
- 로그에서 깊이 128 초과, 잘못된 UTF-8, 16 MiB 초과 줄은 조용히 버려진다. 화면에 없다고 실행되지 않은 것이 아니다(A4). 훅이 있으면 훅으로는 보인다.
- QA 도구: 디버그 빌드의 `ORBIT_CLAUDE_PROJECTS`·`ORBIT_CLAUDE_SETTINGS`를 임시 폴더로 지정하고 WebView2 원격 디버깅으로 조작한다. 실제 `~/.claude`는 열지 않는다.
