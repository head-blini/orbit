# Tauri 폴더 선택 (Rust 쪽 다이얼로그)

- 증상: 폴더 고르기를 웹뷰(JS)에서 하면 경로 문자열이 웹뷰를 거쳐 다시 Rust로 온다. cwd로 쓰기 전에 재검증해야 하고, 웹뷰에 `dialog:*` 권한을 열어야 한다.
- 원인: 웹뷰가 임의 경로 대화상자를 열 수 있게 되고, 웹뷰가 돌려준 경로가 신뢰 경계를 넘는다.
- 해결: `#[tauri::command(async)]` 안에서 `app.dialog().file().blocking_pick_folder()`를 부르고, 결과 경로는 Rust 상태(`Chat.picked`)에 보관한다. 웹뷰에는 폴더 이름만 돌려주고 인자는 받지 않는다. capability는 0개로 뒀고, 실제 앱에서 `폴더 선택` 창이 뜨는 것을 확인했다(VERIFY 8).
- 다음에 미리 할 것:
  - blocking 다이얼로그는 async 명령 안에서 부른다(계획은 메인 스레드 교착을 전제로 잡았다). async 명령 하나가 워커 스레드 하나를 묶는 점은 감수한다.
  - capability는 0개로 시작하고, 정말 다른 dialog 권한이 필요할 때만 최소 한 개를 추가한다.
  - 선택 결과에는 `\\?\` 접두·UNC가 올 수 있으니 검증 테스트에 넣는다.
  - 정션·심볼릭 링크가 네트워크 경로를 가리키면 문자열 검사로는 못 막는다. 후속: `canonicalize` 후 같은 검사를 다시 적용한다(이 run의 R1, 미구현).
