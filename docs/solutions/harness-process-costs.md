# 하네스 진행 비용

- 증상: 계획 검사 루프가 5회 돌았다.
- 원인: 산출물을 쓰는 architect에 부분 편집 도구가 없어 600줄 계획을 매번 통째로 다시 썼다. 검사 역할 plan-checker에 셸이 없어 검증 명령의 문법 문제를 실행 없이 반복 지적했다. 또 Lead가 handoff의 WRITE 범위를 계획의 태스크 행보다 좁게 적어 산출물 절반이 빠졌다(T5).
- 해결: Edit 권한, 제한된 셸, 변경분 한정 재검사, 줄 단위 수정은 engineer에게.
- 다음에 미리 할 것: 역할에 일에 맞는 도구(편집, 실행)를 주고, handoff는 계획의 태스크 행을 그대로 가리킨다.

## 수용 위험과 모델 호출 (open-folder)

- 증상: VERIFY가 미검증 3건으로 FAIL이 났고, 사용자 답을 두 번 받은 뒤 모델 호출을 1회 더 써서야 PASS가 됐다.
- 원인: 미검증 항목을 "사용자 수용 위험"으로 적어도 QA는 VERDICT를 PASS로 바꾸지 않았다(미검증 ≠ 통과). 그 항목 하나가 모델 호출을 필요로 했다.
- 해결: 사용자 허락으로 호출 1회를 더 써서 (a)(b)(c)를 실제 앱에서 직접 확인했다.
- 다음에 미리 할 것: 실제 모델 호출이 드는 검증은 계획 단계에서 호출 수를 적고, 수용 위험 경로로는 VERDICT가 바뀌지 않는다는 점을 사용자 질문에 먼저 알린다.

## 병렬 커밋 메시지 파일 (open-folder)

- 증상: 병렬로 돌던 engineer가 공유 temp 폴더의 같은 이름 메시지 파일을 써서, 한 커밋에 다른 engineer의 오래된 메시지가 들어갔다. amend로 고쳤다.
- 원인: 커밋 메시지 파일 이름이 역할·태스크를 구별하지 않는 공유 경로였다.
- 해결: 자기 커밋만 amend해 고쳤다(다른 커밋은 건드리지 않음).
- 다음에 미리 할 것: 커밋 메시지 파일은 run 폴더 안에 태스크 이름이 붙은 고유 이름으로 쓴다.
