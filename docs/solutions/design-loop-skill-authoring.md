# 디자인 루프·외부 스킬 문서 작성에서 리뷰가 잡은 것 (run 20261121-design-loop)

## 증상
- 외부 UI 스킬(Impeccable·Hallmark)을 폴더째 가져오려 하면 불필요한 파일·라이선스 범위가 따라온다.
- 루프 규칙(한도, 원복, 판정어)을 router·designer 등 여러 파일에 각각 적었더니 리뷰 3회에 걸쳐 문구 불일치가 계속 나왔다(한도 조건, 원복 순서, 마지막 확인 때 원복 여부).
- 프로젝트 문서(`design/DESIGN.md` 등)에 이미 다른 결정으로 대체된 내용이 되살아났다.

## 원인
- 규칙을 복사해 두면 한쪽만 고쳐져 어긋난다.
- 외부 저장소는 움직이므로 고정 커밋 없이 옮기면 출처를 다시 확인할 수 없다.
- 결정 기록(`.orbit/decisions.md`)의 최신 상태를 확인하지 않고 옛 설계 문구를 옮겼다.

## 해결
- 외부 스킬은 폴더째가 아니라 필요한 규칙 텍스트만 고정 커밋에서 옮기고, `harness/skills/vendor/SOURCES.md`에 출처·커밋·라이선스를 적는다.
- 루프 규칙은 한 파일(판정어 항목)에만 정의하고 나머지는 "§ 참조"로 가리킨다.
- 마지막 확인 단계에서는 원복 없이 수정 요청으로만 끝내고, 원복 때는 되돌릴 커밋 SHA를 최신부터 engineer에게 넘긴다.

## 다음에 미리 할 것
- 새 규칙을 쓰기 전에 같은 규칙이 이미 어디에 있는지 `git grep`으로 찾고, 있으면 거기를 가리킨다.
- 프로젝트 문서에 설계를 옮길 때 `.orbit/decisions.md`에서 대체된 결정인지 먼저 확인한다.
- 외부 텍스트를 가져올 땐 커밋 해시와 라이선스를 같은 커밋에서 기록한다.
