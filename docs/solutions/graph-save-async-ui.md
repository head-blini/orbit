# 저장·불러오기·삭제 UI의 비동기 함정

## 증상
- 삭제 뒤 포커스가 사라지거나 엉뚱한 곳에 간다.
- 저장 중에 불러오기·삭제를 누르면 상태가 꼬인다.
- 방어용 try 코드(S4)의 테스트가 예외를 못 만들어 증명되지 않는다.

## 원인
- 목록 갱신(reload)이 비동기라, 갱신 전에 포커스를 옮기면 이미 사라질 요소를 가리킨다.
- 저장·불러오기·삭제가 각자 상태를 가져 서로 막지 못했다.
- 일반 입력으로는 V8이 `JSON.stringify`에서 예외를 내지 않는다.

## 해결
- 포커스는 reload가 끝난 뒤에 옮긴다.
- 세 동작은 공통 busy 하나로 직렬화하고, 진행 중에 누르면 "다른 작업이 끝난 뒤에 다시 누르세요"를 알린다.
- 방어 코드 테스트는 V8에서 확실히 예외를 내는 입력(BigInt, 순환 참조)을 쓴다. 그래도 WebKit 전용 방어는 자동 증명이 안 될 수 있다.

## 다음에 미리 할 것
- 비동기 갱신이 있는 목록 UI는 처음부터 공통 busy와 "갱신 후 포커스"를 설계에 넣는다.
- 두 번 눌러 확인하는 버튼에는 대기 상태의 접근 이름을 함께 붙인다.
