# 관문의 문자열 검사는 끝이 없다

- 증상: 출고(main 머지·push) 감지를 고칠 때마다 리뷰·보안 회차에서 새 우회가 나왔다. 따옴표 친 `"git"`, 붙여 쓴 `-m"…"`, `--git-dir`, `GIT_DIR`, `Push-Location`, `rebase --onto X --root main`, main 위 `cherry-pick`·`commit` 등.
- 원인: gate는 명령 문자열을 정규식으로 보는 1차 감지다. 의미가 다른 정상 옵션과 문자열 변형을 모두 잡을 수 없다. 또 "관문 통과"가 run 단위라서 그 브랜치에 지금 있는 커밋이 검토받은 커밋인지는 보지 않는다(N1).
- 해결: 이번 run은 S1~S13 중 9개를 닫고 4개를 부분으로 남겼다. 남은 우회는 `harness/skills/orbit/gate/SKILL.md`에 적었다. 3회차부터는 코드로 더 쫓지 않고 문서화했다.
- 이어진 run(gate-commit-binding, 리뷰 4회차): 1~3회차 차단이 모두 "입력 문자열을 걷어낸 뒤 검사"(`-m`·`-F` 값 지우기, 따옴표 안 공백·`;&|` 치환, 토큰 끝 문자 떼기, ORBIT_REF 뒤쪽 경계)에서 생긴 옛 관문 대비 회귀였다. 걷어내기를 다듬는 대신 새 판정을 옛 판정의 상위 집합으로 만들었다: 위치 변경은 원문 전체에, rebase는 옛 정규식 OR 새 판정, id 판정은 옛 정규식 그대로. 대가는 닫힌 쪽 과차단(커밋 메시지의 `cd`·`rebase … main`)이고 메시지는 `-F` 파일로 쓰게 문서화했다. 보안 단계에서 옛·새 gate를 같은 명령 61개로 나란히 실행해 회귀 0건을 확인했다. 그래도 `git replace`, `git symbolic-ref HEAD`, `git config … x --list`는 남았다(후속).
- 다음에 미리 할 것: 관문 판정을 바꾸는 계획에는 "옛 판정의 상위 집합" 원칙을 처음부터 넣고, 리뷰 전에 옛·새 gate를 같은 명령 집합에 나란히 돌려 BLOCK→ALLOW가 0건인지 본다(줄 단위 대조만으로는 세 회차가 걸렸다). 우회가 문자열 변형이면 정규식을 늘리지 말고 git 쪽 강제(reference-transaction)와 검토 커밋 해시 대조로 간다. gate.mjs·gate.test.mjs는 에이전트가 못 고치므로 키트(`kit/`)로 만들고 사람이 적용하게 일정에 넣는다. 테스트가 늘 때 기존 테스트의 지워진 줄을 diff로 확인한다.
