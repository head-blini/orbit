# 화면 기준 시안과 구현 맞추기 (마일스톤 ④)

run `20261114-graph-ui`, 검토 커밋 803e28f. 확정 디자인으로 화면을 다시 만들면서 구현이 승인된 모습과 두 번 어긋났다.

## 시안을 파일로 다시 만들 때 빈 값을 채웠다
- 증상: 구현 뒤 사용자가 "시커멓고 딱딱해 보임", "시안은 동글동글했다"고 했다. 노드 모서리와 실행 중 반전이 승인된 모습과 달랐다.
- 원인: 기준 시안(`layout_v4.html`)을 파일로 다시 만들 때 확정 줄에 없는 값(노드 모서리, 한 열 배치)을 임의로 채웠다. 시안에 그림이 없는 상태(노드 6개 이상 칩)에서는 구현이 따로 갔다.
- 해결: 노드 모양 변형 A~E(`graph_variants.html`)를 보여 주고 사용자가 E를 골랐다(DECISIONS 11). 6개 이상도 항상 큰 상자로 확정(DECISIONS 10).
- 다음에 미리 할 것: 시안 재작성 때 확정 줄에 없는 값은 만들지 말고 목록으로 사용자에게 묻는다. 시안에 없는 상태(많은 개수, 빈 상태)는 구현 전에 그림을 먼저 받는다.

## "1단계만"이 깊이와 배치를 구분하지 않았다
- 증상: 팀원이 Lead 뒤에 한 열로 나열됐다. 사용자: "이렇게 구현하려던 게 아니잖아".
- 원인: 범위 질문 "메인 → 서브에이전트 1단계만"은 부모-자식 깊이(손자 노드 없음)만 뜻했는데 배치(열)까지 제한하는 것으로 구현됐다. Lead가 질문에서 둘을 구분해 알리지 않았다.
- 해결: 단계 열 배치와 "다음 열로" 규칙(DECISIONS 12, 13).
- 다음에 미리 할 것: 범위를 줄이는 질문에는 줄이는 것과 줄이지 않는 것을 함께 적는다. 이미 확정된 배치 기록(`.orbit/decisions.md`)이 있으면 질문 전에 대조한다.

## 시각 대조는 같은 데이터, 같은 크기, 측정값과 나란히
- 스크린샷 몇 장과 소스 읽기로는 어긋남을 못 잡았다. 시안과 같은 데이터를 넣은 실제 앱을 같은 크기로 찍어 좌표·크기·테두리 측정값과 함께 시안 옆에 놓고 본다. CDP 측정 방법은 run 폴더 `shots/NOTES.md`. 이렇게 했을 때 차이가 "권한 요청" 문구 누락 하나로 좁혀졌다.

## 사용자만 볼 수 있는 항목은 분리해 판정한다
- 빈 액정 화면(사용자 그림을 옮기지 않음)과 네트워크 없는 실행(Wi-Fi 끄기는 시스템 설정 변경)은 에이전트가 볼 수 없다. 억지로 PASS/FAIL로 두지 않고 "사용자 확인 대기"로 분리하고 수용한 위험을 적는다(DECISIONS 15, ③ run의 기준 14와 같은 방식). 판정은 QA가 낸다.

## 함정: 에이전트 셸에서 띄운 앱의 앱 데이터 폴더
- 에이전트 셸(MSIX 컨테이너)에서 띄운 앱은 앱 데이터 폴더가 리다이렉트된다(T8). 거기서 본 파일 상태는 사용자 PC의 실제 폴더와 다를 수 있다. QA에서 앱 데이터 경로를 가정하는 항목은 이를 감안한다.
