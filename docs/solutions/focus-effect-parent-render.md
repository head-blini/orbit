# 자식 포커스 effect가 부모 재렌더보다 먼저 도는 문제

## 증상
- 터미널 ×·Delete로 줄을 닫으면 포커스가 body로 떨어지거나, 닫은 줄이 맨 위로 내려온 뒤 엉뚱한 줄(두 번째 줄)에 포커스가 남는다.
- 새 터미널을 시작하면 새 임시 줄(`live-<id>`)이 스크롤된 목록 밖에 있다.
- 보이지 않는 줄의 ×를 클릭하면 WebView2에서 포커스가 사라진다.

## 원인
Terminal(자식)의 포커스·scrollIntoView effect가 App(부모)의 onTabs 재렌더보다 먼저 돈다. 그 시점에는 목록 DOM이 아직 옛 상태라, 찾으려는 줄이 없거나 이웃 줄 계산이 어긋난다. 두 컴포넌트를 따로 짜면서 "누가 먼저 렌더되는가"를 계약에 적지 않았다.

## 해결
- 포커스·스크롤은 App이 줄을 다시 그린 뒤로 미룬다(settle 호출).
- 닫는 줄 안에 activeElement가 있으면 row와 같은 이웃 줄로 포커스를 옮긴다. 보이지 않는 줄의 ×도 마찬가지다.

## 다음에 미리 할 것
- 두 컴포넌트가 DOM id·클래스로 약속하는 포커스·스크롤은 PLAN에 "누가 먼저 렌더되는가"와 호출 순서를 적는다.
- 줄이 사라지거나 생기는 동작(닫기·시작)을 QA 절차에 넣어 포커스 위치를 확인한다.
